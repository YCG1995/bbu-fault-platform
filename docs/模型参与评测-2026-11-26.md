日期：2026-11-26  
模型配置：`model_configs.id=1`，模型名 `deepseek-flash`  
密钥处理：模型配置从主库解密使用，不复制到评测临时目录、不写入报告或日志。

## 一、结论

- 3 个真实案例在 `off`、`planner`、`report`、`full` 四种模式下均为 **3/3 完全命中**。
- `full` 模式连续两次完整重跑均为 **3/3**，模型实际调用 **6 次/轮**，根因未发生变化。
- 模型只参与规划和报告叙述；根因仍由技能规则、证据链和确定性仲裁决定，模型不能改写根因。
- 模型叙述经过 claim/数字/时间校验；校验不通过时自动回退确定性模板，不会把无证据内容写进报告。

## 五、本轮发现并修复的问题

1. **评测临时目录导致签名技能不可用**
   评测临时库使用新的 `data_dir`，导致 `demo-bbu-clock-loss` 的 `skill-signing.key` 与技能清单签名不匹配，技能状态变成 `incompatible`。修复为：任务产物仍写入评测临时目录，技能验签统一使用主实例 `data_dir`。修复后 `off` 基线恢复 3/3。

2. **模型叙述引用了未支撑的技能匹配分**
   首轮 `full` 有两例报告叙述因引用 `30.0` 等技能分数、或把 UTC 时间换算为本地时间，被 `validate_narrative` 拒绝并回退。修复：
   - 从报告事实包中移除技能匹配分；
   - 提示词明确禁止引用分数/耗时/token/置信度百分比；
   - 明确要求时间逐字复制证据中的 UTC 值，禁止时区换算。
   修复后连续两轮 `full` 的模型叙述均为 3/3 采纳，0 回退。

3. **评测摘要未统计模型叙述采纳数量**
   `_llm_usage` 最初只统计调用和 token，未读取 `result.narrative`。已增加 `narrative_used`、`narrative_fallback` 并按“调用/采纳/回退”输出到评测摘要和报告。

4. **非法模型配置的 CLI 报错不友好**
   `--model-id 999` 原会输出整段 traceback；已改为 `评测失败: 模型配置不存在或未启用: 999` 并返回退出码 2。

## 六、覆盖与验证

- 真实案例：3 个 golden `test` 案例，覆盖 GNSS 接收链路、OCXO 老化两类根因。
- 模式覆盖：`off`、`planner`、`report`、`full` 各至少一轮。
- 重复覆盖：`full` 连续两轮完整 3 案例；根因均为 3/3，模型叙述均为 3/3。
- 回退覆盖：`validate_narrative` 已覆盖未支撑数字、未支撑时间、过度断言；本轮实际触发了前两类并成功回退。
- API 冒烟：`tests/api_full_smoke.py` 通过，REST 136/136；新增非法 `llm_mode` 返回 400 的断言。
- 评测单测：`tests/test_evaluation.py` 4/4；覆盖默认 off、非法模式、无真实模型拒绝、叙述统计。

## 七、边界

- 3 个真实案例样本量不足，`hidden` 门禁未应用（低于 20 例门槛），不能把 3/3 当作现网准确率。
- 模型参与不等于模型决定根因；模型计划可能增加或跳过步骤，但最终根因仍受技能规则和证据校验约束。
- 模型输出存在波动；本轮两轮 `full` 均为 3/3，但不能保证所有日志分布下稳定。
- 统一使用主库模型配置意味着评测会消耗真实模型额度；每次 `full` 3 案例约 3 万 tokens，批量评测前应确认预算。

## 八、复现命令

```bash
# 确定性基线
python3 tools/real_cases.py evaluate --split test --llm-mode off

# 只让模型规划
python3 tools/real_cases.py evaluate --split test --llm-mode planner --model-id 1

# 只让模型写报告叙述
python3 tools/real_cases.py evaluate --split test --llm-mode report --model-id 1

# 规划 + 报告
python3 tools/real_cases.py evaluate --split test --llm-mode full --model-id 1
```

API 请求体增加：

```json
{
  "split": "test",
  "limit": 3,
  "llm_mode": "full",
  "model_config_id": 1
}
```

不传 `llm_mode` 时仍为 `off`，保持原有确定性调用兼容。
