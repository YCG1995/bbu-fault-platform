## 新增测试

`tests/test_ai_runtime_hardening.py` 共 20 项：

1. 非可重试 `AIError` 只请求 1 次，不退避。
2. 可重试错误按 `retries_per_model` 重试 3 次。
3. 失败 attempt 计入 `Budget.calls`，并发预占归零。
4. 实际 usage 超 `max_tokens` 标记 `over_budget` 并阻断下一次预留。
5. 修复请求异常不会回到同一模型重试。
6. Schema 连续失败触发 `schema_breaker`，能力缓存标记 `degraded`，`choose()` 返回空。
7. 上下文裁剪保留尾部 JSON Schema 约束，输入+输出不超过 1024 窗口。
8. 超长文本裁剪后 token 估算不超过预算。
9. `complete()` 实际使用裁剪后的 prompt 与收紧后的 `max_tokens`。
10. 端点 gate 饱和时按队超时拒绝，且不触发传输熔断。
11. 端点排队上限拒绝额外等待者。
12. 同优先级模型组轮询。
13. allowlist 只放行白名单私网，空值维持允许所有私网。
14. `*.suffix`/CIDR 解析、`policy_from_config`、host/path 审计目标。
15. `replan=True` 不再触发 `len(bool)`，补规划违规被有界 Agent 报告。
16. `agent_max_replans=0` 时补规划被拒绝。
17. 未显式声明 `max_output` 时，显式 12000 输出请求不被数据库默认 4096 截断；显式声明后才按声明值收紧。
18. 能力探测遇到本地端点排队拒绝时不写 `degraded`、不缓存为端点故障。
19. 探测结果正确标记数据库 `max_tokens` 为非声明输出上限。
20. `complete()` 在非声明能力下保留显式 12000 输出请求，实际传给模型的 `max_tokens` 为 12000。

## 行为核对

- 确定性 401/400 不再重试；可重试 503/超时仍按每模型预算退避（含抖动）。
- 失败调用计入 `max_llm_calls`；预算预留包含最大输出，结算后超额会阻断后续调用。
- Schema 首次失败仍修复一次；修复后仍失败才熔断，默认 2 次/300 秒。
- 长 prompt 在模型能力缓存声明的上下文窗口内裁剪；`max_tokens` 同步收紧。
- 能力缓存中的数据库 `max_tokens` 只作默认输出，不当作硬上限；仅显式 `extra.capabilities.max_output` 才限制显式输出请求。
- 单端点并发/排队受限；排队拒绝只换模型，不把端点标坏，也不计入模型健康失败。
- `model_private_allowlist` 为空时行为与 1.28.1 一致；非空时 CIDR/主机/后缀精确放行；元数据/link-local 永远拒绝。
- 补规划新增步骤在 `bounded` 模式下重新过门禁，违规返回 `rejected`，不执行新增技能。
- 原有诊断主链路、模型无工具执行权/发布权、确定性降级路径未改变。
