# BBU FaultScope 1.19.1 版本说明（技能工坊模型调用优化）

发布日期：2026-11-26

本版本基于 1.19.0，不更换模型，重点修复技能工坊的模型调用协议、上下文规模、评审回退和失败可观测性。1.19.0 的安装包、SHA 文件和版本说明保持原样，不覆盖、不静默替换。

## 一、变更范围

### 1. 模型 prompt 只带业务字段

- `bbu/workshop_spec.py` 新增 `model_spec()`，保留 `fault_name/title/summary/domain/symptoms/log_sources/evidence_rules/root_causes/cases/recovery/risks/thresholds` 等业务字段。
- 递归剥离 `provenance`、`diagnostic_reasoning`、`recipe`、`recipe_candidates`、`hard_fields`、`source_revision`、`compiler` 等内部元数据，以及嵌套字段中的 `provenance`、`locked`。
- `bbu/workshop.py` 的 `safe_spec()` 改用 `model_spec()`；`public_spec()` 继续保留完整字段给页面和溯源。
- 看门狗样本：`public_spec` 29,528 字符，`model_spec` 5,707 字符；extract prompt 46,383 → 16,506 字符，review prompt 41,645 → 11,768 字符。

### 2. 结构化输出按能力路由

- `bbu/ai.py` 的 `AIGateway.complete()` 根据模型能力选择：
  - `strict_schema=true`：发送原生 `json_schema`；
  - `json_mode=true`、`strict_schema=false`：发送 `response_format={"type":"json_object"}`；
  - `json_mode=false`：不发送 `response_format`，只用提示词约束。
- `_call_openai()` 支持 `{"type":"json_object"}`，不会再错误包装成非法的 strict schema。
- 本地严格 JSON Schema 校验始终执行，不因端点降级而放宽。

### 3. 评审、修复与最终复核拆小

- 首次评审输出上限从 8,000 降到 `min(5000, max_tokens)`。
- 新增 `workshop_review_final_user()`：最终复核只带上一轮 error、修复后 spec 和确定性质量，输出上限 `min(3000, review_budget)`。
- 评审 system prompt 要求最多报告 6 个最重要问题，不重复、不重写完整规格。

### 4. 失败回退保留评审结论

- `WorkshopService._generate()` 在修复失败且已有 `review` 时，使用 `_merge_review(audit_spec(spec), review)`，不再用确定性审计覆盖评审 error。
- 新增 `extract_status / review_status / repair_status`，保留 `ai_status` 兼容旧 UI。
- `web/assets/js/page_workshop.js` 新增部分成功文案：提取成功但评审/修复失败时，不再统一显示“AI 提取成功”。

### 5. 失败调用可观察

- `AIGateway.complete(..., stage="", attempt_sink=None)` 把成功和失败调用都送入 sink。
- 失败 attempt 记录 `stage/model/latency_ms/status`、错误、可解析的 `http_status`；没有真实 usage 时记录 `estimated_input_tokens`。
- `analysis["attempts"]` 不再只有成功调用。

真实模型复测（主库 `model_configs.id=1`，`deepseek-flash`，密钥未复制到临时目录）：

- 通用时钟：extract input 2,666 tokens，review 1,814，repair 3,907，review-final 2,268；四阶段全部成功，总耗时 122.24s，质量分 92。首次 extract 有一次 30.1s `IncompleteRead`，第二次 27.32s 成功。
- 看门狗：extract input 从 15,184 降到 5,945 tokens；至少一次 run 达到 extract + review + repair 成功，review-final 连续 3 次约 30s `IncompleteRead`；失败 attempt 已记录，质量门禁返回 `needs_confirmation`。
- USB FLASH：extract 连续 3 次约 30s `IncompleteRead`，未拿到 usage，回退确定性规则；说明 P0 缩减上下文后端点仍可能断连。

## 三、数据库、接口与兼容性

- 当前代码数据库 schema **17**；REST **136 条**。
- 1.19.0（schema 16）可直接用 `deploy/upgrade_offline.sh` 升级；升级前自动生成 state/code 备份，旧包和旧 SHA 不覆盖。
- 本版本不改变工坊发布门禁：E1–E4 未验证时仍停在人工确认，不自动发布 AI 生成技能。

## 四、仍未完成

- `deepseek-flash` 端点约 30 秒断连/HTTP 503 仍未消除；本轮只做上下文裁剪、评审输出限制和失败记录，没有做模型 fallback/健康切换。
- 复杂配方的 review-final 仍可能触顶或在 30 秒断连；真实模型复测不是稳定 3/3，不能宣称全部场景已跑通。
- 未实现可重复的真实模型探针脚本；本轮真实调用仍通过临时目录和现有 API 执行。
- Agent Loop/DAG、真实 hidden 集、规则变异矩阵、组织离线签名等 1.19.0 未完成项不在本版本范围内。
