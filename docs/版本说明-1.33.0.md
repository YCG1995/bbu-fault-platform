# BBU 故障诊断平台 1.33.0 版本说明

1.33.0 是 1.32.0 之后的第二波增强，主题是“评测与运营”：把知识库从“能导入、能检索”推进到“可度量、可治理、可运营”。数据库 schema 由 **26** 升到 **27**；REST 路由由 222 增至 **243**；仍为单个 Linux 离线包，不引入新的第三方依赖。

## 本版变更

### 1. 评测台：300 条金标准导入、分层指标与可比较性

- 启用既有 `kb_eval_sets`、`kb_eval_queries`、`kb_eval_runs` 表并实现 `KBEvaluator` 服务；查询新增 `category`（实体精确/症状描述/口语改写/库外无答案）与 `split`（dev/test）分层。
- 支持 JSONL、JSON、CSV 导入；CSV 列为 `query,qrels,category,split`，qrels 用逗号分隔案例 ID。单集最多 5000 条，空查询跳过。
- 指标：`recall@1/5/10`、`mrr@10`、`ndcg@10`、`no_answer_accuracy`、`answered_rate`、`avg_latency_ms`、`p95_latency_ms`，以及 `recall@5_ci95` 的 Wilson 置信区间。
- 空 qrels 不进入召回分母；空索引或全库外问题不会除零，整体与分类别都安全返回 0/0.0。
- 每条查询调用 `KBService.search(..., log=False)`，记录 top-10 案例、`no_answer`、延迟和失败原因，不污染真实查询日志。
- `metrics_json` 固化 `index_checksum`、`qrels_sha256`、`config_hash`、`prompt_version`、`comparable` 与 `warnings`；索引变化后的新 run 标记为不可比，同一冻结索引重复运行的指标一致。
- 管理页面新增「评测」标签：数据集列表、导入、运行、汇总指标、分类别指标、失败样例、CSV/Markdown 导出；页面只读展示，不在浏览器生成 qrels。
- **重要边界**：评测台只负责承载和计算，**300 条真实金标准的 qrels 必须由专家标注，系统不会用模型生成标准答案**；仓库测试中的 300 条是合成回归数据，不能作为上线准确率证据。

### 2. 术语真正进入检索

- `kb_terms` 不再只是展示词典：检索时按当前库动态读取启用中的同义词，词条与别名双向映射，与内置词典合并后去重。
- `expand_terms` 每条查询最多扩展 2 个概念词；板卡型号和版本号不参与扩展，避免把查询扩成另一个实体。
- 术语只做查询扩展，不重建倒排索引；保存后清空 facets 缓存，检索立即生效。
- 新增术语 CRUD 与 CSV 导入/导出；管理员可写，普通用户只读且受库可见性约束。保存拒绝成环、空别名、别名与词条相同、重复词条；同库同类型唯一。
- UI「词典」标签支持新增/编辑/删除、启用开关、权重、CSV 导入导出。

### 3. 近重复合并向导

- 候选发现：候选复用索引的 64 位 SimHash 4 段桶与标题桶初筛，再用字符 3-gram + Jaccard 精确比对，默认阈值 `0.82`；单库最多扫描 20000 个文档、最多返回 200 对。
- 页面展示相似度、源/目标案例数、建议 canonical，以及逐字段差异预览。
- 合并只“并入”不物理删除：源文档置 `status='merged'`、记录 `merged_into`、`merged_at`、`merge_token`；目标文档保留原案例，来源案例逐条写入 `merge` 修订后迁移。
- 合并、案例迁移与文档状态更新在同一事务提交；同一 `merge_token` 重复执行返回 no-op，不重复迁移。
- 需要管理员二次确认；理由写入审计。当前相似度是字符级近似，不是语义向量。

### 4. 导入列映射与 XLSX 工作表

- 新增 `POST /api/kb/import/preview`：返回编码、分隔符、表头、猜测映射与前 20 行脱敏样本，不落库。
- 映射目标为 `title/symptom/cause/solution/board/domain/version/tags/answer`；同一目标不能映射多列，映射列必须存在，且至少包含 `answer` 或一个内容字段。
- 映射随 `kb_import_jobs.options_json` 保存，导入任务可追溯；错误映射返回 400 而不是静默丢列。
- CSV 支持 UTF-8/GBK/GB18030 自动识别；XLSX 支持多工作表，页面切换工作表后重新猜测列映射。多文件导入时预览/映射只作用于第一个文件，这是当前明确的 UI 边界。

### 5. 批量导出报告

- 新增 `POST /api/kb/export/report`，标准库生成 `report.html`、`report.md`、`data.csv`、`report.docx`，与 `manifest.json` 一起打进 ZIP。
- ZIP 使用固定白名单路径，拒绝额外文件；manifest 记录每个文件的 SHA256 与字节数。
- HTML 全量转义；CSV 带 BOM 并防公式注入（`= + - @` 前缀加单引号）；DOCX 为最小 OOXML，不依赖 python-docx。
- 单次最多 2000 个文档/案例；默认脱敏，管理员可显式 `reveal=true` 导出原文。服务端不生成 PDF，HTML 可在浏览器打印为 PDF。
- UI 文档库支持勾选文档后导出报告；案例级 `case_ids` 已由后端支持，当前 UI 只暴露文档级选择。

### 6. AI 自动发布 dry-run

- 自动发布只针对 `target_type=draft`；必须审核 `status=done`、结论 `pass`、无 blocker、分数不低于 `kb_auto_publish_min_score`（默认 90）、置信度不低于 `kb_auto_publish_min_confidence`（默认 0.9）、字段完整、非扫描/图片/人工转写占位稿，且 `prompt_version` 为当前版本。
- policy id 固定为 `review-auto-v1`；dry-run 只计算 `eligible/reasons`，不改草稿状态、不写文档。
- 总开关 `kb_review_auto_publish` 默认 **false**；`kb_review_auto_publish_dry_run` 默认 **true**。只有管理员显式关闭 dry-run 并开启总开关后，审核 worker 才会在审核完成后执行自动发布。
- 实际发布由系统 actor `system:auto_publish` 写入 `kb.auto_publish` 审计；审核记录标记 `decided` / `human_decision=auto_publish`。管理员也可在审核页查看 dry-run 面板并手动触发单条。

## 数据与迁移

- schema 27 为 additive migration：
  - `kb_documents` 新增 `merged_into`、`merged_at`、`merge_token`，并新增 `idx_kb_docs_merged`；
  - `kb_eval_queries` 新增 `category`、`split`；
  - `kb_terms` 新增 `idx_kb_terms_unique(kb_id,kind,term)`；建索引前对历史重复词条去重，避免旧库迁移失败。
- 升级前请备份 `data/`、`master.key` 和 `config.json`；升级脚本会执行 schema 迁移并校验服务健康。
- 旧 1.32.0 代码不能读取 schema 27 的新列/表；回滚必须恢复升级前数据快照，不能只回滚代码。

## 升级与回滚

1. 升级前备份 `/var/lib/bbu-fault-platform`，至少包含 `data/`、`master.key`、`config.json`。
2. 解压 `bbu-fault-platform-1.33.0-offline.tar.gz`，执行 `deploy/upgrade_offline.sh`；schema 26→27 自动迁移。
3. 升级后检查「系统信息」版本为 `1.33.0`、schema 27，并在「知识库管理」抽查词典、评测、近重复和导出报告。
4. 回滚保留 1.32.0 离线包与升级前 `data/` 快照；schema 27 对 1.32.0 不兼容，必须整库回滚。

## 已知边界

- 300 条真实专家金标准尚未随包提供；当前只提供导入/评测能力与合成回归数据。没有专家 qrels 前，Recall 数字不能作为上线门槛。
- 近重复使用字符 3-gram + Jaccard，阈值 0.82 尚未用现场样本校准；不是语义向量，跨语言/同义改写可能漏检。
- 导入映射 UI 只预览第一个文件；多文件批量导入时每文件不同表头需拆批处理。
- 报告 UI 的勾选粒度是文档；案例级选择需要调用 API 的 `case_ids`。
- 自动发布依赖 AI 审核的 `score`（0–100）与 `confidence`（0–1）量纲；接入新模型/提示词后应先看 dry-run 观察期，再开总开关。
- OCR、真语义向量、Windows 便携运行时和真实 2268/10k 性能压测仍属于后续波次。
