# BBU FaultScope 1.19.2 版本说明（技能工坊流式调用修复）

发布日期：2026-11-26

本版本在 1.19.1 基础上继续修复真实模型工坊的剩余问题，不更换模型。1.19.1 的安装包、SHA 文件和版本说明保持原样，不覆盖、不静默替换。

## 一、修复内容

### 1. 工坊四阶段改用 OpenAI SSE 流式读取

- `AIGateway.complete(..., stream=True)` 新增流式调用参数。
- 技能工坊的 `extract`、`review`、`repair`、`review-final` 全部启用流式，避免上游代理在约 30 秒空闲后断开连接。
- `_post_openai_stream()` 逐行读取 `data:` 事件，兼容：
  - 正常 SSE `text/event-stream`；
  - 网关忽略 `stream` 仍返回普通 JSON；
  - 最终 `usage` 事件；
  - 没有 usage 时按 prompt/输出做保守估算。
- 明确不支持流式（HTTP 400/404/405/422 或错误文本包含 stream）时，自动回退非流式，不改变原有 JSON Schema 校验。

### 2. 可观察性

- attempt 记录新增 `stream` 标记，且记录的是实际传输方式：SSE 成功为 `true`，明确不支持流式并回退后为 `false`。
- SSE 解析兼容增量 `delta`、完整 `message` 和旧式 `text`；连接中断按流式重试，不误回退非流式。
- 流式成功仍写真实 `input_tokens/output_tokens`；网关不返回 usage 时写估算值。
- 既有 `estimated_input_tokens`、HTTP 状态、失败 attempt 逻辑保持不变。

### 3. 没有放松质量门禁

- 流式只解决传输层；最终评审报告的问题仍会进入 `_merge_review`，不会因为“调用成功”就放行。
- 本次真实看门狗复测最终仍报告“E1–E4 全部 verified=false”，确定性审计通过，但按现有证据门禁该技能不能作为已验证技能发布。

## 二、真实模型复测

使用主库 `model_configs.id=1`（`gpt-4o-mini`，OpenAI 兼容端点），密钥未复制到输出或报告。

看门狗场景四阶段实际耗时：

| 阶段 | 耗时 | 输入/输出 tokens | 结果 |
| --- | ---: | ---: | --- |
| extract | 15.46s | 5,893 / 3,364 | 成功 |
| review | 27.62s | 5,595 / 4,260 | 成功，报告 12 个问题 |
| repair | 22.66s | 13,064 total | 成功 |
| review-final | 6.65s | 5,245 total | 成功，仍报告 1 个 error（规则未验证） |

对比 1.19.1：同一看门狗场景的 review/review-final 多次在约 30 秒出现 `IncompleteRead`；本轮四阶段全部在 30 秒内拿到完整响应，说明流式读取绕开了空闲断连问题。

另一个短 extract 探针：16,506 字符 prompt，12.92s 返回，5,893 / 3,014 tokens。

## 三、可复现探针

新增 `tests/live_model_probe.py`，复制主库到临时目录后调用真实模型，不污染主库健康统计。默认短探针输出：0.96s，115 / 11 tokens（总 126），attempt 标记 `stream: true`。可用 `--prompt-file` 复现长上下文 extract 场景。

- 数据库 schema **17**；REST **136 条**。

- 流式参数只在 workshop 调用启用；其他 planner/writer 调用仍走原非流式路径，避免改变既有行为。

## 六、仍未完成

- 上游 `gpt-4o-mini` 仍可能出现 HTTP 503；流式解决的是 30 秒空闲断连，不保证端点永远可用。
- 当前没有多模型 failover 和自动健康切换；只有一个模型配置时，端点整体不可用仍会回退确定性结果。
- 看门狗最终评审的“规则未验证”是证据缺口，不是传输 bug；需要现场样本或人工确认，不能由代码伪造。
- Agent Loop/DAG、真实 hidden 集、规则变异矩阵等 1.19.0 未完成项不在本版本范围。
