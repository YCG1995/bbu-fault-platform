# 故障知识库使用手册（1.33.0）

## 1. 入口

- 故障问答：`http://<服务器>:8080/#/kb`
- 知识库管理：`http://<服务器>:8080/#/kb/docs?tab=overview`（概览、统计、文档、导入、审核、变更与审计、词典、知识库、近重复、评测、设置）
- 文档库：`http://<服务器>:8080/#/kb/docs?tab=docs`（只浏览/筛选/分页，不再放导入入口）
- 导入：`http://<服务器>:8080/#/kb/docs?tab=import`（选择文件、查看导入进度和最近任务）
- 知识库管理：`#/kb/docs?tab=libraries`（新建、重命名、可见性、默认库、备份/恢复/归档）
- 知识库操作记录：`http://<服务器>:8080/#/tasks?tab=kb`（检索、修改、导入与审计）
- 单文档详情：`#/kb/docs/{doc_id}`

普通工程师看到脱敏文本和 `visibility=all` 的知识库；管理员可看原文、编辑、启停、删除、恢复版本并管理知识库。

## 2. 管理员首次启用

1. 确认「系统信息 → 运行时配置 → 故障知识库」的 `kb_enabled` 为开。
2. 进入 `#/kb/docs?tab=import`，点「载入示例」；20 条脱敏示例导入后等待索引状态变为 `ready`。
3. 在 `#/kb` 输入“看门狗复位”，确认返回答案、引用卡片和可点击详情。
4. 需要真实数据时，在「导入」标签选择目标知识库与 CSV/TXT/MD/HTML/DOCX/XLSX/PDF/图片；管理员默认直接生效，也可以选“先进入审核队列”。上传后页面会显示文件级进度，可离开页面让后台任务继续。
5. 多库场景先在「知识库」标签新建库，确认默认库和可见性；再切到问答页选择库或勾选跨库范围。

## 3. 多知识库与跨库检索

- 管理员在「知识库」标签新建故障库、专家库或语料库；每个库的文档、案例、索引和审核队列相互隔离。
- 默认库有「默认」标记；新会话和未指定库的问答优先使用默认库。默认库不能归档。
- 可将库设为「仅管理员可见」；工程师在问答页看不到该库，服务端检索也会过滤，不能靠手改 URL 绕过。
- 跨库检索最多选择 5 个库；勾选后按 RRF 融合排序，结果卡片显示来源库。选择会保存在本机 `localStorage`，也可通过 `#/kb?kb=1&cross=1&kb_ids=1,2` 分享。
- 库管理支持重命名、切换可见性、设为默认、备份、恢复和归档；归档库不出现在问答下拉，数据仍保留。

## 4. 导入格式

| 格式 | 解析单位 | 备注 |
| --- | --- | --- |
| CSV/TSV | 一行一文档 | 第一列问题、第二列答案；也识别常见列名 |
| TXT/MD/HTML | 一文件一文档 | MD 首个标题作标题；HTML 去脚本/样式 |
| DOCX | 一文件一文档 | 段落、标题样式、表格转文本；嵌入图片只告警 |
| XLSX | 一行一文档 | 读取共享字符串/内联字符串/公式缓存值；多 sheet 逐个处理 |
| 文本型 PDF | 一文件一文档 | 只抽取文本层；扫描件进入人工队列 |
| PNG/JPEG/WebP | 一文件一文档 | 校验格式与尺寸，进入人工转写；不本地 OCR |

单条答案里有多个 `【原因分析】` 时会拆成多个派生案例。例如：

```text
【详细描述】单板反复复位
【原因分析】EPLD 喂狗时序异常
【处理方案】升级 EPLD
【原因分析】电源瞬断导致复位
【处理方案】更换电源模块
```

会生成 2 个案例，分别可检索、可引用。

### 4.1 导入列映射与工作表

1. 在「导入」页选择 CSV/XLSX 后，先点「解析表头 / 列映射」，不要直接开始导入。
2. 页面显示编码、分隔符、表头、猜测映射和前 20 行脱敏样本；为每一列选择目标字段（标题、现象、原因、方案、整段答案、板卡、领域、版本、标签），或选「忽略」。
3. 同一目标字段只能映射一列；至少要有「整段答案」或一个内容字段，否则后端返回 400。
4. XLSX 有多个工作表时，页面会出现工作表下拉；切换后会重新猜测映射，确认映射后再导入。多文件导入的预览/映射只作用于第一个文件。
5. 映射会随导入任务保存到 `options_json`，可在最近任务里追溯。

## 5. 审核

工程师提交的文档进入「待审核」，管理员可：

- 查看案例预览与脱敏原文；
- 修改标题、批准入库（立即重建索引）、退回并填写原因；
- 在“AI / 人工审核”标签查看 AI 预审结果，按六维分数、问题和建议 patch 做终审；
- 勾选多条记录做批量通过、批量驳回或批量重试。批量通过仍会拦截带 blocker 的记录；驳回/重试按勾选逐条处理。

数量标签使用服务端真实 `total`，不是当前页列表长度。图片和扫描 PDF 即使管理员选择“直接生效”也会保留在审核队列，确认人工补录后再批准。

## 6. 问答与引用

- “检索并回答”：先用本地检索找案例，有真实模型时生成总结；无模型时显示“本地检索模式”。
- “仅检索案例”：不调用模型，只显示案例卡片。
- 引用 `K1..K6` 可点击跳到文档详情；详情里可看现象、原因、方案、版本历史。
- 回答里的“降级”标识表示模型不可用或失败，结论来自抽取式摘要，不是模型编造。

## 7. 案例修订与审计

管理员在文档详情页的每个案例右侧可以看到「修订 / 编辑 / 启停」：

- **修订**：打开案例时间线，查看每次变更的 action、操作人、原因、字段级前后值和 SHA256；顶部显示哈希链校验结果。
- **编辑**：必须填写变更原因；保存后追加一条 update 修订并重建索引。
- **启停**：active/disabled/archived 切换同样写入台账。
- **恢复**：在时间线里选择旧修订恢复，会生成一条新的 restore 修订，旧历史不删除。
- 全库变更与审核决策可在 `#/kb/docs?tab=audit` 查看，支持按操作人/动作筛选与 CSV 导出。

## 8. 统计

`#/kb/docs?tab=stats` 提供七组指标：库存、覆盖、使用、审核、变更、导入、索引。支持 7/30/90 天切换和 CSV 导出；库存、覆盖率、索引大小是当前真值，趋势来自查询/修订/审核/导入日志。

## 9. AI 审核

- 导入草稿默认进入 AI 预审队列；案例编辑复审默认关闭，可在运行时配置打开。
- 模型按六维评分（问答匹配、原因完整、方案可执行、实体一致、来源忠实、安全隐私），输出 allowlist 问题与可选字段 patch。
- 无模型、超时、模型失败或 JSON 不合规时转人工（manual），不影响导入；审核结果是独立维度，不覆盖字段完整度 quality。
- 管理员在「审核」页查看待审草稿与审核记录，详情里看六维分数、问题、建议 patch，再人工通过/驳回/采纳。
- **自动发布 dry-run**：审核页的「自动发布 dry-run」面板只计算哪些草稿满足 policy `review-auto-v1`，不会发布；总开关默认关闭，dry-run 默认开启。观察一段时间后，管理员才可关闭 dry-run 并开启总开关；实际发布会写 `kb.auto_publish` 审计。

## 10. 评测台

1. 进入 `#/kb/docs?tab=eval`，可导入 JSONL/JSON/CSV 评测集。CSV 列：`query,qrels,category,split`；qrels 用逗号分隔案例 ID，四类建议各 75 条。
2. 点「运行」后，系统逐条检索并记录 top-10、是否拒答与延迟；页面显示 Recall@1/5/10、MRR@10、nDCG@10、无答案准确率和 Wilson 95% CI。
3. 分类别表格中的 `—` 表示该类别没有带 qrels 的查询，不参与召回分母；库外无答案类只看拒答准确率。
4. 索引 checksum 变化时，本次 run 会标「索引已变化，不可比」；需要比较模型或词典效果时，先冻结索引再运行。
5. **qrels 必须由专家标注**，系统不会用模型生成标准答案；没有真实标注前，不要把测试集的指标当上线结论。标注流程见 `docs/评测集标注指南.md`。

## 11. 近重复合并

- 进入 `#/kb/docs?tab=dedupe`，页面列出超过默认阈值 0.82 的候选对，显示相似度、源/目标案例数和建议 canonical。
- 点「预览逐字段差异」查看标题、现象、原因、方案等字段的源/目标对比。
- 确认「合并」后，源文档标记为 `merged`，源案例逐条迁移到目标并写 `merge` 修订；不物理删除源文档。
- 合并需要管理员二次确认；合并理由与操作写审计。同一合并 token 重复执行不会重复迁移。
- 字符级相似度不是语义向量，阈值需要按现场语料校准；拿不准时先预览，不要批量合并。

## 12. 批量导出报告

- 在「文档」标签勾选一个或多个文档，点「导出报告」，下载 ZIP；内含 `report.html`、`report.md`、`data.csv`、`report.docx` 与 `manifest.json`。
- 默认导出脱敏文本；管理员可用 API 的 `reveal=true` 导出原文。单次最多 2000 个文档/案例。
- HTML 可直接浏览器打开并打印为 PDF；CSV 已做公式注入防护；manifest 记录每个文件的 SHA256。
- 当前页面只支持文档级勾选；案例级导出需调用 `POST /api/kb/export/report` 并传 `case_ids`。

## 13. 自动发布 dry-run

- 进入「审核」标签底部查看 dry-run；它只计算 `eligible/reasons`，不改变任何草稿状态。
- 只有 draft、审核 done、pass、无 blocker、分数≥90、置信度≥0.9、字段完整、非扫描/图片/人工转写占位、prompt 版本一致的记录才会被列为可发布。
- 总开关 `kb_review_auto_publish` 默认关闭；`kb_review_auto_publish_dry_run` 默认开启。不要在首次接入模型时直接关闭 dry-run。

## 14. 维护

- **重建索引**：编辑/启停/删除后自动标脏；管理员也可在文档详情或 `#/kb/docs` 手动触发。
- **版本恢复**：文档详情 → 版本历史 → 恢复；恢复会生成新版本，当前版本保留。
- **停用/删除**：停用不参与检索但保留数据；删除为软删除，版本仍保留。
- **单库备份**：知识库管理页每个库的「备份」下载 `*.kbbackup.zip`。v3 包含文档、案例、草稿、审核、修订链、词典、文档版本、导入任务和原始上传附件，带逐文件 SHA256、附件 checksum 与总 checksum；恢复前校验，坏包拒绝。v2 旧包仍可恢复。
- **恢复**：可在知识库管理页恢复为新库，或选择「合并到已有库」。恢复保留 disabled 状态、草稿、审核和修订链；修订链使用原始快照重建并重算哈希。整个恢复在单个事务内提交，中途失败不会留下半个新库。
- **合并去重**：合并到已有库时默认按来源 SHA + 内容 SHA 跳过重复文档，返回跳过计数；不覆盖已有文档和修订链。需要强制全量导入时可关闭去重。
- **完整灾备**：单库包已包含原始上传附件；仍建议定期备份整个 `data/`（含 `master.key`、数据库、上传文件、索引和配置），作为跨实例灾备兜底。
- **归档与清理**：归档库可从列表恢复；物理彻底删除不在网页按钮内，使用 `python3 tools/kb_library_purge.py --kb <id> --confirm`，执行前先下载清理清单。

## 15. 常见问题

**导入后没有结果**

先看 `#/kb/docs` 顶部索引状态；等待 `ready`，或点“重建索引”。如果文档在“待审核”，管理员批准后才进入索引。

**图片/扫描 PDF 显示待审核**

当前不内置 OCR/视觉模型，这是预期行为；请在审核弹窗中人工补录现象、原因和方案后批准。

**回答显示降级**

未配置真实模型，或模型调用失败。检索结果仍然有效；配置模型后重试，或使用“仅检索案例”。

**工程师看不到原文**

设计如此：普通用户只使用脱敏文本；管理员在详情页的“编辑与原文”区可查看原文。

**CSV 中文乱码或列不识别**

文件应为 UTF-8/GBK/GB18030；列名可用 `question/answer`、`问题/答案`、`title/content`，也可以在导入页用「解析表头 / 列映射」显式指定。复杂多行答案请用标准 CSV 引号包裹。

**评测集运行后指标都是 0**

先检查 qrels 是否为真实存在的案例 ID、查询是否属于当前库；分类别表格的 `—` 表示该类没有带 qrels 的查询。索引变化会被标记不可比，不代表检索一定失败。

**近重复页没有候选**

默认阈值是 0.82，字符差异较大时不会出现；可先降低阈值观察，但字符级相似度不是语义判断，合并前必须预览。

**自动发布按钮不可用**

总开关默认关闭，dry-run 默认开启；这是安全默认，不是故障。需要管理员在运行时配置中显式开启，并先用 dry-run 观察。
