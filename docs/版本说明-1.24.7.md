# BBU FaultScope 1.24.7 版本说明（Windows 网页上传更新）

1.24.7 为 Windows 增加「网页上传升级包 + 下次启动生效」流程；数据库 schema 保持 **21**，不改变 Linux root/systemd 升级链路。

## 一、使用流程

1. 管理员进入「系统信息 → 离线升级」，选择 Windows 分发包 `.zip`（兼容 `.tar.gz`），点击「上传并预检」。
2. 服务端计算 SHA256，检查版本必须高于当前版本，检查包内只有一个顶层目录、无路径穿越/链接/设备文件，并包含 `run.py`、`bbu/__init__.py`、`web/index.html`、`vendor/yaml/__init__.py`、`deploy/upgrade_offline.sh`、`deploy/rollback_offline.sh`。
3. 预检通过后点击「准备重启生效」，服务端在程序根写入 `pending_maintenance.json`，任务状态变为 `waiting_restart`。
4. 关闭当前平台，重新运行 `deploy\windows\start_platform.bat` 或 `python run.py`。
5. 启动阶段在打开数据库前完成：备份旧程序到 `backups/update-<任务ID>`、替换程序代码、保留 `data / skills / cases / updates / backups / config.json`。
6. 替换成功后 `run.py` 重新执行自身，加载新版本；失败时恢复旧程序并把任务标记为失败。

## 二、代码改动

- `bbu/updater.py`：拆分为「网页可上传/预检」与「可立即执行助手」两种语义；Windows 无自定义助手时返回 `restart` 模式；新增 `.zip`/`.tgz` 安全解压、真实包文件名、`prepare_restart_job()` 与 `pending_update()`；Windows 重启模式隐藏网页回滚。
- `bbu/startup.py`：新增 `update` 分支与 `_apply_update()`；启动前备份旧代码，替换后保留运行数据；复制失败自动回滚旧程序。
- `run.py`：应用更新后通过 `os.execv` 重新执行入口，避免当前进程继续持有旧模块。
- `bbu/api.py`：返回 `mode`、`rollback_supported`、`pending_update`，Windows 页面不再显示「手动更新」。
- `web/assets/js/page_admin.js`：上传接受 `.zip`，新增「准备重启生效」、`waiting_restart` 状态与重启提示，隐藏 Windows 回滚按钮。
- `docs/Windows运行说明.md`：改为网页上传 + 重启生效说明。

## 四、升级说明

- 版本号 1.24.7；Windows 包 `bbu-fault-platform-1.24.7-windows.zip`，Linux 包 `bbu-fault-platform-1.24.7-offline.tar.gz`。
- schema 保持 21，无数据库迁移。
- **首次从 1.24.6 升级到 1.24.7**：旧版 Windows 还没有「准备重启生效」和 zip 预检，无法通过网页完成这次跨版本升级；请先按手动流程停止平台、备份 `data\` 与 `config.json`、解压 1.24.7 Windows 包覆盖程序目录，再启动一次。装到 1.24.7 后，后续更新即可在网页上传 `.zip` 并选择「准备重启生效」。
- Windows 网页升级是「下次启动生效」，不会自动停服或重启；关闭平台后需手动重新启动。
