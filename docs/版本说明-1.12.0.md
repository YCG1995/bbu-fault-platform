# 版本说明 1.12.0

基线：1.11.0（schema 10）→ 1.12.0（schema 11）

1.12.0 按三项现场要求收敛用户组织字段、增加历史备份管理，并把账号注册从“必须邀请”扩展为可配置的自助注册。数据库发生一次需要删列的迁移，因此不按补丁版本发布。

## 一、用户与邀请只保留领域

- `users`、`user_invites` 建表定义删除 `team`、`site`，保留 `domain`。
- 启动迁移时对旧库执行幂等 `ALTER TABLE users DROP COLUMN team/site`、`ALTER TABLE user_invites DROP COLUMN team/site`；账号、角色、状态、领域、密码哈希和邀请记录都保留。
- `bbu/accounts.py` 的 `public_user`、邀请创建/激活、`bbu/api.py` 的搜索、用户创建/更新、用户详情全部去掉班组/站点参数与 SQL。
- 前端用户列表、用户编辑弹窗、个人中心和复核专家选择都不再显示班组/站点；个人中心改为只读显示领域。
- 旧客户端继续传 `team/site` 会被忽略，不再写入数据库。真实案例的 `real_cases.site` 是现场/设备字段，不属于用户班组站点，未改动。

## 二、系统信息新增“备份”标签页

- 新增 `bbu/backups.py::BackupManager`，扫描 `STATE_DIR/backups`（通常 `/var/lib/bbu-fault-platform/backups`）的直接子项。
- 展示字段：名称、绝对路径、类型（升级快照 / 迁移恢复前备份 / 手工或其它）、旧→新版本、创建时间、占用空间、文件数、是否被升级任务使用、引用它的升级记录。
- 新增接口：
  - `GET /api/backups`：管理员只读列表与汇总；
  - `DELETE /api/backups/{name}`：管理员 + CSRF，删除单条备份并写审计。
- 安全边界：名称白名单 `[A-Za-z0-9][A-Za-z0-9._-]*`，拒绝 `.`、`..`、路径越界和符号链接；只允许删除备份根目录的直接子项。正在 `queued/backup/migrating/restarting/health_check/rolling_back` 的升级任务所引用的快照禁止删除。
- 系统信息标签从五个扩展为六个：概览 / 运行参数 / 任务空间 / 备份 / 迁移 / 升级；备份页首次点击时才加载。

## 三、可配置的免邀请码自助注册

- 运行参数新增 `allow_self_register`，布尔值，默认 `false`。保存到 `config.json` 后立即生效，不要求重启；`/api/public/config` 会暴露当前值。
- 关闭时 `POST /api/auth/register` 返回 403；开启时允许用户名、显示名、领域、密码自助注册。
- 注册账号固定 `role=engineer`、`status=active`，不自动登录；用户名沿用 `[A-Za-z0-9._-]{3,32}`，密码执行现有 `validate_password` 策略，用户名已存在时拒绝（包括待激活邀请账号，避免绕过邀请流程）。
- 注册只按 IP 做限流，避免攻击者反复提交已存在用户名而打满该账号的登录限流；成功/失败都写审计。
- 登录页新增“自助注册（无需邀请码）”入口和注册表单；密码确认不一致时前端直接提示。

## 四、接口与数据库

- REST 路由 106 → **109**：新增 `POST /api/auth/register`、`GET /api/backups`、`DELETE /api/backups/{name}`。
- schema 10 → **11**。旧库删列使用 SQLite `DROP COLUMN`，要求 SQLite ≥ 3.35；平台一键包内置 SQLite 3.54.1。
- 迁移包 manifest 与升级后数据库写入的 `schema_version` 同步为 11。

## 五、验证结果

- 单元测试：**94/94**（新增备份管理器 3 项、自助注册/旧库删列 3 项）。
- HTTP 全量 REST 冒烟：**109/109**，覆盖注册开关、注册成功/失败、备份列表与删除、管理员权限和 CSRF。
- 浏览器验证：系统信息六标签、备份列表与删除、用户表单无班组/站点、个人中心领域、自助注册表单与注册后登录；R2 用户/审计/专家回归通过。
- 一键包 L4：1.12.0 初始包落盘、内置 Python 启动、登录、强制改密、个人 Key 接口、空备份列表和 schema 11 通过。
- 一键包 L5：1.8.0（schema 8）→ 1.12.0（schema 11）`upgrade_offline.sh --no-service` 通过，原 admin 记录与初始密码保留，升级后健康检查返回 1.12.0。

## 七、已知边界

- 历史备份页只管理 `backups` 的直接子项，不递归清理 `updates` 下的状态记录；删除被历史升级记录引用的快照后，该记录的回滚入口会失效，页面会提前提示。
- 自助注册只创建工程师账号，不提供管理员、专家角色选择；需要专家账号仍由管理员创建或邀请。
- 网页升级仍依赖目标机 `/usr/bin/sudo` setuid 正常且所在文件系统未挂 `nosuid`；若现场出现 `sudo: 有效用户 ID 不是 0`，需先修复 sudo 权限/挂载，或由 root 手工执行 `upgrade_offline.sh --no-service`。
