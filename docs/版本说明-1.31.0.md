# BBU 故障诊断平台 1.31.0 版本说明

本版把知识库从“单库 + 导入后不可逆”升级为**多知识库、可审核治理、可回退、可追踪**的 1.31.0 基线。数据库 schema 由 25 升到 26，REST 路由由 211 增到 220；升级为 additive migration，不重建旧表。

## 四个主线

### A. 状态、审核与修订链地基

- 新增确定性审核规则 `bbu/kb_review_rules.py`：六维评分重算、缺失维度转人工、blocker / 安全隐私低于 5 / 来源忠实低于 4 直接驳回；只有六维完整、总分 ≥85 且置信度 ≥0.6 才自动通过。
- AI 审核保留 `model_decision` / `model_score` 供对照；人工通过前仍检查 blocker。
- 案例通过/驳回改为 `set_case_status` 进入 append-only 修订链，不再直接改历史行。
- 审核模型支持按配置角色回退：配置角色 → `assistant` → `default`；`kb_review_model` 可填模型 ID。

### B. 导入生命周期与前端体验

- 导入任务支持目标知识库、文件级 SHA 去重和文档级 `content_sha256` 去重；重复默认跳过，并记录 `skipped_files` / `skipped_documents`。
- 新增批量**回退**、**重试失败**、**删除记录**：回退把本批新增文档停用、草稿退回，保留版本和修订链；删除只删任务/暂存，不删已入库文档；1.30.5 及以前的旧任务标记 `rollback_supported=false`，只允许删除记录。
- 左侧导航拆成「故障问答」和「知识库管理」两个入口，管理入口仅管理员可见；去掉页面内重复的双主标签。
- 审核区改为「待入库草稿 / AI 与人工审核」二级标签，支持全选、批量批准、批量退回、批量通过。
- 概览、统计、审计优先显示知识库名、案例标题、目标标题，而不是裸 ID。

### C. 多知识库数据层与索引

- schema 26 新增 `kb_libraries`、`kb_library_index_meta`，核心 KB 表增加 `kb_id`，文档增加 `content_sha256`，导入批次增加 `doc_ids_json` / `draft_ids_json` / `rollback_supported`，查询增加 `kb_ids_json`。
- 默认库固定为 id=1「故障知识库」；专家库、语料库与故障库同构，逻辑隔离、每库独立索引。
- 检索支持单库与跨库：单库仍走原排序；多库分别检索后按 RRF 融合，结果带 `kb_id` / `kb_ids`，引用可回溯。
- 新增知识库 CRUD、归档、`*.kbbackup.zip` 备份与从备份恢复；默认库禁止归档。归档后仍可备份，供删除前留档。
- 新增离线物理清理工具 `tools/kb_library_purge.py`：默认库/未归档/备份计数不一致一律拒绝；保留 `kb_case_revisions` 与 `audit_logs`，只清文档/案例/草稿/审核/导入记录/索引/术语和已无其他库引用的源文件。
- 统计、审核、草稿、审计、导入任务均支持按库过滤。

### D. 执行轨迹、跨库检索与库管理

- 导入任务、AI 审核、知识库检索均写入 `kind="kb"` 执行轨迹，记录 `import` / `import_result` / `review_result` / `retrieval`、命中案例/文档、耗时与无答案原因。
- 执行轨迹页增加「故障知识库」类型和事件标签，可从轨迹跳回导入、审核、问答页面。
- 前端增加知识库切换条、跨库检索开关、库管理标签（列表、类型/状态/文档案例数、备份下载、归档、新建、恢复）。

### E. 迁移、回归与离线包

- schema 25 → 26 的索引顺序问题已修复：依赖新列的 8 条索引从 `SCHEMA` 移入迁移段，在 `ALTER TABLE` 加列后创建，旧库启动不再报 `no such column: content_sha256`。
- 用 1.30.5 工作树生成 schema 25 迁移演练库（2268 文档 / 2762 案例 / 1 草稿 / 1 旧导入任务 / 1 审核 / 1 查询）升级：schema=26，计数不变，默认库 id=1，旧任务 `rollback_supported=0`，索引 checksum 仍为 `77afa39d929c1a9543d85897`（terms 6040，bytes 1441832），抽样文档标题一致。
- 新增 `tests/test_kb_migration.py`：删新列模拟 schema 25 后由当前代码升级，覆盖计数保持、默认库、旧任务回退标记与索引重建。
- 本版仍不包含：向量/embedding、OCR、300 条金标准正式验收、完整性能重写、AI 自动发布、物理硬删除 UI、Windows 包；物理清理只提供离线工具，不提供网页按钮。

## 升级与回滚

1. 备份 `/var/lib/bbu-fault-platform`（至少 `data/`、`master.key`、`config.json`）。
2. 解压新离线包，执行 `deploy/upgrade_offline.sh`；服务启动时自动执行 schema 26 additive migration。
3. 升级后检查「系统信息」版本为 `1.31.0`、schema 26，并在「知识库管理」逐个库查看索引状态。
4. 回滚保留 1.30.5 离线包和升级快照。新表/新列是 additive 的，旧代码可忽略；但回退前建议同时恢复升级前的 `data/` 快照。

## 已知边界

- 1.30.5 及以前的导入任务没有可靠的文档/草稿关联，不支持批次回退，只能删除任务记录。
- 从备份恢复的文档当前统一按 `active` 重建，不保留原 `disabled` 状态；需要保留停用状态时请先导出原库。
- 库的 `visibility` 字段尚未在检索/列表权限中强制；归档库仍可能被显式 `kb_ids` 检索。当前通过管理员入口和默认库限制控制主要路径。
- 知识库统计的非默认库使用 `dim_key=kb:{id}` 写入 rollup，全局趋势口径未在本版重新验收。
- 物理清理后 `kb_case_revisions` 保留为审计孤行（按设计不删），`audit_logs` 也不删；这是 append-only 审计的代价。
