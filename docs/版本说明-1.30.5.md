# BBU 故障诊断平台 1.30.5 版本说明

本版修复浏览器代理在目标网关没有放行平台 Origin 的 CORS 预检时，整条模型链路直接失败的问题。核心变化不是“绕过 CORS”，而是承认浏览器同源策略无法由前端绕过：浏览器执行失败后，如果现场 Python 可以直连同一网关，就由服务端回退执行。

schema 保持 25，REST 路由保持 211 条，浏览器代理的 Key 隔离、单次认领、URL 安全校验与预算/审计链路不变。

## 1. 运行时服务端回退

- 新增模型级配置 `extra.browser_relay.server_fallback`，默认 `true`。旧浏览器模型无需改配置即生效。
- 浏览器 `fetch` 因 CORS、混合内容、代理或 DNS 失败时，服务端捕获 `RelayExecError`，用同一 `Base URL`、`API Key`、请求体和超时策略调用 `_post_json()` 直连一次。
- 浏览器成功时不走回退，不增加额外请求；回退成功时用量记录 `transport=server`，此前会误记为 `browser`。
- 回退也失败时，错误信息同时保留浏览器失败原因与服务端失败原因，便于判断是 CORS、服务端出网还是认证问题。
- 若服务端没有出网能力，管理员在模型弹窗关闭“浏览器执行失败时自动回退服务端直连”即可保持纯浏览器代理语义。

## 2. 链路自检与模型发现

- 模型列表按钮由“浏览器内自检”改为“链路自检”。
- 浏览器执行失败且 `server_fallback=true` 时，后台用同一模型配置做一次 Python 直连；成功返回：
  - `transport=server`
  - `fallback=true`
  - `browser_error`（浏览器失败原因，截断后返回）
  - `reply` / `latency_ms` / `usage`
- 前端提示“服务端直连成功（浏览器代理已回退）”，不再只显示 CORS 失败。
- 浏览器代理模型的“获取”按钮遇到同类浏览器阻断时，也自动用服务端读取 `/models` 列表，审计记录 `transport=server` 和 `browser_fallback=true`。

## 3. 配置与提示

- 模型弹窗新增回退开关，并显示默认值；模型列表执行位置显示“浏览器代理 / 可回退”。
- `/relay-check.html` 的 CORS 结论新增提示：**Python 可直连时，直接取消浏览器代理、改服务端执行即可**；保留浏览器代理时平台也会自动回退。
- 部署手册补充：若 Python 能直连，不需要给网关配 CORS；若使用浏览器代理，再按 CORS/混合内容/PNA 要求配置。

## 4. 验证

- `pytest`：**382 passed**。
- 新增回归：浏览器 CORS 失败回退 Python 成功、关闭回退后保持失败。
- `python3 tests/api_full_smoke.py`：REST **211/211**；管理员自检接口与模型配置校验保持通过。
- `python3 tests/ui_relay_smoke.py`：顶栏徽标、模型编辑回退开关、链路自检入口与免登录自检页通过。

## 5. 部署

1. 解压 `bbu-fault-platform-1.30.5-offline.tar.gz`。
2. 已部署实例执行 `sudo bash bbu-fault-platform/deploy/upgrade_offline.sh`；全新安装执行 `install_offline.sh --port 8080`。
3. schema 保持 25，无需迁移；升级后在模型编辑弹窗确认回退开关默认勾选。
