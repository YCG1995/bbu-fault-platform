# 故障知识库设计（1.33.0）

## 1. 目标与边界

故障知识库把历史故障资料变成可检索、可引用的案例库，服务三个入口：

1. 页面 `#/kb` 的问答与检索；
2. 悬浮助手、MCP 的只读工具；
3. 诊断规划的历史参考与报告附录。

历史案例只作为参考，不能替代当前日志证据，也不改变根因仲裁。本期遵守零第三方 Python 依赖、单机多库、离线部署与单标准离线包约束。

## 2. 数据模型

```text
kb_documents（文档：来源、原文/脱敏文本、状态、版本、质量、PII）
  └─ kb_cases（案例：检索与引用单元，1..N 条）
       └─ sections_json（现象/环境/原因/方案/预防等小节）
```

一个 CSV 行、一个 DOCX、一个 PDF 或一张图片都形成文档；一个答案里出现多个 `【原因分析】` 时按原因块拆成多个案例，派生案例标记 `is_derived=1`，共享同一 `doc_id`。

主要表：

| 表 | 用途 |
| --- | --- |
| `kb_libraries` / `kb_library_index_meta` | 知识库元数据（类型、可见性、默认库、归档）与每库索引状态 |
| `kb_documents` | 文档元数据、原文/脱敏文本、板卡/领域/版本、状态、质量、所属 `kb_id` |
| `kb_cases` | 案例字段、小节、根因键、质量、状态、所属 `kb_id` |
| `kb_case_tags` | 标签 |
| `kb_import_jobs` / `kb_import_files` | 导入任务、逐文件状态、错误、SHA、存储路径 |
| `kb_drafts` | 工程师提交与管理员的审核队列（含目标库、目标文档） |
| `kb_reviews` | AI 预审与人工终审记录（目标类型/目标 ID、结论、patch） |
| `kb_case_revisions` | 案例 append-only 修订链，含快照、diff、前序哈希与 `entry_hash` |
| `kb_doc_versions` | 文档编辑/恢复快照 |
| `kb_query_logs` / `kb_feedback` | 查询、降级、零结果与用户反馈 |
| `kb_index_meta` / `kb_terms` | 索引状态与库内同义词/停用词 |
| `kb_eval_sets` / `kb_eval_queries` / `kb_eval_runs` | 评测集、专家 qrels 与冻结指标 run |
| `kb_documents` 合并列 | `merged_into/merged_at/merge_token` 与近重复合并审计 |

状态：文档 `active/disabled/deleted/merged`（删除是软删除，merged 保留软链）；案例 `active/disabled/archived/deleted`；草稿 `reviewing/approved/rejected`；审核 `queued/running/manual/failed/decided`；导入任务 `queued/processing/completed/partial/failed/cancelling/cancelled`；知识库 `active/archived`。

### 2.1 多知识库隔离

- 每个库有独立 `kb_id`、文档/案例/草稿/审核/词典/修订与索引；检索只能在同一库内完成。
- 跨库检索由服务端按库分别召回，再以 RRF 融合；返回 `kb_id` 与库名，页面标注来源库，不把案例写入另一个库。
- 普通用户只看到 `visibility='all'` 的库；`visibility='admin'` 的库只对管理员开放。默认库由 `is_default=1` 唯一指定，新会话优先使用。
- 归档库不进入问答下拉，但数据、修订和备份仍保留；默认库不能归档。

## 3. 文本处理

- NFKC、全角转半角、去零宽字符、统一标点与大小写。
- 中文使用连续片段与重叠二元组；ASCII 保留型号、版本、告警码（`0xfe`、`V4.30.20.00B219-1`、`slot6`）。
- 板卡型号规范化为大写；版本同时保留完整 token 与分段 token。
- 模板标签去序号/星号后映射为规范小节：详细描述/现象、环境、原因、方案、预防、诊断等。
- PII 在索引前脱敏：姓名+工号、工号、电话、邮箱替换为占位符。`masked_text` 用于索引、普通用户、案例字段与模型证据；`raw_text` 仅管理员可读。

## 4. 索引与召回

索引以案例为单元，包含五个字段：`title`、`symptom`、`cause`、`solution`、`body`。每个词项维护一条 posting 和五个 tf 槽位，避免同词项跨字段重复写入。

召回通道：

1. **BM25F 词法**：标题权重高于正文；返回 top 50。
2. **实体索引**：板卡/领域/版本精确命中，返回 top 50。
3. **短语索引**：标题与原因/方案整句，返回 top 20。
4. **SimHash**：近似标题召回，返回 top 10。

RRF 融合后按以下信号重排：词法归一化分数、实体覆盖、标题覆盖、目标小节命中、质量分、时效、完整度。前 5 条按根因键去重，同文档最多 2 条，并保留各通道第一名的槽位，避免融合淹没精确命中。

查询侧同义词：内置概念词典与当前库启用的 `kb_terms` 合并，按词条/别名双向匹配，最多扩展 2 个概念词；扩展发生在 `analyze_query` 的 term 集合构建阶段，写入 `QueryAnalysis.expansions`。板卡型号和版本号不扩展，术语变更不重建倒排索引。

拒答：没有词项/实体/短语命中，或分数低于 `kb_no_answer_threshold` 且没有实体命中时返回 `no_answer=true` 与空 items；不生成推测性根因。

## 5. 导入管线

```text
上传/粘贴 → 格式校验 → 文本抽取 → 文档/案例草稿 → 去重 → 审核或直接生效 → 防抖重建索引
```

- 文件先落 `data/kb/files/<sha 前缀>`，任务与逐文件状态落库；后台单 worker 顺序处理，单文件失败不影响整批。
- CSV/TSV：一行一文档；列名支持 `question/answer/问题/答案/title/content`，也可通过 `mapping` 显式指定目标字段。
- 导入预览：`POST /api/kb/import/preview` 返回编码、分隔符、表头、猜测映射和前 20 行脱敏样本；映射目标为 `title/symptom/cause/solution/board/domain/version/tags/answer`，同一目标不能映射多列，映射随 `kb_import_jobs.options_json` 保存。
- XLSX：读取 `sharedStrings`、inlineStr、公式缓存值；一行一文档，首行识别为表头；多 sheet 可按 `sheet` 选择。导入列映射的 UI 预览只作用于第一个选中文件，多文件不同表头应拆批处理。
- DOCX：`zipfile + xml.etree` 读取段落、标题样式与表格。
- 文本型 PDF：读取 FlateDecode 流中的 `Tj/TJ` 文本；扫描件没有文本层时创建 `force_review` 草稿。
- PNG/JPEG/WebP：只校验 magic bytes 与尺寸，不本地 OCR；创建 `force_review` 草稿并保留附件。
- 管理员 `kb_auto_approve_admin=true` 时普通文本直接 active；图片/扫描件不受此开关影响，必须人工确认。
- 每个导入任务绑定目标 `kb_id`，逐文件记录 SHA、状态和错误；重复 SHA 默认跳过，批次可整体回退（停用新增文档、撤回未审草稿、保留修订链）。
- 审核规则：blocker 不得直接通过；采纳 patch 或驳回后才可结束。AI 预审失败转人工，不阻断入库。
- 索引构建使用 1 秒防抖的后台线程；构建期间有新写入会在同一线程补建，避免丢更新。

## 6. 问答与引用

1. 检索始终先执行，不依赖模型。
2. `gateway.has_real_model(kb_answer_role)` 为真时调用模型；提示词只允许依据 `<cases>`，案例内容视为不可信数据，禁止执行案例里的命令。
3. 模型返回结构化答案与 `K1..K6` 引用；非法引用丢弃并回退到真实检索结果。模型失败、无模型或 JSON 不合法时返回抽取式答案并标记降级。
4. `degraded=true`、`no_answer=true` 在页面上明确展示，不伪装 AI 总结。

## 7. 权限与安全

- 登录用户可检索/问答/查看脱敏文档；工程师可提交草稿；管理员可审核、编辑、启停、删除、恢复版本、重建索引、管理知识库。
- 知识库可见性在服务端强制：检索、状态页、文档列表、facets、文档/案例详情和库下拉都会过滤 `visibility='admin'` 的库，不能只靠前端隐藏。
- KB 路由全部走登录鉴权；写操作校验 CSRF；速率限制按用户/分钟。
- 原文不返回给普通用户；`get_fault_case` 只返回案例字段；查询日志默认脱敏。
- 导入文件路径落在受控目录，文件下载校验 owner 或管理员；删除为软删除，版本保留审计。
- 诊断规划与报告只读 KB，不写回；报告附录不进入 claim 校验。

## 8. 备份、恢复与归档

- 单库备份格式为 `*.kbbackup.zip`，`manifest.json` 记录 schema、库信息、各表计数、逐文件 SHA256、附件清单 checksum 与总 checksum；恢复前校验版本、计数和 checksum，坏包直接拒绝。
- v2 包含 `documents.jsonl`、`cases.jsonl`、`drafts.jsonl`、`reviews.jsonl`、`revisions.jsonl`、`terms.jsonl`、`doc_versions.jsonl`；v3 在此基础上增加 `import_jobs.jsonl`、`import_files.jsonl` 与 `files/<sha256>` 原始附件。旧 v2 包仍可恢复。
- 恢复会保留文档/案例状态、草稿、审核、词典、修订链、文档版本、导入任务和附件行；修订链按原快照重新计算目标案例的哈希链，不伪造 revision 1。
- 恢复在同一个 SQLite 事务内完成：新库创建、文档/案例、修订、版本、草稿、审核、术语、导入任务和附件行共用一次提交；任一步失败全部回滚，不留下半个新库。
- 恢复支持“新建库”和“合并到已有库”；合并模式复用目标 `kb_id`，默认按 `source_sha256` + `content_sha256` 跳过重复文档，不覆盖已有数据，返回 `skipped_duplicates` / `skipped_cases`。需要强制全量导入可显式关闭去重。
- 附件按 SHA256 写入 `data/kb/files/`，数据库恢复 `kb_import_files.stored_path` 后，`GET /api/kb/files/<id>` 可继续下载；备份时缺失的附件会在 manifest 记 `missing_files`，恢复时对应文件行标记失败。
- 备份/恢复、导入、审核和检索均写 `kind=kb` 执行轨迹；库级操作记录可用 `GET /api/kb/operations?kb=<id>` 过滤。
- 归档库可由管理员恢复为 active；物理清理不在网页按钮内，使用离线脚本 `tools/kb_library_purge.py` 并保留清理清单与审计。

## 9. 评测台

- 数据表：`kb_eval_sets`（评测集元数据）、`kb_eval_queries`（查询、qrels、category、split）、`kb_eval_runs`（run 状态、`metrics_json`、`failures_json`）。查询与 qrels 是专家输入，系统不生成 qrels。
- 导入：JSONL/JSON/CSV；CSV 列 `query,qrels,category,split`，qrels 逗号分隔案例 ID；单集最多 5000 条。运行前可先导入 300 条四类分布数据集，真实标注由专家完成。
- 执行：逐条调用 `KBService.search(..., log=False)`，保存 top-10 case_id/title、`no_answer`、`latency_ms`、`hit_rank`、`error`；单条失败不拖垮整次 run。
- 指标：Recall@1/5/10、MRR@10、nDCG@10、no_answer_accuracy、answered_rate、avg/p95 latency；qrels 非空才进入召回分母，库外问题只进入拒答分母，空 qrels 不除零。分层输出 `by_category` 与 `by_split`，Recall@5 带 Wilson 95% CI。
- 可比性：`metrics_json` 固定 `index_checksum`、`qrels_sha256`、`config_hash`、`prompt_version`；同一冻结索引重复运行指标一致；运行前后 checksum 变化或相对上一 run 变化时标 `comparable=false` 并给 warning。
- 导出：run 的失败样例可导出 CSV/Markdown；页面只读展示，不在浏览器生成或篡改 qrels。
- 上线门槛：P0 全过、300 条基线有报告、真实数据迁移可对账、Linux/Windows 干净环境演练；没有专家 qrels，不把 Recall 数字当成验收结论。

## 10. 近重复合并

- 对同库 active、有案例的文档生成标题 + 前 4 条案例现象/原因的指纹；候选初筛使用索引已有 64 位 SimHash 的 4 个 16bit 段桶与标题桶，再做字符 3-gram Jaccard 精确相似度，默认阈值 0.82。
- 单库最多扫描 20000 文档、返回 200 对；页面展示相似度、源/目标案例数、建议 canonical 和逐字段 diff。
- 合并只“并入”不物理删除：源文档 `status='merged'`、`merged_into`、`merged_at`、`merge_token`；目标文档保留原案例，来源案例逐条写 `merge` 修订并迁移，目标 `revision` 递增。单事务提交；同 token 重复调用 no-op。
- 合并理由写审计；管理员二次确认。字符级相似度不是语义向量，阈值需用现场样本校准。

## 11. 导入列映射与批量报告

- 列映射在导入前完成：预览接口只读，不落库；猜测映射覆盖常见中英文列名；非法映射（列不存在、同目标多列、无内容字段）返回 400。
- 映射随任务保存，便于审计与重试；CSV 支持 UTF-8/GBK/GB18030，XLSX 支持多 sheet。
- 批量报告由 `KBReport` 生成 HTML/Markdown/CSV/最小 DOCX，与 `manifest.json` 一起放入 ZIP；ZIP 固定白名单，HTML 全量转义，CSV 防公式注入，manifest 记录每个文件 SHA256。
- 单次最多 2000 文档/案例；默认 masked，管理员可显式 reveal；服务端不生成 PDF，HTML 可打印为 PDF。
- UI 文档库勾选文档导出；案例级 `case_ids` 由 API 支持，当前 UI 只提供文档级选择。

## 12. AI 自动发布 dry-run

- 只对 `target_type=draft`：审核 `done`、`decision=pass`、无 blocker、`score>=90`、`confidence>=0.9`、案例现象/原因/方案完整、非扫描/图片/人工转写占位、`prompt_version=review-v1`。
- `policy_id=review-auto-v1`；dry-run 只计算 eligible/reasons，不改状态、不写文档。
- 总开关 `kb_review_auto_publish` 默认 false；`kb_review_auto_publish_dry_run` 默认 true。审核 worker 完成后才执行；实际发布由 `system:auto_publish` 写 `kb.auto_publish` 审计，review 标记 `decided` / `human_decision=auto_publish`。
- 量纲边界：当前按 AI 审核 `score` 0–100、`confidence` 0–1 解释；接入新模型/提示词后先观察 dry-run。

## 13. 未实现与后续

- 图片视觉转写、扫描 PDF OCR、复杂 PDF 版面还原。
- 真实 300 条专家 qrels 的采集、复核与版本冻结（平台只提供承载和计算，不生成标准答案）。
- 近重复阈值现场校准与语义向量通道；当前是字符级近似，不是真语义。
- 多文件不同表头的批量映射 profile；当前预览/映射只作用于第一个文件。
- 报告 UI 的案例级选择、报告 PDF 服务端生成（当前 HTML 打印替代）。
- 真实 2268/10k 性能压测与完整性能重写、Windows 内嵌运行时离线包。

这些缺口不影响 1.33.0 的“可度量、可治理”闭环，但要把评测数字当作上线门槛，仍需用真实专家 qrels 和现场样本补验。
