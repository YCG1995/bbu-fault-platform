## 3. 阶段 2：证据质量、置信度与拒判

实现：

- `bbu/evidence.py`：证据去重、文件独立性、规则独立性、根因支撑度、质量分。
- `bbu/skills.py`：`rule_meta` 输出规则权重、已验证状态和根因映射。
- `bbu/pipeline.py`：仲裁阶段加入证据质量门槛；支持 `multiple_causes`、`unknown_fault`。
- 报告与 UI 展示证据质量、并行根因、拒判原因。

行为约束：

- 同一文件、同一规则重复 20 条 → `quality_score ≤ 44`，不能升级为高置信。
- 不同文件、不同规则 → 可达到 `quality_score ≥ 70`、`confidence=high`。
- 两个独立根因均达到质量门槛 → `multiple_causes`，不强行合并成单根因。
- 有异常证据但无已知根因 → `unknown_fault`，不硬猜。

验证：`tests/test_evidence_quality.py` 4/4 通过。多根因使用构造的双技能结果验证通过；`mixed-demo` 的确定性计划只选中时钟技能，因此自然运行是单根因，不能用它冒充多根因现网样本。

## 4. 阶段 3：专家反馈闭环与技能治理

实现：

- `bbu/review.py`：专家确认/改判/驳回、经验 trust、真实案例回流、质量门禁。
- 数据表：`task_reviews`、`real_cases`、`evaluations`、`evaluation_cases`。
- 接口：`POST /api/tasks/{id}/review`、`GET /api/quality`。
- 经验隔离：未复核经验默认不进入检索；`include_unreviewed` 仅用于显式调试。
- 技能灰度：`skills.channel=stable/canary`，管理员可切换；普通任务默认只选 stable。
- UI：任务详情复核弹窗、证据质量/多根因标签、技能页灰度按钮、仪表盘成熟度卡片。

本轮修复的实际缺陷：

1. 案例回流 `ingest(labels=...)` 参数不存在 → 改为写入 `notes`。
2. 质量查询使用不存在的 `task_skills.version` → 改为 `skill_version`。
3. `quality()` 中 `(review["task_id"])` 不是元组 → 改为 `(review["task_id"],)`，修复 23 个绑定参数错误。

质量门禁当前只统计真实来源；`/api/quality` 已返回 4 项门禁和 `limitations`，不会用合成回归冒充现网结论。

## 5. 阶段 4：生产可复现

### 5.1 运行指标

- `GET /api/metrics`（管理员）：队列深度/容量、任务状态、运行阶段、技能健康、耗时 P50/P95、模型调用/失败/成功率、恢复次数、DB 大小。
- `GET /api/metrics/prometheus`（管理员或 `X-Metrics-Token`）：Prometheus 文本格式。
- 队列深度、容量、饱和度、运行/排队数均实时输出。
- 修复小样本 P95 低于 P50 的百分位错误，并新增 `tests/test_metrics.py`。

### 5.2 队列与恢复

- `max_queue` 有界队列；满队列提交/恢复直接失败并记录原因，不无限堆积。
- 服务重启时 `running` 任务在 `max_task_resume` 次数内改为 `queued` 自动恢复；超过次数才 `failed`。
- 恢复后读取 `plan.json / routing.json / task_skills`，跳过已完成技能；已有 `replan.json` 时跳过重复补规划。
- 修复“同一任务在恢复循环中被重复入队”的竞态。

断点恢复已用模拟崩溃验证：第二次运行未重新执行技能，任务仍为 `matched`，事件含“已有 1 个技能结果，跳过重复执行”。

### 5.3 离线复现与现场回传

```bash
# 生成任务级支持包（默认脱敏，不含原始日志）
python3 tools/support_bundle.py --task T2026xxxx --mode task --out support.zip

# 完整支持包（含原始输入；回传前由现场负责人确认）
python3 tools/support_bundle.py --task T2026xxxx --mode full --out support-full.zip

# 研发侧离线复现
unzip support-full.zip -d support
python3 support/reproduce_task.py \
  --task-file support/task.json --input-dir support/inputs \
  --out-dir data/repro --root /path/to/bbu-fault-platform
```

三档 `metadata / task / full` 均已生成验证；支持包自动脱敏 API Key、Bearer、Cookie、password/secret、`sk-*`、home/数据目录，hostname 固定 `<REDACTED>`，manifest 含每个文件的 SHA256。`task` 模式不含原始日志；`full` 模式才含输入和完整任务目录。

## 7. 未完成项与真实数据缺口

1. **真实标签为 0**：3 个真实包仍是 `unlabeled`；没有专家确认的 expected/excluded，不能计算真实准确率。
2. **复核样本为 0**：质量门禁的 30 个已复核任务尚未开始积累；经验库 trust 机制已就绪，但需要现场专家实际使用。
3. **多根因阈值未校准**：目前只通过构造双技能结果验证；需要在真实双故障案例上校准 `quality_score ≥ 50` 与置信度门槛。
4. **反证/阴性证据模型尚未实现**：当前只有支持度、独立性、重复度惩罚，没有显式“排除规则”；阴性案例仍依赖 `expected=__unknown__`。
5. **灰度无自动回滚**：`stable/canary` 通道已可手工切换，但未实现按错误率/复核结果自动晋升或回滚。
6. **版本级技能指标有限**：质量页按 `original_skill_version` 聚合，尚无完整的版本晋升/降级策略。

下一步优先级：先由现场专家给 3 个真实包中的至少 1 个补 expected/excluded，再积累 30 个复核任务与 10 个独立 test 案例；在达到门禁前，对外只报告“合成回归通过”，不报告现网准确率。
