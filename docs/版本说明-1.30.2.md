# BBU 故障诊断平台 1.30.2 版本说明

本版是故障知识库的体验与治理重构：把问答和管理拆成明确的主标签，把导入独立出来并补齐进度，把检索/修改纳入任务记录，同时解决大数据量下进入知识库的卡顿。数据库 schema 保持 25，REST 路由 210 → 211，新增 `GET /api/kb/operations`；继续只交付一个标准 Linux 离线包。

## 1. 页面结构

- `#/kb`：故障问答。顶部双主标签「故障问答 / 知识库管理」；检索和问答都在这里发起。
- `#/kb/docs?tab=overview|stats|docs|import|review|audit|terms|eval|settings`：知识库管理。保留原有子分区，新增独立「导入」子标签。
- `#/kb/docs?tab=docs`：文档库独立标签，只保留筛选、分页和文档列表；不再出现导入表单、最近导入或草稿审核。
- `#/kb/docs?tab=import`：导入标签。文件选择、入库方式、三步导入提示、文件级进度、最近导入任务都在这里。
- `#/tasks?tab=kb`：任务记录中的「知识库操作」视图，展示检索、人工修订、导入/审核/设置等审计操作。
- `#/dashboard`：总览新增「故障知识库」卡片，展示文档/案例/索引词项/待审核和入口按钮。

## 2. 检索进度与后台操作

检索和问答提交后，结果区先渲染进度卡：

1. 解析问题与过滤条件；
2. 检索索引与候选案例；
3. 融合排序并生成结果（问答多一步「整理回答与引用」）。

进度卡显示进度条、阶段状态、已耗时和请求参数；「查看后台操作」展开当前请求、查询词、过滤条件，并说明本次检索会写入查询日志、可在任务记录查看。完成后结果卡显示服务端返回的 `latency_ms` 和 `query_id`，并提供「任务记录」链接。

> 说明：检索/问答仍是同步请求，进度是客户端阶段展示；它不是可离开页面继续运行的服务端异步查询任务。导入是真正的后台任务，支持轮询文件级进度。

## 3. 任务记录

新增 `GET /api/kb/operations?limit=50`：

- 普通工程师：只返回本人的 `kb_query_logs` 检索记录；
- 管理员：合并检索日志、案例人工修订（排除批量导入产生的 `case.import`）和 `kb.%` 审计（导入、审核、设置等）；
- 统一字段：`kind=query/revision/audit`、`action`、`target`、`actor`、`query`、`created_at`、`detail`（耗时、是否零结果、引用数、模型）。

导入产生的逐案例修订仍在「变更与审计」完整保留；任务记录只显示一条导入审计，避免上千条导入修订淹没人工检索/修改。

## 4. 性能

真实 2,268 文档 / 2,762 案例数据下的本机实测（API 端到端，含鉴权与 JSON 序列化）：

| 请求 | 本版 |
| --- | --- |
| `GET /api/kb/status` | ~17 ms |
| `GET /api/kb/facets`（首次/缓存） | ~19 ms / ~3 ms |
| `GET /api/kb/docs?size=6&status=active` | ~30 ms |
| `GET /api/kb/docs?size=50&page=2` | ~27 ms |
| `GET /api/kb/docs?q=看门狗` | ~36 ms |
| `GET /api/kb/operations` | ~17 ms |

关键改动：

- `list_documents()` 不再先 `SELECT d.*` 并对全部文档调用 `_doc_public()`；改为 SQL 过滤/分页、只取当前页全文、只对当前页批量统计案例数。修复前隔离路径生成全部文档公开对象约 7.2 秒，修复后列表 6 条约 22 ms。
- `status()` 用一条 SQL 同时取文档、案例、草稿、待审核、修订数，减少多次 SQLite 往返。
- `facets()` 增加进程内缓存，写操作/导入/编辑/停用/重建时自动失效；避免每次进入问答页都全表扫描板卡和领域。
- 导入任务仍按原有后台 worker 执行，页面轮询 `GET /api/kb/import/jobs/{id}` 显示文件级进度。

## 6. 升级与部署

1. 解压 `bbu-fault-platform-1.30.2-offline.tar.gz`。
2. 已部署实例执行 `sudo bash bbu-fault-platform/deploy/upgrade_offline.sh`；全新安装执行 `install_offline.sh --port 8080`。
3. schema 保持 25，无需额外迁移；升级后管理端「系统信息」应显示版本 1.30.2。
4. 升级前备份 `data/`；升级后检查知识库索引状态为 `ready`，并在 `#/tasks?tab=kb` 确认检索记录可见。

## 7. 已知边界

- 检索进度不是服务端异步任务，离开页面会中断本次请求；导入任务可以离开页面继续。
- `q` 文档搜索使用 SQLite `LIKE` 在标题/脱敏正文上匹配；跨标点、繁体/简体的模糊匹配仍以检索页的归一化检索为准。
- 批量导入逐案例修订仍会写入变更链，但不在任务记录主列表展示；需要完整追溯请到「变更与审计」。
