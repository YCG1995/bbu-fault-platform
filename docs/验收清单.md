## 4. 部署验收

```bash
bash deploy/make_release.sh
sha256sum -c dist/*.sha256
# 在测试机解压后
sudo bash deploy/install_offline.sh --port 8080
sudo systemctl status bbu-fault-platform
curl -fsS http://127.0.0.1:8080/api/health
```

预期：

- 发布包不含 `data/`、`skills/`、`cases/`、`config.json`、管理员密码；
- 安装脚本检查 Python ≥3.11 与 vendor PyYAML；
- 首次初始化生成随机管理员密码（0600）；
- systemd 服务自动启动且健康检查通过；
- 重启服务后历史任务/技能/用户仍在（数据在 `--state-dir`）。

## 5. 已知未自动化项

- 真实 OpenAI/Anthropic 公网 Key 的端到端调用（当前用本地假 endpoint 验证协议形状；生产需用现场 Key 做一次「测试连通」）。
- 企业 MaaS 的真实模型标题生成成功路径；临时实例无真实模型，只验证了确定性回退。
- 大日志（GB 级）解压与磁盘上限的压测。
- 多浏览器并发 SSE 断线重连的长时间稳定性。
- systemd 安装脚本、`tools/bbu_ops.py` 的 `start/stop/restart --systemd`、`backup` 和离线 `release` 需在目标 Linux 发行版上实际执行（开发环境无 systemd）。
- Windows 服务停机/重启激活和 `restart_windows.bat` 需在真实 Windows 主机验收。
- 一键包已在当前环境用内置 Python 3.13 跑完 83 项单测；真实 Ubuntu 16.04/20.04 的 glibc、权限与端口占用仍需目标机安装验收。
