# 版本说明 1.14.0

发布日期：2026-11-25

## 主题

本版落地《BBU 诊断与技能工坊智能化改造实施计划》的 R1（可信基线与出域治理）和 R2（统一证据、诊断会话与同任务补证续跑）。

## 主要变化

### 数据出域治理

- 新增 `DataEgressPolicy`，工坊默认 `excerpt`、诊断默认 `evidence_only`。模型只接收关键字行、必要上下文和白名单证据，不再发送完整 `source_text` 或原始日志。
- 自动清理 Authorization、Bearer、API Key、Token、密码、JWT、私钥、邮箱、手机号；保留告警码、寄存器、阈值、时序等运维必需值。
- 模型出域审计只记录用途、长度、行数、SHA-256 和策略版本，不保存发送正文；工坊与诊断分别写入 `workshop_model_egress`、`diagnostic_model_egress` 审计。
- 启动时拒绝 `work_dir/data/skills/cases/examples/meta` 指向文件系统根目录，避免误清理或越界读写。

### 统一证据与会话

- 新增 `evidence_events`、`session_events`、`task_supplements` 表；数据库 schema 升到 12。
- 旧技能证据通过适配器旁路写入统一证据库，保留文件、行号、时间戳、原文摘录、内容哈希和原始文件 SHA-256；日志中的命令文本标记为不可信数据。
- 新增事件溯源 `DiagnosticSession`，任务 ID 即会话 ID，支持 revision、假设、gap、补充输入和终态摘要；不保存自由思维链。
- 任务详情新增补证面板；新增接口：
  - `GET /api/tasks/{id}/questions`
  - `GET /api/tasks/{id}/session`
  - `GET /api/tasks/{id}/evidence`
  - `POST /api/tasks/{id}/inputs`
  - `POST /api/tasks/{id}/continue`

### 同任务补证续跑

- 补充文件先写入独立 supplement 目录，再在事务中校验任务状态、`expected_revision`、`Idempotency-Key + request_hash`，写补充记录、`input_added` 会话事件和技能失效标记。
- 同一幂等键重放返回原结果，同键异内容返回 409；revision 冲突返回 409，不静默覆盖。
- 新文件按保守策略失效全部已执行技能；不删除历史结果，pipeline 加载时过滤 `invalidated=1`，并在内存重置受影响 plan step 后重跑。
- `continuation_count` 与自动恢复 `resume_count` 分离；续跑不占用服务重启恢复额度。
- 跨轮预算通过 `tasks.session_budget_json` 持久化，模型调用次数和 Token 从上一轮继续累计；墙钟仍按单轮限制。
- 队列满时续跑任务保持 `queued` 并后台补投递，不把已提交的补证直接标为失败；服务重启也会恢复 `queued` 任务。

### 真实评测门禁

- 新增任务卡 Schema 校验（`bbu/task_card.py`）：输入哈希、split、标签哈希、必需证据、允许拒判、禁止工具和 hidden 隔离声明。
- 评测新增跨 split 泄漏检查：输入指纹精确重复、标题/描述近重复（字符三元组 Jaccard ≥ 0.82）；hidden 与其它 split 存在泄漏时拒绝运行 hidden 评测。
- hidden 独立评测默认要求至少 20 个已标注案例；样本不足直接报告缺口，不使用合成 data 补齐。
- 评测摘要新增 exact/precision/recall 的 Wilson 95% 区间、F1 bootstrap 95% 区间、泄漏审计和 hidden gate；报告同步展示。
- 质量页 `GET /api/quality` 新增 `dataset_audit`，可查看 `dev/test/hidden/train` 案例数与泄漏明细。

## 兼容性与升级

- schema 11 → 12 为追加式升级：新增表、`tasks.continuation_count`、`tasks.session_budget_json`、`task_skills.invalidated`、`task_supplements.invalidated_skills_json`；不删除旧列和旧数据。
- 旧任务不强制回填会话；任务详情首次打开时按任务状态创建只读会话记录。旧技能结果继续作为报告和证据链来源。
- 1.12.0 的历史升级包仍可按原流程导入；导入后启动 1.14.0 会自动补齐 schema 12。

## 验证结果

- 单元测试：**115/115** 通过。
- REST/SSE 全量冒烟：**114/114** 路由通过。
- R2 端到端：首轮缺时钟日志 → 任务进入 `needs_data` → 同任务补充 `clock-demo.zip` 与现场回答 → `continue` → 同 task ID 得到 `matched` 的时钟失锁结论；重复提交、revision 冲突、同键异内容均按契约返回。
- 出域测试：真实工坊提示词和审计记录不含测试密钥；诊断模型载荷为脱敏证据视图。

## 数据边界

本版交付的是可信基线**框架**和当前可复现基线，不包含真实 hidden 集成绩。计划中的五条基线目前只完成了“确定性 Matcher+全技能”一条；当前 AI 工作流、无经验检索、无补规划和后续新引擎仍待 R3/R4 的开关化改造。没有现场案例和专家标注时，平台只展示样本缺口和区间，不伪造 hidden 准确率。

## 回退

- 关闭 `session_continue_enabled` 可隐藏/禁用补证与续跑接口；历史证据和会话表保留，不影响旧任务查看与报告。
- 出域策略可按用途降级到 `none`（仅确定性链路）；云端全文默认关闭，不能通过旧兼容开关绕过。
- 评测 hidden gate 只影响 hidden 运行，dev/test 评测和旧报告不受影响。
