# BBU 故障诊断平台 1.33.1 版本说明

1.33.1 是 1.33.0 的 Windows 兼容性修复版；功能、schema 27、REST 243 条和页面行为均与 1.33.0 相同。

## 修复内容

### Windows Python 3.14 自更新重启失败

- 现象：网页更新或启动时应用 `pending_maintenance.json` 后，控制台出现：

  ```text
  C:\Program: can't open file 'C:\software\bbu-fault-platform\Files\Python314\python.exe':
  [Errno 2] No such file or directory
  ```

- 根因：1.33.0 的 `run.py` 在 Windows 上使用 `os.execv(sys.executable, argv)`。CPython 3.14 的 Windows `os.execv` 会把 argv 拼成命令行；当解释器路径为 `C:\Program Files\Python314\python.exe` 时，空格把路径拆成 `C:\Program` 与 `Files\Python314\python.exe`，新进程无法启动。Python 3.14.3 实机已复现。
- 修复：Windows 分支改用 `subprocess.Popen(argv, cwd=BASE_DIR, close_fds=False)`，把完整解释器路径作为 argv 列表首项交给 `CreateProcess`；POSIX 继续使用 `os.execv`，不改变原有替换语义。
- 回归：新增 `tests/test_run_restart.py`，锁定 argv 列表、工作目录、句柄继承和 POSIX `execv` 分支。

## 升级说明

1. 已运行的 1.33.0 在升级到 1.33.1 时，仍由旧进程执行替换。旧 `run.py` 的自重启 bug 可能再报一次同样的错误；这时代码已经落盘为 1.33.1，**在平台目录重新执行一次 `python .\run.py`** 即可正常启动，之后的自动重启不再受影响。
2. 如果升级后进程没有自动拉起，先检查 `updates/<job_id>/status.json` 和 `backups/update-<job_id>/code/run.py`；程序文件已替换时不要重复执行升级，直接手工启动即可。
3. 数据目录、schema 27、配置和知识库不需要回滚；本次修复只涉及入口重启方式。
