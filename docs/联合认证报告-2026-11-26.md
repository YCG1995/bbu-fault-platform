## 一、结论先行

本轮把 17 步验收条款和前端关键工作流从“文档条目”落成了可执行、可复跑、带证据的测试矩阵。后端首次全量暴露的 1 个 fail（步骤 0 的 `unmatched` 拒判反例）已修复并重跑为 8/8；前端旧 smoke 的过期契约已修复到 5/5，FE0～FE7 在真实临时实例上完成全量执行。

但这不是“17 步全绿”或“可以宣称满足报告全部要求”的认证：

- 后端仍有 **14 个结构性 blocked 条款**，集中在真实 DAG、qrels/Recall@k、Brier/ECE、字段级 diff、规则变异矩阵、canary 自动暂停、级联失效、恢复重开、全链审计和 SFT/LoRA。
- 前端仍有 **3 个 blocked 条款**：工坊字段级 diff 完整 UI、SSE 断流探针、工坊五步真实模型全链路。
- 真实有效性证据不足：300 张任务卡和 20 张 hidden-sim 均为合成数据，**没有真实 hidden 标注集**；真实模型只覆盖 1 条 live 正例，未达到 G3 的 6 条 live 与 15 个最终场景；未跑 Windows Chrome/Edge。
- 因此只能结论为：**机制已覆盖、合成数据工程符合性基本通过、真实效果待现场数据验证**。不能写“满足报告全部要求”，不能把合成回归或旧 smoke 当成现网准确率。

### 后端 blocked 明细

- **7-A4**：当前 `BoundedAgent` 只审查计划，不存在 `bbu/dag.py`、`action_space.py`、`stop_policy.py`，不能伪称可执行 DAG 已落地。
- **8-A4**：仓库没有 qrels/分层查询集和 Recall@k 评测器；现有检索只验证“可检索”，无法量化 Recall@3 相对纯词法的提升。
- **9-A3**：`CalibrationStore` 只输出三档经验准确率和 Wilson 区间，没有 Brier/ECE/risk-coverage 计算器。
- **9-A4**：现有 evaluation summary 有 F1/误报/拒判，但没有按设备/版本/站点/故障域的分桶与 95% 区间。
- **11-A4**：`workshop_patches` 只有通用 patch 记录，缺少字段级 diff、并发 patch 冲突、无来源阻断发布的端到端测试。
- **11-A5**：缺少工坊 analyze/build 后通过 HTTP 读取 provenance、锁字段与审计计数的 E2E；现有只到 spec 层。
- **12-A3**：没有 `test-plan.yaml` / `mutation_test` 生成器；`case_matrix` 不是规则变异矩阵。
- **12-A4**：现有 intake 回归覆盖少量边界，但没有按生产根因清单强制每个根因一份近邻反例。
- **13-A5**：canary 只支持频道切换，没有指标超阈自动暂停/自动回滚执行器。
- **14-A4**：已有 experience_candidates 与校准快照，但没有一次改判触发经验/索引/校准/候选四类产物级联失效的端到端断言。
- **15-A4**：恢复状态可判别，但没有恢复失败后自动重开 HypothesisState 并进入有界补诊断的 E2E。
- **15-A5**：`recovery_runs` 有路由和表，但没有 task→approval→runbook→回执的端到端审计断言。
- **16-A1 / 16-A3**：未实现 SFT/LoRA 训练流水线、模型 Registry 灰度和一键回退；按计划自动 `not_started`，不得计入通过。

### 后端实际验证到的关键链路

- 全新数据目录冷启动；管理员初始化、模型代理注册、用户创建；重启后任务与会话恢复。
- 任务卡 schema 校验：300 张合成卡全部通过 `bbu.task_card.validate_task_card`。
- 真实模型正例一次约 3 次模型调用，完成 `done / matched / R1 参考时钟源失锁`；代理审计可看到 planner 与 writer 角色提示，未泄露密钥。
