# 领域配方与通用编译器

## 为什么要拆

`bbu/workshop_spec.py` 之前的 `_domain_spec()` 把看门狗、SSD、USB FLASH 三套规则写死在编译器里。它有三个问题：

1. **过拟合**：规则与三个示例技能高度重合，换单板、版本或寄存器布局就可能失效。
2. **隐式规则**：工坊界面上看不到“这是编译器塞进来的规则”，来源审计也定位不到原文，现场专家只能改平台代码。
3. **假 verified**：`_rule()` 默认写 `verified: true`，但并没有正例、反例、案例 ID 或回归结果支撑。

现在把边界收成三层：

| 层 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| 通用编译器 `workshop_spec.py` | 文本抽取、路径转 glob、ID/条件归一、质量审查、生成 `diagnostic_reasoning` 骨架 | 具体领域的阈值、寄存器、日志特征、根因优先级 |
| 配方库 `bbu/workshop_recipes/*.yaml` | 领域规则、根因条件、版本范围、样本案例、判断顺序、误判陷阱 | 生成技能目录、跑案例回归、签名 |
| 工坊/供应链 | 人工确认、案例回归、构建、发布验签 | 不经确认就把配方规则标成 verified |

## 配方文件

每个 YAML 文件声明：

```yaml
schema: bbu-workshop-recipe/1
id: vsw-watchdog
skill_slug: vsw-watchdog
name: VSW 看门狗复位
category: 复位类
version_scope: "VSWc/d/e 单板；其他单板与版本待补充"
verified: false
sample_cases:
  positive: [case-02-mce, case-03-caterr, case-04-power]
  negative: [case-01-normal]
trigger:
  all_terms: ["watch dog underflow"]
  any_terms: []
rules:
  - id: E1
    source: reset
    any_of: ["(07)Watch Dog Underflow"]
root_causes:
  - id: R1
    all: [E1, E2]
    excludes: []
reasoning:
  strategy: "..."
  hints: [{keyword: "mce", rule_ids: [E2]}]
  pitfalls: ["..."]
  stop_conditions: ["..."]
```

关键约束：

- `rules[].id` 必须是 `E1..En`，`root_causes[].id` 必须是 `R1..Rn`；根因只能引用存在的规则。
- 配方加载时校验 schema、ID 唯一性、规则和根因引用。
- 规则默认 `verified: false`，**配方文件里写 `verified: true` 也不会让规则变成已验证**；`apply_recipe()` 始终写入 `verified: false`。
- 每条规则带 `recipe_id`、`sample_cases`、`version_scope` 和 `source_excerpt`，可以追溯回配方文件和样本案例。
- AI 语义合并不会覆盖配方的 `category`、`version_scope`、`aliases`、`keywords`；这些字段是配方契约，不是模型可自由改写的语义。
- `diagnostic_reasoning` 的 `strategy`、`hints`、`pitfalls`、`stop_conditions` 也来自配方，编译器不再按故障名写 if/else。

## 选择方式

- `parse_source(text, recipe_id="auto")`：自动匹配只做“候选提名”，规则仍然是未验证。
- `parse_source(text, recipe_id="vsw-ssd")`：显式选择配方；未知 ID 直接报错，不静默降级。
- `parse_source(text, recipe_id="none")`：不注入任何领域规则，只走通用编译。
- 工坊新建弹窗默认 `none`，需要领域规则时显式选择；API 省略 `recipe_id` 时保留 `auto` 兼容旧调用。
- 工坊草稿保存 `recipe_id`，切换配方会清空旧的分析、校验和构建结论；构建时若 profile 仍是旧配方，会拒绝并提示重新分析。

## 验证与发布

1. 配方规则进入 profile 后仍是 `verified: false`。
2. `scaffold_child_skill.py --check` 会以“根因引用未验证规则”拒绝通过。
3. 在工坊“规则审查”中勾选并人工确认，或在 `tests/workshop_regression.py` 中模拟专家确认后跑正例/反例回归。
4. 只有 `build.verified == true`（存在案例且回归全部通过）才允许发布；发布时 `sign_skill()` 写入 `case_regression`。
5. 只做人工确认、没有案例回归的技能可以构建草稿，但 `verified=false`，不能发布。

## 新增领域

在 `bbu/workshop_recipes/` 新增一个 YAML，补 `trigger`、`rules`、`root_causes`、`sample_cases` 和 `reasoning` 即可，不需要改 `workshop_spec.py`。新增后重启服务（配方目录使用进程内缓存），再用工坊选择该配方并跑案例回归。
