# 一键部署包说明（1.22.0 初始包）

## 1. 这是什么

`bbu-fault-platform-1.22.0-ubuntu1604-offline.tar.gz` 是面向**离线、老系统**的初始部署包：

- 程序：`app/`
- 内置运行时：`runtime/python/`（CPython 3.13.18，自带 OpenSSL/SQLite）
- 安装器：`install.sh`
- 现场说明：`安装说明.txt`

目标机不需要预装 Python、pip、Node，也不访问外网。程序、运行时、数据三分目录：

| 内容 | 默认路径 | 权限 |
| --- | --- | --- |
| 程序 | `/opt/bbu-fault-platform` | root 只读 |
| 运行时 | `/opt/bbu-python313` | root 只读 |
| 运行数据根 | `/var/lib/bbu-fault-platform` | `bbu` 用户可写；`data`、`skills`、`cases`、`updates`、`backups` |

后续更新只替换程序目录；运行时和数据不动。当前初始包已包含统一工作目录与精简迁移包能力。

## 2. 安装

```bash
sha256sum -c bbu-fault-platform-1.22.0-ubuntu1604-offline.tar.gz.sha256
tar -xzf bbu-fault-platform-1.22.0-ubuntu1604-offline.tar.gz
cd bbu-fault-platform-1.22.0-ubuntu1604-offline
sudo bash install.sh
```

完成后：

```bash
sudo cat /var/lib/bbu-fault-platform/data/初始管理员密码.txt
sudo systemctl status bbu-fault-platform
```

浏览器访问 `http://<服务器IP>:8080/`，用户名 `admin`，首次登录强制改密。

常用参数：

| 参数 | 默认 | 用途 |
| --- | --- | --- |
| `--prefix` | `/opt/bbu-fault-platform` | 程序目录 |
| `--python-prefix` | `/opt/bbu-python313` | 内置运行时目录 |
| `--state-dir` | `/var/lib/bbu-fault-platform` | 数据目录 |
| `--host` | `0.0.0.0` | 监听地址；反代场景设 `127.0.0.1` |
| `--port` | `8080` | 端口 |
| `--user` | `bbu` | 运行账号 |
| `--no-service` | 否 | 不装 systemd，只落盘/初始化（非 root 测试） |
| `--no-helper` | 否 | 不安装网页升级助手 |
| `--force` | 否 | 覆盖已有程序目录，数据保留；仅修复/重装用 |

安装器会：

1. 检查 x86_64、glibc ≥ 2.17、端口和内置 Python；
2. 停止旧服务（如有），创建 `bbu` 账号；
3. 落盘运行时与程序，生成绝对路径 `config.json`；
4. 建状态目录并执行 `run.py --init-only`，生成随机管理员密码；
5. 写 Ubuntu 16.04 兼容的 systemd 单元，启动并轮询 `/api/health`；
6. 安装 `bbu-upgrade-helper@.service`，为后续网页更新做准备。

## 2.1 统一工作目录与迁移（1.10.0）

状态目录现在是一个统一工作目录，标准布局：

```text
/var/lib/bbu-fault-platform/
  data/       数据库、上传、任务、密钥
  skills/     技能源码与版本
  cases/      案例元数据
  updates/    升级与迁移任务记录、临时工作区
  backups/    覆盖恢复前的旧数据
```

安装器生成 `config.json` 时仍写入 `data_dir/skills_dir/cases_dir`；平台会取三者的公共父目录作为 `work_dir`。也可以直接配置：

```json
{"work_dir": "/srv/bbu-runtime"}
```

或用 `BBU_WORK_DIR` 环境变量覆盖。统一目录切换可在「系统信息 → 工作目录与迁移」完成：

1. 预检目标路径（必须为空或不存在，且位于 `/var/lib`、`/srv`、`/data`、`/mnt` 之下）；
2. 输入管理员密码提交，root/systemd 助手会停服、复制精简工作区到目标、改写 systemd 环境变量和 `ReadWritePaths`，再启动并做健康检查；
3. 旧目录保留，不自动删除；失败自动恢复旧配置并重启旧服务。

`/etc/bbu-upgrade.json` 的 `allowed_work_roots` 控制允许根目录。如果 `--state-dir` 不在默认四个根下，请先编辑该字段，否则助手会拒绝切换。

迁移包导出/导入同样在管理页完成。包内不包含原始上传、案例输入、解压目录和登录会话；目标实例覆盖恢复前会备份 `data/skills/cases`。迁移包使用纯 Python ChaCha20-Poly1305，目标机没有 `cryptography` 也能解密；速度约 0.7 MB/s。

## 3. 后续更新

初始包已把升级助手配置为使用 `/opt/bbu-python313/bin/python3.13`，后续收到普通更新包（如 `bbu-fault-platform-1.22.0-offline.tar.gz`）直接：

1. 登录平台 →「系统信息 → 离线升级」；
2. 上传 `.tar.gz` 与版本号；
3. 预检通过后执行；
4. 失败可在同一页面回滚。

更新包只含程序代码，不包含运行时；升级脚本会自动使用已安装的 `/opt/bbu-python313`，数据目录保留。不要用 `install.sh` 覆盖方式做版本升级。

手动验证升级助手：

```bash
sudo cat /etc/bbu-upgrade.json
sudo systemd-analyze verify /etc/systemd/system/bbu-upgrade-helper@.service
sudo systemctl status bbu-fault-platform
```

## 4. 构建方法（研发侧）

```bash
# 1. 下载 python-build-standalone install_only（x86_64 baseline）
#    要求 glibc 2.17，解压后目录含 bin/python3.13
# 2. 生成一键包
bash deploy/make_oneclick.sh --runtime /path/to/python
```

产物：

```text
dist/bbu-fault-platform-1.22.0-ubuntu1604-offline.tar.gz      约 76MB
dist/bbu-fault-platform-1.22.0-ubuntu1604-offline.tar.gz.sha256
```

`make_release.sh` 仍用于生成**更新包**（只含程序，不含运行时）。

## 6. 常见问题

| 现象 | 处理 |
| --- | --- |
| 端口被占用 | `--port 8090` 或先释放 8080 |
| 页面 403/500 | 检查程序目录 root 只读、状态目录属于 `bbu` |
| 不知道初始密码 | 看 `<状态目录>/data/初始管理员密码.txt` |
| 网页升级不可用 | 检查 `bbu-upgrade-helper@.service` 与 `/etc/bbu-upgrade.json` |
| 网页升级报“有效用户 ID 不是 0” | 先执行 `systemctl show bbu-fault-platform -p NoNewPrivileges`；为 `yes` 时用 `fix_upgrade_helper.sh --fix-nnp` |
| 网页升级报 `/usr/bin/systemctl: 没有那个文件或目录` | 用 1.20.2 及以后包内 `deploy/bbu-upgrade-helper-trigger` 覆盖 `/usr/local/bin/bbu-upgrade-helper-trigger` |
| 升级成功、版本已变但页面报未知错误 | 旧触发器同步等待 oneshot，停服切断了 HTTP 响应；刷新页面确认版本，后续使用带 `--no-block` 的新触发器 |
| 公司内网 MaaS 连接失败 | 确认在办公网/VPN；个人 Key 在个人中心配置 |
| 更新包校验失败 | 先 `sha256sum -c`，确认传输完整 |
