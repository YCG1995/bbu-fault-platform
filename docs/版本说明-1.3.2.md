# 版本说明 · 1.3.2（R1 账号安全与登录体验）

日期：2026-11-25  
基线：1.3.1

## 1. 本版改动

### 服务端

- 统一认证入口强制 `must_change`：未改初始密码时仅允许 `/api/auth/me`、`/api/auth/password`、`/api/auth/logout`，其余受保护 API 返回 `403`，`detail.code=password_change_required`。
- 用户自己改密：撤销其他会话，当前会话保留并轮换 CSRF；管理员重置密码、停用账号：撤销目标用户全部会话。
- 初始管理员首次改密成功后自动删除 `data/初始管理员密码.txt`；文件不存在不影响启动。
- 登录限流改为 `IP + username` 双计数：账号连续失败 10 次锁定该账号，IP 失败总量默认 30 次；仅当直连地址命中 `trusted_proxies` 时才信任 `X-Forwarded-For`。
- 新增 `cookie_secure` 配置，HTTPS 部署可让会话 Cookie 带 `Secure`。
- 密码策略默认最小 10 位，拒绝包含用户名、常见弱口令和单一字符类别；仅作用于新建/改密，不影响既有密码登录。
- 新增会话管理 API：会话续期、当前用户会话列表、退出其他设备、撤销指定会话。
- 登录、改密、重置、停用、会话续期/撤销均写入审计日志；审计不记录令牌、密码或 API Key。

### 前端

- 登录页支持记住用户名、密码显隐、Caps Lock 提示、登录失败等待秒数提示。
- 会话到期前默认 120 秒提示，可“继续在线”或重新登录。
- 401 使用重新登录弹窗，不清空当前页面、表单和上传选择。
- 首次改密页展示密码策略；修改密码后提示已退出的其他会话数量。

## 2. 新增配置

```json
{
  "session_hours": 12,
  "session_warn_sec": 120,
  "cookie_secure": false,
  "password_min_length": 10,
  "login_rate_window_sec": 300,
  "login_rate_ip_limit": 30,
  "login_rate_account_limit": 10,
  "trusted_proxies": []
}
```

对应环境变量：`BBU_SESSION_WARN_SEC`、`BBU_COOKIE_SECURE`、`BBU_PASSWORD_MIN_LENGTH`、`BBU_LOGIN_RATE_IP_LIMIT`、`BBU_LOGIN_RATE_ACCOUNT_LIMIT`、`BBU_TRUSTED_PROXIES`。

反向代理部署时，将代理的直连地址或网段写入 `trusted_proxies`，例如 `["10.0.0.0/24"]`；未配置时始终使用直连地址，伪造 `X-Forwarded-For` 无效。HTTPS 环境必须设置 `cookie_secure=true`。

## 3. 新增 API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/refresh` | 续期当前会话，需 CSRF |
| GET | `/api/auth/sessions` | 当前用户活跃会话（不含令牌） |
| POST | `/api/auth/sessions/revoke-others` | 退出其他设备 |
| DELETE | `/api/auth/sessions/{id}` | 撤销指定会话，不能撤销当前会话 |

## 5. 升级与回滚

使用 1.3.2 离线包中的升级脚本：

```bash
sudo bash <新包>/bbu-fault-platform/deploy/upgrade_offline.sh
```

本次无数据库 schema 变更，升级后检查：

1. `/api/health` 版本为 `1.3.2`；
2. 管理员使用原密码登录，首次改密文件不存在也能正常登录；
3. 新建或重置一个账号，确认首次登录被要求改密；
4. 回滚使用同一升级快照：

```bash
sudo bash /opt/bbu-fault-platform/deploy/rollback_offline.sh --backup <快照> --with-state
```
