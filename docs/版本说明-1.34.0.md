# BBU 故障诊断平台 1.34.0 版本说明

1.34.0 聚焦故障知识库的可用性：问答历史与检索进度持久化、模型超时可见、文档库与案例编辑改造、审计深链和近重复预览内容。schema 28，REST 252 条。

## 新增与修复

### 1. 故障问答：历史对话与进度刷新不丢

- 新增 `kb_chat_sessions` / `kb_chat_messages`（schema 28），按用户隔离保存会话、消息、进度与回答。
- 新增接口：`GET/POST /api/kb/chats`、`GET/DELETE /api/kb/chats/{id}`、`POST /api/kb/chats/{id}/messages`、`GET /api/kb/chats/{id}/messages/{mid}`。
- 问答改为服务端异步任务：提交后立即返回，后台线程依次写入“解析 → 检索 → 排序 → 生成回答”进度；页面刷新后重新挂载轮询，进度与结果继续显示。
- 服务重启时，未完成的助手消息标记为 `interrupted` 并给出原因，可在对话里直接重试。
- `/api/kb/chat` 同步接口保留，兼容既有工具与脚本。

### 2. 模型超时与执行轨迹

- `KBService.answer()` 现在把检索、模型请求（`gateway.complete(trace=...)`）、回答事件写入同一条 `kind=kb` 轨迹；模型请求失败会记录 `model_error`。
- 回答结果新增 `model_status`：`ok` / `timeout` / `no_model` / `error` 与 `latency_ms`、原因文本；页面显示“模型调用超时，已降级为本地检索摘要”和轨迹入口。
- 超时分类同时识别 `timeout`、`timed out` 和中文“超时”。

### 3. 文档库编辑体验

- 文档详情改为多标签：概览 / 案例 / 编辑原文 / 版本 / 修订记录。
- 案例编辑弹窗改为三标签（标题与现象、原因与方案、预防与变更），补字段指引与必填校验。
- 保存案例后自动跳到“修订记录”并高亮该案例的新修订；从修订记录页再次保存也会立即刷新计数和列表（不再因 URL 未变化而停留在旧数据）。
- 内容没有任何变化时不再提示“新增修订”，后端返回 400 明确说明未生成修订。
- 修订列表直接展示字段 diff，动作和审核状态显示中文。
- 案例停用后仍返回详情页并标记“已停用”，提供“恢复启用”；文档停用/启用同样保留。
- 新增 `GET /api/kb/docs/{id}/revisions`，文档级修订列表不再需要逐条打开案例。
- 新增“AI 优化”按钮与 `POST /api/kb/cases/{id}/ai-polish`：模型只生成建议稿，不直接落库；应用时只填入有改动的字段，仍需人工核对与填写变更原因。无模型时明确返回 503。
- 新增“修复现象重复标题”维护动作与 `POST /api/kb/maintenance/repair-symptoms`，批量清理历史导入拼进现象的标题并写审计。

### 4. 变更与审计可直达文档

- `list_audit` 的每条记录新增 `doc_id`、`case_id`、`href`；案例修订、案例状态、文档操作都能从审计表点进对应文档/案例。
- 修复文档详情路由只匹配无参数 URL 的问题：`#/kb/docs/{id}?tab=...&case=...` 现在能直接打开并定位案例。
- 页面“对象”列改为链接，保留原始对象 ID 便于检索。

### 5. 编辑案例：现象不再重复标题

- `kb_text` 新增 `strip_title_prefix`：仅在标题后紧跟分隔符时裁剪，避免误伤“标题+正文”粘连的正常句子；同时清理标题后的“（详细描述的附件…）”模板噪声。
- 导入解析补上 `故障现象 / 故障描述 / 问题现象` 三个模板别名；没有现象小节时不再用标题顶替现象。
- 展示层（`get_case` / `get_document`）与应用层（`update_case`）双重去重，历史数据可用维护按钮一次性修复。

### 6. 近重复合并预览可读

- `duplicates/preview` 的字段对照改为全字段返回（标题、案例数、现象、原因、处理方案、预防、板卡、领域、版本、质量），每项带 `same` 标记。
- 新增 `source_case_list` / `target_case_list`，直接展示两侧案例正文（单字段最多 1600 字），不再只看到 JSON 差异。
- 页面用可滚动文本块展示，相同字段也保留，便于判断合并是否安全。

## 升级说明

1. 启动时自动建新表，schema 从 27 升到 28；不需要手工迁移，原有文档、案例、修订链不受影响。
2. 历史数据中“现象 = 标题 + 描述”的记录不会自动改写；管理员可在文档详情“概览”点击“修复现象重复标题”，执行前会二次确认。
3. AI 优化依赖已配置的可用模型；无模型或模型超时不会阻塞编辑，只返回明确错误或降级提示。
4. 旧客户端仍可调用 `/api/kb/chat`；新页面默认使用会话接口。

## 已知边界

- 问答进度是 1.2s 轮询而非 SSE；同一会话串行使用，多个标签页同时提问会各自排队。
- 会话只对当前用户可见，不提供团队共享会话；审计仍只记录删除会话动作。
- AI 优化质量取决于模型与原文信息量，不补造缺失事实。
- `api_full_smoke.py` 在本机 Windows 环境运行到离线升级段落时，因升级包路径问题返回 400，与本次知识库改动无关；知识库部分由定向脚本覆盖。
