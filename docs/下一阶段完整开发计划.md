# BBU 故障诊断平台：下一阶段完整开发计划

> 基线：`1.3.1` · 计划日期：2026-11-25  
> 目标：在不影响现有诊断、案例、复核和离线部署能力的前提下，完成账号安全、用户体验、权限治理和网页离线升级，并继续推进真实案例成熟度。

## 1. 现状与约束

已有能力：

- 四阶段主体功能、40+ 单元测试、56 条 REST 路由回归、75 例合成案例回归。
- 本地账号、scrypt、CSRF、HttpOnly/SameSite Cookie、审计、admin/engineer 两级权限。
- 命令行离线升级、完整备份、数据库迁移、健康检查和回滚脚本。
- 当前开发服务已运行 `1.3.1`。

已确认缺口：

- `must_change` 只在 UI 强制，API 可绕过；改密/重置/停用不撤销旧会话。
- 初始管理员密码文件改密后仍存在；登录限流只按 IP；用户搜索、筛选、分页和会话管理缺失。
- 只有 admin/engineer；专家跨任务复核没有合适的 reviewer 角色。
- 会话过期会丢当前页面上下文；登录、表单、移动端、通知和空状态仍可优化。
- 网页离线升级尚未实现，不能让 Web 进程直接获得 root 或任意 shell 能力。
- 3 个真实日志包仍为 `unlabeled`；真实准确率尚不能计算，合成 75/75 不能作为现网指标。

基本决策：

- **不做公开注册**：采用管理员邀请、一次性激活码或可选 LDAP/AD/OIDC 自动开户。
- **不做联网自动更新**：只做管理员上传离线包后的受控升级。
- **不让主 Web 服务自我提权**：升级由独立、受限的 root/systemd 助手执行。
- 所有数据库迁移保持幂等、尽量只做新增；升级必须保留 `config.json`、数据库和 `master.key`。

## 3. R1：账号安全与登录体验（先做）

### 3.1 服务端账号安全

1. 在统一认证入口强制 `must_change`：
   - 仅允许 `/api/auth/me`、`/api/auth/password`、`/api/auth/logout`；
   - 其他受保护 API 返回 `403 password_change_required`；
   - 前端收到后进入改密页，不暴露额外账号信息。
2. 会话撤销：
   - 自己改密：撤销其他会话，当前会话可保留并轮换 CSRF；
   - 管理员重置：撤销该用户全部会话；
   - 停用账号：立即撤销全部会话；
   - 增加“退出所有设备”和管理员“强制下线”。
3. 初始管理员密码：
   - 首次改密成功后自动删除 `data/初始管理员密码.txt`；
   - 文件不存在不影响启动；
   - 后续版本可升级为一次性初始化向导。
4. 登录限流：
   - 计数键改为 `IP + username`，同时保留 IP 总量上限；
   - 仅信任显式配置代理的 `X-Forwarded-For`；
   - 返回剩余等待秒数，前端显示倒计时；
   - 登录错误继续统一为“用户名或密码错误”。
5. Cookie 与密码策略：
   - 增加 `cookie_secure` 配置，HTTPS 部署开启；
   - 密码最小长度调整为 10–12 位，拒绝用户名和常见弱口令；
   - 不强制频繁换密，优先保证可记忆性和会话撤销。

### 3.2 登录交互

- 记住用户名，不保存密码；密码显示/隐藏、Caps Lock 提示。
- 会话到期前 2 分钟提示，可续期或重新登录。
- 401 时使用重新登录弹窗，保留当前表单、任务草稿和页面位置。
- 登录、改密、重置、停用均写审计日志。

### 3.3 验收标准

- `must_change=1` 用户访问任意业务 API 均返回 403，改密后恢复。
- 同用户两个会话，A 改密后 B 立即 401；管理员重置和停用同样生效。
- 首次改密后初始密码文件被删除。
- 同一代理 IP 下，账号 A 连续失败不会锁死账号 B；单 IP 仍受总量限制。
- HTTPS 配置下 Cookie 带 `Secure`；HTTP 开发环境仍可登录。
- 会话过期重新登录后，原任务描述、文件选择和未保存编辑不丢失。

## 4. R2：注册替代方案、用户管理与专家权限

### 4.1 邀请开户

流程：

1. 管理员填写用户名、显示名、角色、领域、到期时间；
2. 系统生成一次性激活码，只显示一次，默认 24 小时过期；
3. 数据库只保存激活码哈希、使用状态和过期时间；
4. 用户通过激活码设置自己的密码，账号从 `invited` 变为 `active`；
5. 激活码使用、过期、撤销全部审计。

1.12.0 起可由管理员开启 `allow_self_register`，允许匿名自助创建普通工程师账号；关闭时仍只走邀请激活。未开启时如需自助申请，仅提供“账号申请 → 管理员审批”队列，不直接创建可用账号。

### 4.2 用户管理页

- 搜索：用户名、显示名、领域；筛选：角色、状态；服务端分页。
- 支持批量停用，但不能批量删除审计关联账号。
- 用户详情抽屉：基本资料、最近登录时间/IP/UA、活跃会话、最近审计、重置密码、强制下线、停用。
- 个人中心：用户可修改显示名、密码、通知偏好，查看并撤销自己的其他会话；用户名、角色和领域由管理员管理，个人中心只读显示领域。
- 账号状态：`invited / active / disabled / expired`。
- 危险操作明确影响范围，保留“至少一个启用管理员”和“不能停用当前账号”保护。

### 4.3 角色与权限

优先增加 `reviewer`，避免一次引入过多角色：

- `engineer`：创建并查看自己的任务、维护自己的工坊草稿。
- `reviewer`：查看被分配任务、提交复核；不能管理用户、模型、发布技能或升级系统。
- `admin`：全部管理能力。

后续确有需求再增加 `viewer/auditor`。提供权限矩阵页，所有授权由服务端校验，不能只靠隐藏菜单。

### 4.4 审计体验

- 时间、用户、动作、对象、结果筛选；服务端分页；导出 CSV。
- 用户详情和任务详情可跳转到对应审计记录。
- 登录失败分类记录，但前端不暴露账号是否存在。
- 审计导出也需要管理员权限并写入审计。

### 4.5 管理员安全设置（P2）

- 可选 TOTP 二次验证和一次性恢复码；默认关闭，不影响现有本地账号。
- 开启/关闭 MFA 必须重新认证，恢复码只显示一次且数据库只存哈希。
- 管理页可配置会话时长、密码最小长度、Cookie Secure 和邀请有效期；配置修改写审计。

### 4.6 可选 SSO

现场提供 LDAP/AD/OIDC 时才进入开发：先实现只读连接测试，再做组到角色映射和首次登录自动开户；保留本地应急管理员。没有明确环境前不阻塞 R2 发布。

### 4.7 验收标准

- 激活码单次使用、过期失效、撤销失效，管理员无法查看用户最终密码。
- 用户列表 1000 条数据时分页和筛选有效，无全量加载。
- reviewer 只能访问分配任务和复核接口，访问用户/模型/升级接口返回 403。
- 停用或强制下线后，目标用户现有页面下一次请求立即失效。
- 审计筛选、导出、权限与日志内容一致。

## 5. R3：诊断工作台与通用用户体验

### 5.1 新建诊断

- 分步但不强制向导：故障描述 → 上传日志 → 模式与技能 → 确认提交。
- 服务端草稿自动保存，刷新/401/误关闭后可恢复。
- 上传显示单文件和总进度、速度、失败原因；支持暂停前取消和失败重试。
- 文件格式、大小、数量在提交前校验；错误定位到具体文件。
- 未保存离开提醒；重复提交按钮始终防重。

### 5.2 任务详情与复核

- 任务阶段时间线：受理、盘点、规划、技能执行、仲裁、报告、复核。
- 每个阶段显示开始/结束时间、耗时、失败原因和下一步建议。
- 证据、拒判、多根因和复核结果保持现有展示，增加“为什么得出这个结论”的折叠说明。
- reviewer 有待办入口；复核意见支持草稿，提交后不可静默修改。

### 5.3 全局体验

- 首次登录 checklist：管理员“配模型/装技能/建任务”，工程师“建首个任务”，reviewer“处理首个复核”。
- 空状态提供明确下一步；加载使用骨架屏；错误提示包含可执行动作。
- 站内通知：任务完成/失败、待复核、升级结果、账号状态变化；不依赖外部邮件。
- 全局搜索：任务 ID、标题、案例、技能；按权限过滤结果。
- 危险操作统一二次确认；所有异步按钮有进行中、成功和失败状态。

### 5.4 移动端与无障碍

- 375px 宽度下无整页横向滚动；用户、任务、审计宽表格改卡片/抽屉。
- 移动端优先支持查看、复核和通知；复杂用户管理仍以桌面为主。
- 关键操作触控区域至少 44px；弹窗支持 Esc、焦点回收和键盘导航。
- 状态不只依赖颜色；表单有 label；正文和控件对比度满足可读性要求。

### 5.5 验收标准

- 新建任务中途刷新或重新登录，草稿和已上传文件引用可恢复。
- 大文件上传有真实进度，失败可重试，不产生重复任务。
- 任务每个阶段可追溯，失败时有下一步建议。
- 移动端 375px 和桌面 1440px 关键流程无阻塞；键盘可完成登录、新建任务和复核。
- 通知和全局搜索不越权显示他人数据。

## 6. R4：网页上传离线包并自动升级

### 6.1 页面流程

```text
上传离线包 → 结构/大小/SHA/签名预检 → 显示版本与发布说明
→ 检查运行任务和磁盘空间 → 管理员密码与二次确认
→ 自动备份 → 停止服务 → 数据迁移 → 替换代码 → 重启
→ 浏览器自动重连 → 健康与版本检查 → 成功或回滚
```

页面显示当前版本、目标版本、包 SHA256、大小、备份位置、实时阶段、日志摘要和最终状态。升级过程中禁止重复提交。

### 6.2 权限与执行架构

- 主 Web 服务仍以 `bbu` 用户运行，不放开任意 sudo，不关闭 `NoNewPrivileges`。
- 包上传到 `STATE_DIR/updates/<job_id>/`，只读固定请求格式。
- 独立 root/systemd 一次性助手读取请求，仅允许调用 `deploy/upgrade_offline.sh` 和 `rollback_offline.sh`。
- 助手不接受任意命令、任意路径；路径必须位于受控更新目录。
- 更新状态写入 `status.json` 和升级历史，服务重启后页面继续查询，不因 SSE/HTTP 断开误判失败。

### 6.3 预检规则

- 管理员 + CSRF + 重新输入密码；高风险操作写审计。
- 仅 `.tar.gz`，独立大小上限；拒绝绝对路径、`..`、链接逃逸和异常条目。
- 必须包含 `run.py`、`bbu/__init__.py`、`vendor/yaml`、`web/` 和升级脚本。
- 校验 SHA256；SHA 只证明完整性，正式发布建议增加签名验证，证明来源可信。
- 默认只允许更新版本；同版修复需显式确认，降级走回滚入口。
- 有运行任务时默认阻止；磁盘空间不足时阻止；已有升级任务时返回 409。

### 6.4 建议 API

- `POST /api/system/updates/upload`
- `POST /api/system/updates/{id}/verify`
- `POST /api/system/updates/{id}/apply`
- `GET /api/system/updates/{id}`
- `GET /api/system/updates`
- `POST /api/system/updates/rollback`

复用现有升级/回滚脚本，不在 Python Web 代码里复制一套覆盖逻辑。

### 6.5 验收标准与故障注入

- 篡改包、错误签名、路径穿越、超大包均在换码前拒绝，原服务不受影响。
- 普通工程师和 reviewer 无法访问任何升级接口。
- 服务重启导致浏览器断开后，刷新可恢复到正确升级状态。
- 真实旧包升级后，配置、账号、案例、技能和 `master.key` 保留。
- 模拟备份失败、磁盘不足、迁移失败、服务启动失败、健康检查超时；均有明确状态和可执行回滚。
- 完整回滚后版本和升级前数据恢复；当前数据移入 `rollback-safety`。
- 并发点击只产生一个执行中的升级任务。

## 7. R5：真实案例与诊断成熟度持续推进

这部分依赖现场专家，不以开发完成代替数据成熟。

1. 标注工作流：
   - reviewer 可分配案例、填写 expected/excluded、证据时间窗和恢复结果；
   - 案例版本化，标签修改保留历史；
   - `dev/test/hidden` 切分，test/hidden 不参与规则调参。
2. 评测看板：
   - 展示 exact、误报、漏报、拒判率、置信度校准；
   - 明确样本量、案例来源和版本；
   - 未达门槛继续显示 `ready_for_real_data=false`。
3. 证据质量：
   - 用真实双故障案例校准多根因阈值；
   - 引入显式反证/排除规则；
   - 对 unknown_fault 和 multiple_causes 做专家复核闭环。
4. 技能治理：
   - canary 版本级指标、人工晋升/降级；
   - 自动回滚只有在样本量和误判证据充分后启用。
5. 数据目标：
   - 30 个已复核真实任务、20 个 golden 真实案例、10 个独立 test/hidden 案例；
   - 达标前只报告合成回归和真实样本覆盖，不宣称现网准确率。

## 8. 跨版本非功能要求

- **兼容性**：新增 API 不破坏旧字段；数据库迁移幂等；旧配置缺省项自动使用新默认值。
- **安全**：所有新写操作有 RBAC、CSRF、审计；高风险操作再认证；日志不记录密码、激活码或 API Key。
- **可靠性**：升级、恢复、评测、复核均能从持久化状态恢复；单个案例失败不中断批次。
- **性能**：用户、审计、任务和通知全部服务端分页；大文件上传流式处理，不读入整个内存。
- **可观测**：新增登录失败、会话撤销、邀请、复核待办、升级阶段/耗时/失败原因指标。
- **隐私**：支持包继续默认脱敏；升级快照包含密钥和真实日志，必须按敏感介质管理。

## 9. 测试与发布门禁

每个迭代必须同时交付：

1. 单元测试：认证、权限、状态机、输入校验、迁移。
2. API 测试：正向、401/403/409、越权、CSRF、分页、重复提交。
3. UI/E2E：登录、邀请、复核、新建任务、通知、升级状态恢复。
4. 安全测试：路径穿越、签名/哈希错误、会话固定、越权、暴力尝试、恶意上传。
5. 升级测试：旧版安装 → 新版升级 → 数据/配置检查 → 完整回滚。
6. 故障注入：磁盘不足、DB 迁移失败、服务启动失败、健康检查超时、浏览器断连。
7. 文档：用户操作、管理员操作、API 变更、升级说明、回滚说明。
8. 发布物：离线 tar.gz、SHA256、版本说明、升级快照机制验证记录。

发布硬门禁：

- 所有测试通过；无 P0/P1 未解决缺陷。
- 至少一次真实离线包升级和回滚成功。
- 不改变真实案例的标签与切分，不用合成数据替代真实验收。
- 网页升级功能必须先在测试环境完成一次“用网页升级下一小版本”的 dogfood 验证。

## 10. 上线与回退策略

- 每个版本先在开发环境，再在隔离测试环境，最后进入生产维护窗口。
- 生产升级前检查运行任务、磁盘空间和最近备份；默认停服升级。
- 升级后检查：健康版本、登录、历史任务、模型配置、技能、创建任务、复核、指标。
- 出现迁移失败、版本不符、关键页面不可用或诊断回归失败时停止推广，按快照回滚。
- 保留升级后日志、支持包和 `backup.json`，用于定位；不直接回传数据库或 `master.key`。

## 11. 风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| 网页升级需要 root | 任意命令执行风险 | 固定助手、固定路径、参数白名单、签名、审计、故障注入 |
| 服务重启导致页面误判失败 | 用户重复升级 | 状态持久化、自动重连、唯一升级锁 |
| 大日志备份耗时和占空间 | 停服时间过长 | 空间预检、显示备份阶段、维护窗口、快照保留策略 |
| 角色扩展造成越权 | 专家看到敏感任务 | reviewer 只读分配任务，服务端对象级授权测试 |
| 草稿/上传恢复复杂 | 数据重复或丢失 | 服务端草稿、文件指纹、幂等提交 |
| 现场无 LDAP/OIDC | SSO 阻塞 | SSO 作为可选适配，不阻塞本地邀请开户 |
| 真实标签迟迟不足 | 无法证明现网成熟 | 开发先行，现场并行标注；质量门禁持续显示未通过 |

## 12. 完成定义（DoD）

一个功能只有同时满足以下条件才算完成：

- 代码、数据库迁移、前端交互和错误路径完整；
- 权限、审计、异常和边界条件有自动化测试；
- 从上一发布版升级验证通过，必要时回滚验证通过；
- 用户文档和管理员文档更新；
- 提供离线包、SHA256、版本说明；
- 对真实数据能力的描述明确样本来源与限制。
