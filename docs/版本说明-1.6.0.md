# 版本说明 · 1.6.0（R4 网页离线自动升级）

基线：1.5.0（R3 诊断工作台体验）  
数据库：schema 6（R4 无 schema 变更，升级不触发迁移）

## 本次交付

### 1. 网页升级入口
- 系统信息页新增“离线升级”卡片：当前版本、上传、预检结果、目标版本、SHA256、大小、版本说明、磁盘/运行任务、实时阶段、助手日志、升级历史。
- 上传后自动预检；管理员可重新预检、执行升级、从成功/失败记录回滚。
- 升级/回滚需重新输入管理员密码；升级过程中禁止重复提交。

### 2. 后端预检与状态机
新增 API：

- `POST /api/system/updates/upload`
- `GET /api/system/updates`
- `GET /api/system/updates/{id}`
- `POST /api/system/updates/{id}/verify`
- `POST /api/system/updates/{id}/apply`
- `POST /api/system/updates/rollback`

预检：仅 `.tar.gz`、大小上限 `max_update_mb`（默认 512 MB）、单顶层目录、必需文件齐全、拒绝绝对路径/`..`/链接/特殊文件、SHA256、版本必须更高（同版需显式确认）。状态持久化在 `STATE_DIR/updates/<job>/status.json`，浏览器断开/服务重启后可恢复。

执行前检查：管理员+CSRF+二次密码、无排队/运行任务、磁盘至少 `max(512 MB, 包大小×4)`、无其他执行中的任务（409）；默认只允许升级，降级走回滚入口。

### 3. root/systemd 一次性助手
- `deploy/bbu-upgrade-helper@.service`：root 一次性模板服务；`deploy/bbu-upgrade-helper.sh` + `deploy/bbu_upgrade_helper.py` 读取固定请求。
- `deploy/bbu-upgrade-helper-trigger`：只接受任务 ID，`sudoers` 仅允许 Web 用户执行该触发器；主 Web 不提权。
- 助手只接受 `STATE_DIR/updates/<job>/request.json`，再次校验 SHA 并自行安全解压，只调用固定的 `upgrade_offline.sh` / `rollback_offline.sh`；单实例锁；阶段/日志/失败原因写入 `status.json`。
- `deploy/install_upgrade_helper.sh` 一键安装 unit、trigger、sudoers、`/etc/bbu-upgrade.json`。

### 4. 回滚与历史
- 成功/失败任务均保留升级快照路径；回滚时 `--with-state` 恢复升级前数据，当前数据移入 `rollback-safety`。
- 历史保留最近记录；状态不因 SSE/HTTP 断开误判失败。

## 已知边界与上线要求
- 正式环境必须先在测试机安装 root 助手，完成一次“用网页升级下一小版本”的 dogfood；当前开发容器无法安装 systemd 单元。
- SHA256 只证明完整性；如单位有签名基础设施，建议在包分发环节增加签名验证。
- 助手健康检查依赖 `/api/health` 返回目标版本；服务未启动或版本不符会标记失败，不影响回滚入口。
