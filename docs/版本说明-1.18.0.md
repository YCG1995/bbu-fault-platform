# BBU FaultScope 1.18.0 版本说明（R3–R6）

发布日期：2026-11-25

本版本在已发布的 1.14.0 基线上完成 R3～R6。1.14.0 的安装包、SHA 文件和版本说明保持原样，不做覆盖；1.18.0 使用独立版本号、独立离线包和独立备份快照。

## 一、R3：工具授权、沙箱、模型网关与导入供应链

### 工具合同与审批

- 新增 `GET /api/skills/{name}/tool`，返回 ToolManifest：技能状态、角色要求、输入 JSON Schema、路径根、最大文件数、网络声明、风险等级、审批要求和作用域。
- `tool_policy_mode=shadow` 时计算 `would_deny` 但继续执行；`enforce` 时拒绝启动子进程。高风险/破坏性工具未显式配置审批时强制要求审批。
- 审批记录绑定 `task_id / tool_name / tool_version / arguments_hash / session_revision / status / expires_at`，参数或会话 revision 变化后旧审批失效。
- 新增 `GET /api/tool-calls`、`GET /api/tool-approvals`、`POST /api/tasks/{id}/tool-approvals`、`POST /api/tool-approvals/{id}/decide`，调用和审批全量落库。

### 沙箱边界

- 实现环境变量白名单、RLIMIT（CPU/内存/输出/子进程）和 Python audit hook；每次任务使用输出目录下 `.sandbox-tmp`，TMPDIR/TEMP/TMP 指向该目录。
- 读取根包含 Python 标准库、zoneinfo、`/etc/localtime`、`/dev/null`、`/dev/urandom`、`/proc/self` 和本次任务精确声明的输入；路径判断使用目录边界，不用字符串包含。
- `RLIMIT_NPROC` 按当前 uid 线程数动态加余量，避免云主机同 uid 线程较多时 Errno 11。
- **明确边界**：当前宿主机 `unshare -n` 返回 Operation not permitted，因此没有 network namespace；本实现是 Python audit hook + rlimit + 环境白名单，不是容器、seccomp 或内核级隔离。高安全现场仍建议独立系统账号或容器运行。

### 模型能力探测

- OpenAI 兼容 endpoint 用 16 token 探测 `response_format={"type":"json_object"}`，不发送业务数据；Anthropic 默认支持 JSON；未知 provider 保守降级。
- 能力缓存表 `model_capabilities`，endpoint key 由 provider/base_url/model 的 SHA-256 前 24 位生成；extra 显式声明的能力优先于缓存。缓存默认 24 小时。
- `model_schema_mode=off` 或能力 `json_mode=false` 时不传 `response_format`，改用提示词约束；本地严格 JSON Schema 校验始终执行。
- 新增 `POST /api/models/{id}/capabilities` 手动刷新能力。

### 导入供应链

- 外部 zip 先 quarantine 到临时目录，流式解压并按实际字节计数；拒绝路径穿越、绝对路径、重复路径、符号链接/设备文件/管道、加密 zip、文件数/总大小/单文件/压缩比超限。
- 必须且只能有一个 `SKILL.md`；计算逐文件哈希和 `content_sha256`，HMAC-SHA256 签名写入 `.bbu-manifest.json` 和 `.bbu-signature.json`。
- `verify_skill` 可识别 missing / unsigned / invalid / tampered / bad_signature / verified；shadow 下问题技能标记 degraded，enforce 下标记 incompatible。
- 导入失败返回 422；导入成功采用原子替换，失败回滚。新增 `GET /api/skills/{name}/manifest`、`POST /api/skills/{name}/manifest/sign` 供管理员审计和补签遗留技能。

## 二、R4：有界 Agent、混合检索、反证校准与可信报告

### 有界 Agent

- 固定动作空间：`select_registered_skill / execute_skill / request_more_data / replan_once / stop`。
- 校验计划波次、技能总数、重规划次数、技能是否注册、gate 是否合法；拦截 shell、subprocess、curl、wget、任意 URL、自动发布等开放动作。
- 轨迹写入 `agent_traces`；模式 `off/shadow/canary/bounded`，默认 shadow。bounded 下违规计划转 `needs_data`；canary 只对指定任务生效。新增 `GET /api/tasks/{id}/agent-trace`。

### 混合检索与反例

- 经验检索由纯词法升级为词法 + 字符三元组哈希向量（64 维）混合打分，权重 0.55 lexical + 0.35 vector + 技能/根因加分。
- 支持按 device_type、software_version、fault_domain 过滤，排除当前任务，返回相似反例；`invalidated=1` 的经验不参与检索。
- 新增经验失效接口字段和 `source_revision`，专家驳回时旧经验失效而不是继续被规划消费。

### 反证与校准

- 根因决策卡按条件生成必要证据、反证、近邻鉴别、适用设备和版本范围，状态为 `supported / contradicted / missing_data / unknown`。
- 缺扫描不等于反证：没有对应日志源统一为 `missing_data`；只有已扫描到该日志源且规则阴性/none_of 命中才记为 `contradicted`。
- `CalibrationStore` 只读取 `evaluations.split='dev'` 的最新完成评测，按 low/medium/high 统计 exact 和 Wilson 95% 区间；样本不足返回 `uncalibrated`。禁止用 hidden 拟合，不显示伪精确概率。
- 新增 `GET /api/calibration`、`POST /api/calibration/fit`。

### 可信报告

- 报告生成结构化 claim：root_cause / verdict / evidence / time / number / action。
- 根因和动作必须有属于本任务的证据引用；数字和时间必须有 claim 或证据支撑；模型叙述中的未支撑数字/时间/过度断言会被拦截，失败回退确定性模板。
- 报告附“结构化报告校验”附注；任务结果增加 `claims / claim_check / narrative_check / agent_trace`，不再只信模型叙述。

## 三、R5：工坊字段溯源、案例矩阵与签名持续学习

### 字段级溯源

- 关键字段记录 JSON Pointer、来源 revision、字符区间、quote hash、归一化方式、验证状态、是否硬字段、是否人工锁定。
- 支持 `GET /api/workshop/drafts/{id}/provenance` 查看覆盖率、未定位字段和锁定数量；`POST /api/workshop/drafts/{id}/provenance/lock` 锁定字段。
- 模型合并/修复时保留人工锁；锁定字段不会被静默覆盖。原文 revision 变化后锁请求返回 409，要求重新分析。
- 阈值从原始文本解析为指标、比较符、数值、单位、时间窗、版本范围、含义和来源行，不再只存一段自然语言。

### 案例矩阵

- 按技能/根因/技能版本聚合案例数、命中数、置信度分布、平均证据质量和高频证据规则。
- 快照签名同时绑定技能名、构建 SHA、结果集、兼容范围和内容 SHA-256；任一变化都会使旧签名失效。
- 新增 `GET /api/case-matrix`、`POST /api/case-matrix/rebuild`；`verify` 返回 verified / unsigned / bad_signature / content_tampered。

### 增量候选与改判级联

- 专家改判/驳回生成 `experience_candidates`，按输入哈希、技能和根因幂等；候选不直接改技能，需管理员审批。
- 新增 `GET /api/experience-candidates`、`POST /api/experience-candidates/{id}/decide`；审批记录写入审计。
- 专家复核仍同步更新 `plan_experiences` 的 trust_level、corrected_root 和 review_id，旧经验按 invalidated 过滤。

## 四、R6：只读恢复验证闭环

- 任务完成后可登记恢复验证；现场只回传恢复前后只读证据，平台不连接设备、不执行命令、不改配置。
- 确定性前后对照输出 `recovered / still_fault / new_fault / inconclusive`，并列出证据规则变化和恢复后独立文件数。
- 新增 `GET /api/tasks/{id}/recovery-runs`、`POST /api/tasks/{id}/recovery-runs`、`POST /api/recovery-runs/{id}/observe`、`POST /api/recovery-runs/{id}/review`。
- 学习门禁必须同时满足：对照状态 `recovered`、恢复后独立证据文件 ≥1、专家 `confirmed`；任一不满足 `learning_eligible=0`。已复核记录不可覆盖。
- 任务详情页新增“恢复验证”卡片：登记、回传、专家确认/驳回均可在网页完成。

## 五、数据库与兼容性

- schema 从 1.14.0 的 **12** 升到 **16**。
- 新增表：`calibration_snapshots`、`agent_traces`、`case_matrix_snapshots`、`workshop_patches`、`experience_candidates`、`recovery_runs`。
- `plan_experiences` 新增列：`invalidated`、`device_type`、`software_version`、`source_revision`。
- 迁移保持幂等，旧库升级会创建新表/列并写当前 schema 版本；恢复数据库时写 `SCHEMA_VERSION`，不再硬编码旧版本。
- 1.14.0 数据可直接升级；升级前自动做 state/code 备份，回滚使用升级快照。

## 六、接口与测试

- REST 接口从 114 条增至 **135 条**（R3 +8、R4 +3、R5 +6、R6 +4）。
- 单元测试 **140/140** 通过（新增 R3 安全回归 16 项、R4 4 项、R5/R6 5 项）。
- HTTP 全量冒烟 **135/135** 通过，覆盖新增路由的真实调用、权限、CSRF、幂等和负向路径。
- 验证命令：
  - `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_*.py'`
  - `PYTHONDONTWRITEBYTECODE=1 python3 tests/api_full_smoke.py`

## 七、已知边界与未决项

1. 沙箱不是容器/seccomp；宿主机 `unshare -n` 不可用，没有 network namespace。对强隔离有要求的现场应使用独立系统账号或容器。
2. 模型能力探测请求当前不计入任务 Budget，结果按 endpoint 缓存 24 小时。
3. `ToolPolicy` 默认 shadow；外部导入技能即使签名通过，是否可直接进入 stable 仍需按现场供应链策略配置。
4. `CalibrationStore` 当前只按置信度三档统计，不按设备/版本拆分；样本不足时只展示 `uncalibrated`。
5. R5 的字段锁只保护已记录的关键字段路径；新增字段需要重新分析或补充来源后才能锁定。

## 八、升级提示

- 不要覆盖或重命名 1.14.0 的安装包和 SHA 文件；1.18.0 使用 `bbu-fault-platform-1.18.0-offline.tar.gz`、`...-ubuntu1604-offline.tar.gz`、`...-windows.zip`。
- 升级前确认 `STATE_DIR` 空间足够保存快照；升级后访问 `/api/health` 应返回 `{"ok": true, "version": "1.18.0"}`。
- 首次升级后建议检查：schema 16、技能清单签名状态、运行参数中的 `tool_policy_mode/tool_sandbox_mode/agent_engine_mode`、以及任务详情页恢复验证卡片。
