# BBU FaultScope 1.20.0 版本说明（平台助手与 MCP Server）

发布日期：2026-11-26

本版本在 1.19.2 基础上新增“平台内悬浮小助手”和“本机 MCP Server”，把任务、通知、技能、文档、审计和部分运维能力封装成统一工具层。1.19.2 的安装包、SHA 文件和版本说明保持原样，不覆盖、不静默替换。

## 一、新增能力

### 1. 全局悬浮小助手

所有登录用户都能在页面右下角看到“助手”悬浮按钮。点开后可以：

- 问平台使用问题：新建诊断、日志包、技能、工坊、模型、账号、升级、备份等；
- 查自己的站内通知、任务事件和外部 IM 消息（当前外部 IM 为可插拔本地适配器）；
- 管理员额外可以查系统状态、磁盘、备份、升级状态、用户/模型/通知配置，并执行受控写操作。

助手不是“模型直接查库”：模型只负责选择工具和组织答案，真正的数据访问、权限判断和审计都在 `bbu/assistant_tools.py` 的统一工具层完成。没有可用模型时自动降级为本地文档/消息检索，平台仍可回答基础使用问题。

### 2. MCP Server（本机 HTTP + Bearer Token）

- 端点：`POST /mcp`，标准 JSON-RPC 2.0；`GET /mcp` 返回 405，不提供 SSE。
- 协议版本：`2025-06-18`、`2025-03-26`、`2024-11-05`。
- 鉴权：`Authorization: Bearer <token>` 或 `X-MCP-Token`；Token 存在 `settings.mcp_token_v1`，只保存 SHA-256 哈希，不保存明文。
- Token 格式：`bbu_mcp_<token_urlsafe(36)>`，生成时只展示一次；轮换或撤销后旧 Token 立即失效。
- Token 绑定创建它的管理员账号；账号停用后 Token 失效。模式分 `read` 和 `admin`，非 admin 账号即使写入 admin 模式，鉴权时也会降为 read。
- 默认只接受 loopback 请求；`mcp_allow_remote=false`。确需内网访问时由管理员显式开启。
- 支持 `initialize`、`ping`、`tools/list`、`tools/call`、`resources/list`、`resources/read`、`prompts/list`、`prompts/get`、`logging/setLevel`、批量请求和 JSON-RPC 通知（通知不返回 result）。

### 3. 统一工具层（20 个工具）

注册表集中在 `bbu/assistant_tools.py`，悬浮助手和 MCP 共用：

`search_docs`、`search_messages`、`get_task`、`list_tasks`、`search_skills`、`get_system_status`、`list_backups`、`delete_backup`、`storage_overview`、`release_task_storage`、`get_update_status`、`apply_update`、`rollback_update`、`list_users`、`update_user`、`list_models`、`update_model`、`get_notification_prefs`、`update_notification_prefs`、`mark_notifications_read`。

### 4. 权限分级

| 能力 | 普通登录用户 | 管理员 | MCP read | MCP admin |
| --- | --- | --- | --- | --- |
| 平台文档问答 | 可用 | 可用 | 可用 | 可用 |
| 自己的通知/任务事件/外部 IM | 可用 | 可用（可查全部） | 按绑定账号 | 按绑定账号 |
| 审计/操作记录 | 不可用 | 可用 | 按绑定账号 | 按绑定账号 |
| 系统状态/备份/存储/升级状态 | 不可用 | 可用 | 可用 | 可用 |
| 删除备份/释放任务空间/改通知偏好/标记已读 | 不可用 | 待确认后执行 | 不可用 | 需 `confirm=true` |
| 升级/回滚/用户/模型变更 | 不可用 | 待确认+管理员密码 | 不可用 | 不可用 |

说明：

- 悬浮助手的写操作不会直接执行，先生成 10 分钟有效的 pending action；管理员确认后一次性执行并写审计。高风险动作（升级、回滚、用户/模型变更）额外校验管理员密码。
- MCP 只读模式只暴露查询工具；admin 模式也只额外放行删除备份、释放任务空间、通知偏好、标记已读等低风险写工具。`apply_update`、`rollback_update`、`update_user`、`update_model` 标记为 MCP 不可调用。
- 待确认动作只存内存，服务重启后丢失；未确认不会产生任何修改。

## 二、接口与数据

### 1. 新增 REST 接口（8 条）

- `GET /api/assistant/status`
- `GET /api/assistant/suggestions`
- `POST /api/assistant/chat`（最近 10 条 user/assistant 消息，单条最多 2000 字）
- `POST /api/assistant/actions/{id}/confirm`
- `POST /api/assistant/actions/{id}/cancel`
- `GET /api/mcp/info`
- `POST /api/mcp/token`（body `mode: read|admin`，返回 Token 一次）
- `DELETE /api/mcp/token`

### 2. 新增 MCP 传输路由（2 条）

- `GET /mcp`：405，明确不支持 SSE
- `POST /mcp`：JSON-RPC 2.0

REST 路由从 **136** 增至 **146**（含两条 `/mcp`）。数据库 schema 仍为 **17**，本版本没有数据库迁移。

### 3. 新增后端模块

- `bbu/assistant_kb.py`：11 份平台 Markdown 的标题分块与轻量中文检索。
- `bbu/external_im.py`：外部 IM 适配器协议 + 本地 JSON 适配器（`data/external_messages.json`）。
- `bbu/assistant_tools.py`：20 个工具注册表、角色过滤、参数校验、审计、MCP 模式限制、待确认摘要。
- `bbu/assistant.py`：悬浮助手编排、模型规划、结果总结、本地降级、pending action。
- `bbu/mcp_server.py`：MCP JSON-RPC、Token 生成/轮换/撤销、loopback 限制、resources/prompts。
- `bbu/model_roles.py`：模型角色常量，新增 `assistant` 角色。

### 4. 新增配置

| 配置 | 默认 | 环境变量 | 说明 |
| --- | --- | --- | --- |
| `assistant_enabled` | `true` | `BBU_ASSISTANT_ENABLED` | 关闭后悬浮窗隐藏，助手 API 返回 404 |
| `assistant_rate_per_min` | `12` | `BBU_ASSISTANT_RATE_PER_MIN` | 每用户每分钟助手请求上限 |
| `mcp_allow_remote` | `false` | `BBU_MCP_ALLOW_REMOTE` | 默认仅本机；非必要不要开启 |

模型角色新增 `assistant`。现有模型没有该角色时回退到 `default`；如果也没有 `default`，助手走本地文档/消息检索，不影响使用。

## 四、安全边界

- MCP 默认只允许本机 loopback。若部署在反向代理后，代理可能改变对端 IP；没有明确需要时不要开启 `mcp_allow_remote`，也不要直接把 `/mcp` 暴露到公网。
- Token 只显示一次；页面和 API 的 info 接口不会回传明文。轮换/撤销会立即让旧 Token 失效。
- 助手/MCP 的所有工具调用写审计；工具层统一做角色、参数和 MCP 模式校验，模型不能绕过。
- 外部 IM 当前只是适配器接口，未接真实飞书/豆包。接入真实 provider 前需要确定凭据、出域授权和用户身份映射。
- 助手 pending action 只在内存保留 10 分钟；服务重启丢失，不会出现“重启后自动执行”。

- 1.19.2 → 1.20.0：从 1.20.0 包执行 `upgrade_offline.sh --no-service`，代码替换和幂等初始化成功，健康返回 `1.20.0`；管理员 `password_hash`、schema 17 和 settings 保留。
- Windows 包已做结构与版本审计（关键模块、版本号、JS/CSS 均在包内），未在 Linux 环境执行 Windows 启动测试。

## 六、升级与安装

- 1.19.2 → 1.20.0 无数据库 schema 变更，沿用 `deploy/upgrade_offline.sh`；升级前自动生成 state/code 备份。
- 升级后 `/api/health` 应返回 `{"ok": true, "version": "1.20.0"}`。
- 首次使用 MCP：管理员进入“系统信息 → MCP / 助手”，生成 read Token，把客户端配置里的 `<YOUR_TOKEN>` 替换为实际 Token；默认连接 `http://127.0.0.1:<port>/mcp`。
- 建议先使用 read 模式；确认客户端可信后，再按需生成 admin Token。

## 七、已知限制

- 上游 `deepseek-flash` 仍可能出现 HTTP 503；本版本没有多模型 failover。
- 悬浮助手的模型规划路径依赖 `assistant`/`default` 角色可用；没有模型时只做本地检索，回答会比模型模式短。
- MCP admin 模式仍不暴露升级/回滚、用户/模型变更；这是安全取舍，不是遗漏。
- 外部 IM 的 `data/external_messages.json` 是本地只读样例格式，尚未实现飞书/豆包 OAuth、消息回写和增量同步。
- 待确认动作只存内存，适合单实例；多实例部署需要改为共享存储后再启用写操作。
