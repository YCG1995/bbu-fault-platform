# BBU 故障诊断平台 1.30.4 版本说明

本版按使用位置做了一次导航与信息归属调整：系统资源从总览移到「系统信息 → 概览」，系统信息、故障知识库的位置同步调整。数据库 schema 保持 25，REST 路由保持 211 条。

## 1. 系统资源归入系统信息

- 总览不再显示系统资源卡；`GET /api/stats` 不再返回 `system`，避免普通总览请求触发资源采样。
- 「系统信息 → 概览」新增系统资源卡，展示：
  - CPU 使用率、核数、1 分钟负载和采样来源；
  - 当前应用内存 RSS、总内存、占比和线程数；
  - 系统内存已用/可用/总量与使用率；
  - 数据盘已用/可用/总量与使用率。
- `GET /api/system/info` 继续返回 `system` 字段；采样实现仍在 `bbu/system_metrics.py`，Linux `/proc`、Windows `ctypes`，1.2 秒进程内缓存。
- 系统信息页本身只在管理导航开放；总览里的「系统资源」入口和刷新按钮一并移除。

## 2. 导航顺序

左侧导航调整为：

1. 诊断顺序：总览 → 新建诊断 → 任务记录 → 用量统计 → 真实案例 → 技能库 → 技能工坊 → 故障知识库。
2. 管理顺序：模型接入 → 用户管理 → 审计日志 → 执行轨迹 → 系统信息。

即：

- **故障知识库移动到技能工坊后面**；
- **系统信息移动到执行轨迹后面**。

路由和权限不变：`#/kb`、`#/system` 深链仍按原权限打开。

## 3. 验证

- `pytest`：380 passed。
- `python3 tests/api_full_smoke.py`：REST 211/211；`GET /api/system/info` 校验资源字段，`GET /api/stats` 保持无 `system` 负载。
- `python3 tests/ui_kb_smoke.py`：总览不再出现系统资源卡；系统信息概览出现 CPU/应用内存/系统内存/数据盘；导航顺序校验通过；390px 移动端通过。
- 真实知识库 2,268 文档 / 2,762 案例回归保持通过。

## 4. 部署

1. 解压 `bbu-fault-platform-1.30.4-offline.tar.gz`。
2. 已部署实例执行 `sudo bash bbu-fault-platform/deploy/upgrade_offline.sh`；全新安装执行 `install_offline.sh --port 8080`。
3. schema 保持 25，无需额外迁移；升级后「系统信息」显示版本 1.30.4。
