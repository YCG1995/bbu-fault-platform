# BBU FaultScope 1.20.1 版本说明（真实模型助手评测修复）

本补丁在 1.20.0 的“平台助手 + MCP Server”基础上，用真实模型完成助手智能化评测，并修复评测中暴露的两个工具参数问题。**数据库 schema 仍为 17，REST 路由和接口契约不变，不迁移数据。**

## 一、真实模型评测

- 模型：`deepseek-flash`（OpenAI 兼容端点，管理员默认模型，`assistant` 角色回退 `default`）
- 数据集：临时复制的数据库 + 一名工程师账号、一个已完成任务、一条未读通知、一条外部 IM 样例；不触碰生产数据
- 用例：13 个，覆盖文档问答、任务状态、通知、审计、外部 IM、权限隔离、敏感信息拒答、写操作待确认和多轮上下文
- 结果：修复后连续 2 轮均为 **13/13**；两轮平均约 4.7 秒和 8.1 秒，单轮约 3.2 万 tokens，最大单例约 38.8 秒
- 评测脚本：`evaluations/real_assistant_eval.py`；原始结果在 `evaluations/runs/assistant-real-model-*.json`；完整报告见 `docs/助手真实模型评测-1.20.1.md`

## 二、评测发现并修复

1. **工具参数只给名字、没给约束**：真实模型会把 `search_messages.scopes` 写成非枚举值，或把 `limit` 写成大于 30，导致“查未读通知/审计”工具报错。现在规划提示中直接给出每个工具的完整参数 Schema（enum、required、minimum/maximum），并要求严格按 Schema 生成参数。
2. **中文“失败”检索不到英文审计动作**：审计动作名是 `auth.login_failed` 这类英文；用户说“重点看失败操作”时，原先按中文子串过滤会漏掉失败记录。现在 `search_messages` 在审计 scope 识别“失败/错误/failed/error”意图，按 `failed/error` 动作或 `detail ok=false` 过滤，不再做中文子串匹配。

## 五、升级方式

沿用 1.20.0 的升级命令，不需要手工迁移：

```bash
tar -xzf bbu-fault-platform-1.20.1-offline.tar.gz
sudo bash bbu-fault-platform/deploy/upgrade_offline.sh
```

已有用户、模型配置、任务、审计、技能、案例和 `data/master.key` 保留。MCP Token、助手配置、schema 17 均不变。

## 六、已知限制

- 真实模型延迟存在波动，实测单例 1.7–20.7 秒；这是上游模型服务波动，不是本地检索耗时。
- 外部 IM 仍只有本地 JSON 只读适配器，未接真实飞书/豆包。
- 评测集为 13 个场景的定点回归，不等同于开放式对话的通用智能评测；后续新增工具或改提示词时应重跑。
- Windows 包仍只做结构与版本审计，未在 Windows 真机启动。
