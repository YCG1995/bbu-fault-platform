# 现场问题回传包（精简版）

> 目标：现场出问题时，10 分钟内产出一个可回传、可复现、默认脱敏的压缩包；研发侧不需要远程登录，也能从同一份输入和计划重跑。

## 1. 什么时候用

出现下列任一情况时生成支持包：

1. 诊断结果为空、`unknown_fault`、`multiple_causes`，但现场确认有明确告警；
2. 任务卡在 `running`/`queued`，或服务重启后没有自动恢复；
3. 报告结论与现场判断不一致，或证据引用明显错误；
4. 技能执行失败、模型调用失败、队列满、上传/解压异常；
5. 需要把一个已复核案例回流成真实案例，但接口报错。

## 2. 生成命令

在平台根目录执行：

```bash
# 默认：任务级，含计划/仲裁/报告/证据片段，不含原始日志
python3 tools/support_bundle.py --task T2026xxxx --mode task --out support.zip

# 只收环境与健康：不确定是否含敏感内容时先用这个
python3 tools/support_bundle.py --mode metadata --out support-meta.zip

# 完整：含原始日志和完整任务目录；回传前必须确认现场允许
python3 tools/support_bundle.py --task T2026xxxx --mode full --out support-full.zip
```

输出会打印压缩包大小和 SHA256；把 zip 和 SHA256 一起回传即可。

## 3. 包内有什么

| 文件 | 内容 | 是否含原始日志 |
|---|---|---|
| `README.md` | 回传与复现说明 | 否 |
| `environment.json` | 版本、OS、脱敏配置、schema 版本 | 否 |
| `health.json` | 队列、任务、技能、模型健康、成熟度门禁 | 否 |
| `metrics.txt` | Prometheus 文本指标 | 否 |
| `recent_tasks.json` | 最近 20 个任务摘要 | 否 |
| `cases.json` | 真实案例登记与标签状态 | 否 |
| `task.json` | 故障描述、模式、输入文件名与 SHA256 | 否 |
| `task_detail.json` | 计划、路由、仲裁、技能结果、证据片段 | 否 |
| `task/` | 报告、计划、补规划、错误日志 | 否 |
| `reproduce_task.py` | 离线复现脚本 | 否 |
| `inputs/` | 原始输入 | **仅 full** |
| `task/full/` | 完整任务目录 | **仅 full** |

`task` 模式看不到原始日志，但能看到输入指纹和每条规则的证据片段；多数结论错误可以用它定位到“规则/字段/阈值”层面。

## 4. 隐私边界

- 默认模式自动脱敏：API Key、Bearer、Cookie、password/secret、`sk-*`、用户 home、平台根路径、数据目录。
- `environment.json` 的 hostname 固定为 `<REDACTED>`，不采集用户名、会话、数据库密码、模型密钥。
- 不包含 `bbu.db`、`data/uploads`（除非 `full`）、`data/skill_versions` 全量备份。
- `full` 模式会包含站点名、IP、单板序列号等原始内容；回传前由现场负责人确认。

## 5. 回传后研发侧怎么复现

```bash
unzip support.zip -d support
python3 support/reproduce_task.py \
  --task-file support/task.json \
  --input-dir support/inputs \
  --out-dir data/repro \
  --root /path/to/bbu-fault-platform
```

脚本会：

1. 建临时 SQLite 和临时任务目录，不写生产库；
2. 复制输入并按 SHA256 校验；
3. 关闭 planner/replan/report_llm/auto_distill，走确定性 `TaskPipeline`；
4. 输出 `reproduction.json` 和新的 `report.html`。

`task` 模式没有原始日志时，先把现场原始日志放进 `support/inputs/`，文件名与 `task.json.inputs[].name` 一致，再运行。

## 6. 现场侧最少要补的 6 个信息

支持包之外，回传时请用一段话补充：

1. 站点/设备型号/单板型号；
2. 故障发生时间与恢复时间（时区）；
3. 现场可见的告警码或现象；
4. 已做过的操作（重启、换板、换光纤、升级）；
5. 期望结论（哪个根因、哪个技能应该命中）；
6. 是否允许把该任务回流为真实案例（是/否）。

## 7. 已知限制

- 真实案例没有根因标签时只能作为 `unlabeled` 样本，不能计入准确率；合成案例的 75/75 不代表现网准确率。
- 支持包不包含模型服务端日志；模型调用失败只能看到平台侧的错误、耗时和熔断状态。
- 若现场禁止导出原始日志，`task` 模式只能做结构级复现，不能验证具体字段内容。
