# BBU 故障诊断平台 1.28.2 版本说明

发布日期：2026-11-27

## 变更

本版按“AI 交互流程”分析逐项落地六项硬化，不改变确定性诊断内核、模型无工具执行权与发布权的边界。

### 1. 重试语义与预算计数

- `AIGateway.complete()` 尊重 `AIError.retryable`：401/400、JSON Content-Type 错误、本地地址策略拒绝等确定性失败不再在同一模型上重试 2 次，直接换下一个模型。
- 失败 attempt 通过 `Budget.settle_failed()` 计入 `calls`；网络错误、401/400、修复请求异常都不能再绕过 `max_llm_calls`。
- 重试退避加入 `llm_retry_jitter_sec` 抖动（默认 0.5 秒），避免多个任务同时重击同一端点。
- 预算预留改为“输入估算 + 最大输出”，结算后记录 `over_budget`，后续调用在 `reserve/check` 处硬拦截。
- 输入 token 估算改为 CJK 感知（中文按 1 字≈1 token，其余按 4 字符≈1 token），不再使用偏低的 `len//3`。

### 2. Schema 失败熔断与降级

- JSON 初次校验失败仍只修复一次；修复后仍不合法，计入独立的 `schema_breaker`，默认连续 2 次失败、冷却 300 秒。
- 熔断期间 `choose()` 跳过该端点；端点能力缓存写入 `degraded=true`、`probe_error`、`schema_failed_at`，管理页能力查询可见。
- Schema 熔断与传输熔断分离，不把“模型偶尔返回坏 JSON”误记为网络故障。

### 3. 上下文窗口裁剪

- 根据模型能力缓存的 `context_window/max_output`，在请求前裁剪 prompt；保留头部数据和尾部 JSON Schema/格式约束，中间插入裁剪标记。
- 数据库 `max_tokens` 只作默认输出上限，不截断调用方显式请求；只有 `extra.capabilities.max_output` 显式声明时才作为硬上限（例如工坊的 12000 输出请求可保留）。
- 同时收紧本次请求的 `max_tokens`，确保 `输入估算 + 输出上限 + 余量 ≤ context_window`，避免长 prompt 直接 400。
- 裁剪字符数、有效 `max_tokens`、`context_window` 记录到 attempt 与轨迹，便于复盘。

### 4. 端点并发与负载分散

- 新增端点级 `EndpointGate`：默认单端点并发 4、排队上限 32、排队超时 30 秒；排队满/超时直接换下一个模型，不触发传输熔断。
- 并发槽按 `provider + base_url` 共享，同一 Base URL 下的不同模型别名不会各自开满 4 个并发；能力探测请求也走同一端点闸门，探测被本地排队拒绝时不标记端点 degraded。
- 同优先级全局模型组内轮询（`priority` 仍是主排序），避免多个任务永远打 `id` 最小的模型。
- 个人模型仍保持原有“个人优先”语义；本版只调整全局同优先级组的分散。
- 并发、队列、超时、抖动均可在运行配置中调整。

### 5. 私网 allowlist 与目标审计

- 新增可选 `model_private_allowlist`（逗号分隔，支持 CIDR、精确主机、`*.suffix` 后缀），环境变量 `BBU_MODEL_PRIVATE_ALLOWLIST`。
- 默认空值维持 1.28.1 行为：允许所有私网/回环；非空时只放行匹配的私网目标，公网目标不受影响。
- 云元数据地址（`169.254.169.254` 等）与 IPv6 link-local（`fe80::/10`）无论 allowlist 如何配置仍永久拒绝。
- 模型发现、连通性测试、草稿测试、推理 attempt 均审计目标 host/path；发现审计额外记录 `allow_private` 与 allowlist 条数（不记录白名单内容）。

### 6. 补规划重新过有界 Agent 门禁

- `pipeline._maybe_replan()` 在补规划新增步骤执行前再次调用 `BoundedAgent.review_plan()`，`bounded` 模式下违规计划直接返回 `status=rejected`，保留已有结果继续仲裁。
- 修复 `replan=True` 布尔值被当作列表取 `len()` 的隐患，统一按重规划次数判断。
- 补规划门禁轨迹写入 `replan-agent-trace.json`，并在 `routing.json` 记录 mode/violations/action_count。

## 新增/调整配置

| 配置 | 默认 | 说明 |
|---|---|---|
| `llm_retry_jitter_sec` | 0.5 | 重试退避随机抖动上限（秒） |
| `llm_schema_fail_threshold` | 2 | Schema 失败熔断阈值 |
| `llm_schema_cooldown_sec` | 300 | Schema 熔断冷却（秒） |
| `llm_endpoint_concurrency` | 4 | 单端点并发上限 |
| `llm_endpoint_queue_limit` | 32 | 单端点排队上限 |
| `llm_endpoint_queue_timeout_sec` | 30 | 端点排队超时（秒） |
| `llm_context_margin_tokens` | 256 | 上下文裁剪余量（token） |
| `model_private_allowlist` | 空 | 私网 CIDR/主机白名单 |

## 兼容性

- 数据库 schema 仍为 22，无迁移。
- 默认 allowlist 为空，私网访问行为与 1.28.1 一致。
- 行为变化：确定性错误不再重试；失败 attempt 计入调用上限；超长 prompt 会被裁剪；同优先级全局模型会轮询。
- 既有 API 路径、权限、REST 162 项与 UI 入口不变。
