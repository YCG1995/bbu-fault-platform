# BBU 故障诊断平台 1.8.0 版本说明（个人 MaaS Key）

版本：`1.8.0`  
发布时间：2026-11-25  
基线：`1.7.0`（schema 7）→ `1.8.0`（schema 8）

## 一、版本目标

上一版本所有 AI 调用都共用管理员配置的模型。现场成员共用同一个企业内网 MaaS Key 时，容易出现额度争抢、429 限流和“一个人的 Key 失效影响所有人”的问题。本版本增加成员级个人 Key：每个成员可以在个人中心配置自己的企业内网 MaaS Key，诊断和工坊优先使用个人 Key；未配置时继续使用管理员默认模型。

核心原则：

1. **个人 Key 只属于本人**：按 `user_id` 隔离，不能跨用户读取或使用。
2. **未配置不阻塞**：没有个人 Key 时自动使用管理员默认模型，不影响现有部署。
3. **异常有出口**：管理员默认模型不可用时，任务详情、工作台和个人中心给出友好提示，并直达个人 Key 页面。
4. **Key 不落明文**：数据库加密存储，接口只返回掩码，审计不记录明文。

## 二、功能变化

### 2.1 个人中心新增“企业内网模型（个人 Key）”

- 展示当前状态：未配置（使用管理员默认模型）/ 已配置且可用 / 已配置但不可用（回退默认模型）。
- 可选择管理员预置的 MaaS 模型：`gpt-4o-mini`、`enterprise-lite-v7.0`、`enterprise-lite-cot-v7.0`。
- 填写或更新个人 API Key；已配置时留空表示只修改模型、不更换 Key。
- 支持“测试连接”和“清除个人 Key”。
- Key 获取地址：`https://maas.example.com/personal-api-key`。

### 2.2 模型选择顺序

单次 AI 调用按以下顺序选择：

1. 任务提交者本人的个人 MaaS 配置（启用且 Key 可解密、熔断未打开）。
2. 管理员 `model_configs` 中按角色、优先级匹配的默认模型。
3. 个人配置连续失败时，自动回退管理员默认模型。
4. 全部不可用时抛出带个人 Key 提示的错误，任务详情保留失败原因。

任务流水线在 `TaskPipeline.run()` 入口绑定任务提交者的 `user_id`，规划、补规划、仲裁、报告都沿用同一归属；技能工坊的“分析 / 追问 / 构建”也按当前登录成员绑定个人 Key。

### 2.3 异常提示

以下场景会在工作台、任务详情和个人中心展示提示：

| 场景 | 提示 |
| --- | --- |
| 未配置个人 Key，且管理员未配置默认模型 | 尚未配置可用模型，请配置个人 MaaS API Key |
| 未配置个人 Key，默认模型熔断/连续失败 | 管理员默认模型暂时不可用，建议配置个人 MaaS API Key |
| 已配置个人 Key，但 Key 解密失败或个人模型不可用 | 个人 MaaS Key 暂不可用，请更新个人 API Key |
| 个人 Key 不可用但默认模型可用 | 自动回退默认模型，不阻断任务 |

提示中的“配置个人 Key”按钮直接打开配置弹窗；弹窗内提供 MaaS 个人 Key 页面外链。

## 三、数据库与接口

### 3.1 schema 8

新增 `user_model_configs`：

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `user_id` | 用户 ID，唯一，外键 `users(id)` |
| `name` | 展示名，默认“个人 MaaS” |
| `provider` | 固定 `openai`（企业 MaaS 为 OpenAI 兼容协议） |
| `base_url` | 固定企业内网地址，默认 `https://maas.example.com/v1` |
| `api_key` | `SecretBox` 加密后的 Key |
| `model` | 模型名 |
| `max_tokens` / `temperature` / `timeout_sec` | 调用参数 |
| `enabled` | 是否启用 |
| `extra` | 预留扩展 JSON |
| `created_at` / `updated_at` | 时间戳 |

升级时 `CREATE TABLE IF NOT EXISTS` 自动建表，不修改 `model_configs`，不回填个人 Key。

### 3.2 新增接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/profile/model-key` | 登录用户 | 当前个人配置、掩码、模型列表、默认模型状态、异常提示 |
| PUT | `/api/profile/model-key` | 登录用户 + CSRF | 保存/更新个人 Key 和模型 |
| DELETE | `/api/profile/model-key` | 登录用户 + CSRF | 清除个人 Key，回退默认模型 |
| POST | `/api/profile/model-key/test` | 登录用户 + CSRF | 使用已保存的个人配置测试连通性 |

`GET /api/profile/model-key` 不返回 Key 明文；`PUT` 的审计只记录模型与接入地址。

### 3.3 既有接口扩展

- `GET /api/tasks/{id}` 新增 `model_status`，包含任务提交者的个人/默认模型状态与 `notice`。
- `GET /api/stats` 新增 `model_status`，工作台据此展示提示。
- `POST /api/tasks/{id}/retry` 继续使用任务原提交者，重跑仍优先使用其个人 Key。

## 四、安全与边界

1. **加密存储**：复用 `SecretBox`（SHA256-CTR + HMAC），主密钥 `data/master.key` 权限 `0600`；`master.key` 更换后旧 Key 解密失败，界面提示重新配置。
2. **用户隔离**：查询条件固定 `user_id`；不存在“读取他人 Key”的管理员接口。
3. **不记录明文**：API 响应只返回 `api_key_masked`（前 4 + `****` + 后 4）；审计详情不含 Key。
4. **CSRF**：写操作全部校验 CSRF；未登录返回 401。
5. **失败回退**：个人 Key 失效不会让全员不可用；默认模型失效也不会伪造诊断结论，任务按既有逻辑失败或走确定性路径。
6. **固定接入地址**：个人配置不允许成员改 `base_url`，避免把 Key 发往非企业地址；新增模型需管理员在服务端配置预置列表。

## 六、升级说明

更新包：`dist/bbu-fault-platform-1.8.0-offline.tar.gz`  
初始一键部署包：`dist/bbu-fault-platform-1.8.0-ubuntu1604-offline.tar.gz`（约 76MB，内置 CPython 3.13.18）  
SHA256：见同目录 `.sha256` 文件。

升级路径：`1.7.0`（schema 7）→ `1.8.0`（schema 8）。

演练目录 `/tmp/bbu-r6-upgrade2`：1.7.0 安装后保留 2 个用户、1 个模型；升级后 schema 8、`user_model_configs` 存在；回滚 `--with-state` 后 schema 7、个人表消失，`rollback-safety` 保留 1.8.0 数据；再次升级回到 schema 8，用户与模型均保留。个人 Key 因随数据回滚，1.7.0 期间不可见，重升级后需重新配置。

升级后管理员不需要做任何配置：已有 `model_configs` 继续作为默认模型；成员个人 Key 为空时行为与 1.7.0 一致。需要成员自助配置时，把个人 Key 页面地址发给成员即可。

回滚到 1.7.0 时，`user_model_configs` 表随数据库快照回滚；1.8.0 期间写入的个人 Key 不会保留。升级前建议使用 `deploy/upgrade_offline.sh` 的默认备份，或额外执行 `sqlite3 data/bbu.db ".backup ..."`。

## 七、一键部署包

首次部署使用 `bbu-fault-platform-1.8.0-ubuntu1604-offline.tar.gz`：

```bash
tar -xzf bbu-fault-platform-1.8.0-ubuntu1604-offline.tar.gz
cd bbu-fault-platform-1.8.0-ubuntu1604-offline
sudo bash install.sh
```

包内包含程序、CPython 3.13.18 运行时、`install.sh` 与现场说明；程序/运行时只读，数据目录独立。安装器会同时配置使用内置 Python 的 root 升级助手，后续普通更新包可在「系统信息 → 离线升级」上传。详细参数与验证记录见 [`一键部署说明.md`](一键部署说明.md)。

## 八、已知限制

1. 企业内网 MaaS 域名 `maas.example.com` 仅在办公网/VPN 可达；非办公网环境无法完成真实联调。本版本用本地假 OpenAI 端点验证协议、加密、隔离与 UI，真实 MaaS 连通性需在办公网验证。
2. MaaS 限流较严格（连续请求易 429）。平台已有重试与熔断，但多人同时使用同一默认 Key 时仍可能触发限流；个人 Key 正是为缓解该问题。
3. 个人 Key 目前固定为企业 MaaS 的 OpenAI 兼容协议，不支持成员自行填写 Anthropic 或其他厂商地址。
4. R5 真实数据门禁仍未达标：3 个真实案例保持 `unlabeled`，`ready_for_real_data=false`；本版本不影响该结论。
