# 使用手册

## 1. 登录与权限

- 首次部署后，管理员账号 `admin` 的初始密码在 `data/初始管理员密码.txt`（生产为 `/var/lib/bbu-fault-platform/data/初始管理员密码.txt`）。
- 首次登录不强制修改密码，可直接进入工作台；建议尽快在“个人设置”改密，普通改密至少 10 位。
- 角色：
  - **管理员**：任务、技能、工坊、模型、用户、审计、系统信息全部可用；可发布技能。
  - **工程师**：新建任务、查看自己的任务与报告、编辑/构建自己的技能草稿；不能改模型/用户/系统配置，不能发布技能。

登录态默认 12 小时；服务端 `SameSite=Strict` Cookie，换浏览器或清 Cookie 需重新登录。

## 2. 发起一次诊断

1. 打开「新建诊断」。
2. 只填**故障描述**，页面不再要求人工填写标题。提交时先用描述首行生成确定性占位标题；规划阶段由 AI 结合日志盘点自动生成 40 字内中文标题，失败时保留占位标题。描述越具体，规划和技能选择越准，建议包含：
   - 设备形态（BBU / ITBBU / SDR）、站点/网元名；
   - 告警码与首现时间、持续时长；
   - 已做过的检查/操作（重启、换纤、换板等）；
   - 关键现象（PLL 失锁、收光低、链路闪断等）。
3. 拖拽或选择日志包（zip / tar.gz，可多选）。平台会在任务目录内安全解压，不执行日志中的任何内容。
4. 选择模式：
   - **快速定位**：最多 2 个候选技能，适合现场抢修；
   - **深度分析**：最多 4 个候选技能，扩大检索与交叉验证，适合复盘。
5. 点「开始诊断」。提交后进入队列，页面自动跳到任务详情。

任务详情固定为四个一级分区：

- **诊断概览**：结论、置信度、证据覆盖与下一步动作；
- **证据与技能**：参与技能、匹配分、命中规则和可回查的文件/行号；
- **诊断报告**：HTML 报告与 Markdown 原文，iframe 按需加载；
- **运行详情**：阶段时间线、SSE 实时事件、补规划与重试记录。

运行中首次进入默认停留在「诊断概览」；已完成且有报告的任务默认进入「诊断报告」。SSE 刷新会保持当前分区、滚动位置和报告视图，不把用户跳回默认页。

任务可以「重跑」（以相同输入新建一次任务）和「取消」（运行中）。取消只终止后续阶段，已产出的技能结果保留。原始输入释放后不能再重跑，但报告和证据仍可查看。

## 3. AI 计划与一次补规划

平台不再使用固定「路由一次」的流水线。每次任务：

1. **AI 规划**：planner 读取故障描述、日志盘点结构、技能目录和相似历史经验，生成 1–4 个波次。首波只放最能区分假设的最少技能，波次内并行。
2. **按门槛执行**：后续波次只有在 `前序未命中` / `结论冲突` / `置信度不足` / `证据缺口` 时才执行；实际执行时还会校验门槛。
3. **最多补规划一次**：首轮执行后，若所有技能都无结果、没有任何命中，或唯一命中但置信度不是 high，平台会让 planner 在**未执行技能**中补选最多 4 个；补规划返回空步骤就停止。多个不同根因并存时不补规划，直接交给仲裁，避免循环扩搜。
4. **收敛**：唯一高置信根因出现即停止扩展；随后仲裁、生成报告。

计划里的目录外技能、重复技能、已执行技能、超并行/超总技能/超步数都会被确定性裁剪；裁剪后没有可执行技能时回退确定性波次。任务详情能看到计划来源、每一波的门槛与状态，以及补规划结果。

### 3.1 专家推理数据

平台技能目录除名称/关键词外，还携带 `diagnostic_reasoning`：竞争假设、证据检查顺序、关键鉴别点、阈值口径、误判陷阱和停止条件。planner 用它形成假设，报告用它解释“为什么采信这个根因、为什么排除其他根因”。这些推理绑定真实规则编号，报告只写本次实际命中/未命中；证据不足时明确写“未评估”，不伪造排除理由。随包附 75 条合成案例和 3 份专家剧本，详见 `docs/诊断推理数据说明.md`。

## 4. 日志包建议

优先上传故障时间窗前后 30 分钟的日志，至少包含：

- 时钟/告警/运行日志（`clockstatuslog`、`alarmlog` 等）；
- 单板与链路状态、光模块读数、收发光功率；
- 近期复位、升级、配置变更记录；
- CloudMAT 工装日志可直接打包上传。

平台不会把原始日志发给模型，只发送抽取后的证据片段与技能目录。大包建议先按时间窗裁剪，避免超过 2048 MB。

## 5. 技能库

「技能库」展示运行中的子 Skill：

- **可用 / 降级 / 不可用**：是否具备执行组件；
- **已验证 / 未验证**：是否在构建时跑过案例回归；
- 规则数、根因数、版本、来源、描述与匹配关键词。

操作：

- **详情**：查看 profile、根因、步骤、组件、案例、版本历史；
- **停用/启用**：停用后不参与规划；
- **导出**：下载技能 zip，便于在其他实例导入；
- **导入技能**：管理员上传符合契约的技能 zip，平台会重新扫描并做健康检查；缺组件会显示不可用，不会强行运行。

## 6. 技能工坊（粘贴整段资料生成技能）

工坊改为引导式流程，页面不再要求逐步填十几个字段。顶部按「资料输入 → AI 解析与命名 → 规则审查 → 案例回归 → 构建发布」展示当前进度，长操作全部转入后台任务并显示真实阶段与百分比。

1. **粘贴资料生成**：把现有故障资料整段粘贴进文本框即可，不需要填写技能名。平台立即创建草稿并用确定性规则生成占位名称，随后启动后台「分析」任务。
2. **AI 解析与命名**：配置了 `workshop` 模型时，模型只输出结构化 FaultSpec，补充别名、症状、案例映射、待确认问题和 40 字内中文标题；不会直接写 YAML，也不会覆盖已明确的领域规则、日志源和阈值。技能名由故障语义自动生成，构建或首次写入案例后锁定，避免后续升级改名。
3. **规则审查与中途确认**：确定性编译器生成规则 ID、文件 glob、关键字/正则、根因表达式和案例断言。质量审查会列出错误与阻塞问题；可在「补充/纠正」文本框自由说明，点击「按补充重新生成」追加到原资料后后台重跑。
4. **案例回归**：案例列表显示自动递增的 `case-01` 等 ID、正例/反例、期望根因、命中规则和上传文件。正例必须选择根因，反例固定 `NONE`；重复案例需明确覆盖。至少 1 个正例 + 1 个反例，并覆盖每个根因条件，构建才会通过覆盖率门禁。
5. **构建发布**：构建在后台执行 `scaffold_child_skill.py --check`、规则回归和一键报告，页面显示真实阶段（解包/提取/审查/回归/校验/完成）。失败会落库显示错误和重试入口；成功后管理员才可发布，发布进入正式技能库并参与规划。

任务状态与进度通过 `GET /api/workshop/jobs/<job_id>` 和草稿任务列表轮询；创建、日志上传、分析、补充重建、构建、案例写入均支持 `?async=1`。模型不可用时页面会明确提示「未配置 workshop 真实模型，本次使用确定性解析」并保留确定性结果，不伪装成 AI 生成。高级 Profile YAML 默认折叠，只有排障时才展开手工编辑。

> 三类示例资料已做确定性编译和合成案例回归：USBFLASH 3 条规则/3 个根因、看门狗 4 条规则/3 个根因、SSD 5 条规则/4 个根因。合成案例只证明规则结构闭环，不等于真实日志证据已验证；真实附件仍应写入案例并重跑。

### 自学习草稿

任务成功（匹配根因、置信度 high/medium）后，后台会自动创建一个「自学习：<根因>」草稿：

- 草稿列表/详情带「自学习草稿」标识，并显示来源任务与采信技能；
- 日志已自动分析出规则候选，仍需人工核对规则、根因、适用范围；
- 同一任务只沉淀一次；同一根因已有自学习草稿时不再重复创建；
- **不会自动发布**。必须走「校验并构建」→ 案例回归 → 管理员发布，和普通技能一样受 `verified` 硬规则约束。

### 规则 `verified` 的硬规则

元 Skill 要求「根因只能引用 `verified: true` 的规则」。若构建报“引用了 verified: false 的规则”，优先补真实案例并回归，让规则由证据支撑；不要为了过校验而盲目标记。错误规则会导致误诊。

### 案例目录约定

```text
cases/<skill-name>/<case-id>/
  case.yaml          # 期望根因、命中/未命中规则
  input/             # 日志包或解压后的输入
  expected/          # 期望证据/输出（按元 Skill 约定）
```

工坊详情页可直接“写入案例”上传日志包并填写期望根因，构建时自动使用 `--cases-dir`。发布门禁会检查该目录中是否同时存在正例和反例。

## 7. 模型接入

- 新建模型默认填入公司 MaaS：Base URL `https://nebulacoder-maas.zte.com.cn/v1`、默认模型 `deepseek-v4-flash`、名称「公司 MaaS」；模型名输入框带公司模型下拉建议。
- OpenAI 兼容与 Anthropic 原生两种协议；Mock 仅用于联调。
- 同一配置可勾选多个角色，`priority` 数字越小越先尝试；失败自动切下一个配置。
- `default` 是兜底；`planner` 生成动态波次计划（每任务 1 次）；`router` 是老部署的规划回退；`arbiter` 只在结论冲突时调用一次；`writer` 负责报告研判；`workshop` 只做技能起草。
- 未配置真实模型、计划非法或调用失败时，平台自动回退确定性波次，仍会完成诊断；任务详情、技能工坊会直接显示未配置/失败提示，不让用户误以为 AI 已生效。
- API Key 保存后只显示掩码；编辑时留空表示保持原 Key。
- 编辑器提供「测试当前填写值」：直接调用 `POST /api/models/test`，**不保存配置、不写模型记录**。未填 Key 时仅 Mock 可测试；公司 MaaS 需先输入 Key。
- 「测试连通」会发一条最小请求，不消耗任务预算，但会消耗一次真实模型调用。

## 8. 用户与审计

- 「用户管理」新增用户只填四项：**用户名（同时作为默认显示名）、角色、领域、初始密码**。用户与邀请不再有「班组 / 站点」字段，界面、API 和个人中心只保留「领域」；旧邀请 API 仅用于兼容激活码。
- 管理员可在「系统信息 → 运行参数 → 账号与注册」开启「允许免邀请码自助注册」。开启后登录页出现「自助注册」按钮，注册账号固定为普通工程师，可填写显示名和领域；注册成功不自动登录，需返回登录页使用新账号登录。该开关默认关闭，保存后立即生效，无需重启。
- 管理员创建账号的初始密码可设为 9 位（默认 `bbu-skill`），但首次登录仍强制改密；普通用户自主改密至少 10 位。
- 用户列表、详情、搜索和审计均支持「领域」筛选；角色仍为管理员/工程师。
- 「审计日志」记录登录、改密、任务创建、技能导入/发布、工坊操作、模型与用户变更；可按页查看详情。
- 所有写操作都校验 CSRF 并写审计；审计记录不包含 API Key 明文。

## 9. 系统信息

系统信息分为「概览 / 运行参数 / 任务空间 / 备份 / 迁移 / 升级」六个标签页，首屏只加载概览。概览展示版本、Python、服务运行时长、运行/并发上限和数据/技能/案例/元 Skill 路径；其他标签首次点击时才请求对应接口。

### 9.1 运行参数（管理员）

「系统信息 → 运行参数」可在线编辑全部运行参数，分组包括：

- 任务并发、队列上限、单任务技能扇出；
- 工坊后台并发/队列、任务空间释放并发/队列；
- 单任务 LLM 调用上限、Token 上限、任务/技能超时、补规划次数、模型重试与健康窗口；
- 快速/深度模式技能数、最低路由分、最大波次、规划技能总数与补规划上限；
- 单次上传、解压总大小、解压文件数、更新包、迁移包上限；
- 账号与注册：是否允许免邀请码自助注册；
- 工具授权：`tool_policy_mode=shadow/enforce`、审批有效期；
- 沙箱：`tool_sandbox_mode=off/audit/enforce`、CPU、内存、输出、子进程上限；
- 技能清单：`skill_manifest_mode=off/shadow/enforce`；
- 模型 Schema：`model_schema_mode=auto/off`、能力缓存小时数；
- 有界 Agent：`agent_engine_mode=off/shadow/canary/bounded`、波次/技能/重规划上限；
- 置信度校准：`calibration_min_samples` 最小 dev 样本数；
- 导入供应链：文件数、总大小、压缩比上限。

「保存配置」写入 `config.json`（保存前生成 `config.json.bak`，临时文件写完后原子替换）。容量、并发、预算类参数需「保存并重启」或「仅重启服务」；账号与注册开关保存后立即生效。重启会停止旧 `AppServer`，由 `run.py` 重新加载 `Config` 并装配新的 `App`，监听同一端口。存在诊断、工坊、空间释放、迁移/导出、升级或评测任务时返回 409 并列出阻塞项，不能强行重启。环境变量覆盖的字段在页面禁用，保存会被拒绝。

### 9.1.1 1.19.0 缺陷修复边界

- **报告数字**：claim 中的数字/时间必须在被引用证据原文中定位；校验失败直接回退确定性模板，不再让模型自证。
- **工具授权**：默认 `shadow` 仍会记录普通 `would_deny`，但审批缺失/不匹配、角色/站点/设备越权、路径越界、Schema 非法、网络未受控会直接拒绝；高风险工具必须审批。
- **工坊锁字段**：`locked:true` 的字段值在模型合并/修复后保持原值，并在结果里记录 `locked_restored`。
- **字段来源**：三个 intake 样本覆盖率为 100%；页面分别显示原文直引和可追溯推导数量，不再只统计 `verified`。
- **恢复验证**：根因从有到无时必须满足同任务/同对象且恢复后新增独立文件 ≥1 才判 `recovered`；`observe()` 会自动写一条 `recovery.verification` EvidenceEvent。
- **技能验签**：只有案例回归通过且清单签名 verified 才显示 `verified`；tamper/bad_signature 为 `incompatible`，不能以 degraded 执行；ZIP 导入只做 quarantine，不冒充案例回归。
- **补证失效**：按 zip 成员与技能声明的 glob 选择性失效，响应返回 `invalidation_reasons`；声明 `**/*.log` 的宽范围技能仍会按合同失效。

### 9.1.2 1.18.0 安全与学习边界

- **工具授权**：默认 `shadow` 只记录 `would_deny`，不会阻断；要高安全现场把 `tool_policy_mode` 改为 `enforce`。高风险工具审批绑定参数哈希与会话 revision，改参数后必须重新审批。
- **沙箱**：`audit` 只审计不阻断，`enforce` 才阻断；当前实现为环境白名单 + rlimit + Python audit hook，不是容器/seccomp。强隔离现场请用独立系统账号或容器运行。
- **技能导入**：坏 zip、路径穿越、符号链接、加密包和超限包返回 422；签名校验在 `shadow` 标记 degraded，在 `enforce` 标记 incompatible。
- **有界 Agent**：默认 `shadow`，只写 `agent_traces`；`bounded` 下违规计划转 `needs_data`，不会执行 shell/任意 URL/自动发布。
- **校准**：只用 dev 集，hidden 拟合返回 400；样本不足显示 `uncalibrated`，不展示伪精确概率。
- **恢复验证**：只读回传，不改设备；只有 recovered + 独立证据文件 + 专家确认才允许进入学习。任务详情页的“恢复验证”卡片可完成登记、回传和复核。

### 9.2 任务空间统计与释放（管理员）

「任务空间统计与释放」按任务展示原始输入、中间产物、合计、共享引用和可立即释放字节，并显示磁盘剩余。释放流程：

1. 勾选一个或多个可释放任务，点「释放选中任务的原始输入」；
2. 二次确认后提交后台任务，页面轮询真实进度并汇报完成/失败/累计释放字节；
3. 只删除 `data/uploads` 下的原始上传，保留报告、证据、案例和数据库记录；
4. 重跑任务与原任务共享同一批输入，释放前扫描全部引用；只有最后一个引用者释放时才真正删除共享文件；
5. 任务状态变为「原始输入已释放」，不能再重跑，但历史报告和证据仍可查看；
6. 服务重启时未完成的 `releasing` 自动转为 `release_interrupted`，可重新发起。

### 9.3 工作目录与迁移（管理员）

「系统信息」下方新增「工作目录与迁移」卡片：

- **切换工作目录**：统一运行数据根目录，标准子目录为 `data/skills/cases/updates/backups`。填绝对路径先预检；目标必须为空或不存在，且位于部署允许的根目录内。Linux 由 root/systemd 助手自动停服、切换、改写 systemd 路径并重启；Windows 准备完成后提示手动重启，重启前写入 `pending_maintenance.json`。旧目录保留。
- **导出迁移包**：输入至少 12 位独立迁移口令两次，再输入管理员密码。包内包含用户与密码哈希、模型 Key 密文、`master.key`、技能、任务/案例元数据与报告；不包含原始上传、案例输入、解压目录、缓存和登录会话。
- **覆盖恢复**：选择 `.bbumig`、输入迁移口令两次并要求管理员密码。导入是覆盖式替换 `data/skills/cases`，不做增量合并；当前数据先备份到 `backups/import-<任务ID>`，健康检查失败自动恢复旧目录。请在新实例或已停机窗口执行。

迁移包使用 ChaCha20-Poly1305 认证加密，不依赖 `cryptography`，可在无该库的离线实例导入；错误口令或篡改会拒绝。包内仍有 `master.key`，必须和口令分渠道保管。

### 9.4 历史备份（管理员）

「系统信息 → 备份」扫描 `STATE_DIR/backups`（通常为 `/var/lib/bbu-fault-platform/backups`）的直接子项，显示：

- 备份名称与绝对路径；
- 类型（升级快照 / 迁移恢复前备份 / 手工或其它备份）与版本变化；
- 创建时间、占用空间、文件数；
- 是否正被升级任务使用，以及引用它的历史升级记录。

删除按钮仅管理员可用，走 CSRF 校验。正在被 queued / backup / migrating / restarting / health_check / rolling_back 升级任务引用的备份禁止删除；普通历史快照删除后不可恢复。页面只管理备份根目录的直接子项，拒绝 `..`、路径越界和符号链接。

**迁移口令和管理员密码会随网页请求传输，生产环境必须通过 HTTPS 反向代理访问，不要把 8080 明文端口暴露到办公网之外。** `.bbumig` 文件和迁移口令也不要用同一个邮件、IM 或共享目录传递。

迁移后历史任务可以查看报告和证据，但任务详情会标记「原始输入未迁移」：重跑按钮隐藏、后端重跑接口返回 400、复核不能勾选「回流案例」；案例列表显示「原始输入未迁移」，评测不会选中这些案例。需要重新分析时请上传原始日志新建任务。

## 10. 平台助手与 MCP

### 10.1 悬浮小助手

登录后页面右下角会出现「助手」悬浮按钮，所有账号都能使用。

可以问：

- 平台怎么用：新建诊断、日志包、技能库、技能工坊、模型接入、账号、备份、升级；
- 我的消息：未读站内通知、与我相关的任务事件、外部 IM 消息；
- 管理员还可以问：系统状态、磁盘、备份列表、升级状态、用户/模型/通知配置。

示例：

- “平台怎么新建诊断任务？需要准备什么？”
- “查一下我的未读通知”
- “最近失败的任务和最后一条事件是什么？”
- 管理员：“看一下系统当前状态、磁盘和模型是否可用”

回答下方会列出：

- **工具执行卡片**：助手实际查了哪些工具、结果摘要；
- **来源**：平台文档片段，可以点开查看原文；
- **跳转链接**：通知中心、系统信息、任务详情等；
- **待确认操作**：写操作不会立即执行，需管理员点“确认执行”。

如果标题旁显示“本地检索”，说明当前没有可用的 `assistant`/`default` 角色模型。助手仍会检索平台文档和自己的消息，只是不会做模型总结。配置模型角色后可切换为“模型在线”。

### 10.2 管理员运维确认

管理员在悬浮窗里要求删除备份、释放任务空间、修改通知偏好时，助手会先生成一条 10 分钟有效的待确认操作：

1. 核对操作标题和摘要；
2. 低风险写操作点“确认执行”；
3. 升级/回滚、用户/模型变更等高风险操作还需重新输入管理员密码；
4. 取消或超时不会产生任何修改。

待确认操作只存在内存，服务重启后会丢失，不会自动补执行。

### 10.3 MCP Token 与外部客户端

外部 AI 客户端通过 MCP 接入平台：

1. 管理员进入「系统信息 → MCP / 助手」；
2. 点「生成 Token」，选择 `read`（推荐）或 `admin`；
3. Token 只显示一次，立即复制；
4. 把客户端配置中的 `<YOUR_TOKEN>` 替换为实际 Token。

示例配置：

```json
{
  "mcpServers": {
    "bbu-faultscope": {
      "type": "http",
      "url": "http://127.0.0.1:8080/mcp",
      "headers": { "Authorization": "Bearer <YOUR_TOKEN>" }
    }
  }
}
```

MCP 端点只接受 `POST`，`GET /mcp` 返回 405；不支持 SSE。默认只允许本机 loopback，外部客户端应与平台运行在同一台机器。确需内网访问时由管理员显式开启 `mcp_allow_remote`，并自行承担网络边界风险。

Token 轮换或撤销后旧 Token 立即失效；账号停用后 Token 同步失效。

### 10.4 权限边界

| 能力 | 普通用户 | 管理员 | MCP read | MCP admin |
| --- | --- | --- | --- | --- |
| 平台文档问答 | 可用 | 可用 | 可用 | 可用 |
| 自己的通知/任务事件 | 可用 | 可用（可查全部） | 按绑定账号 | 按绑定账号 |
| 审计/操作记录 | 不可用 | 可用 | 按绑定账号 | 按绑定账号 |
| 系统状态/备份/存储/升级状态 | 不可用 | 可用 | 可用 | 可用 |
| 删除备份/释放空间/通知偏好/标记已读 | 不可用 | 确认后执行 | 不可用 | 需 `confirm=true` |
| 升级/回滚/用户/模型变更 | 不可用 | 确认+密码 | 不可用 | 不可用 |

### 10.5 外部 IM

当前外部 IM 是“可插拔适配器”，默认读取 `data/external_messages.json`，不连接真实飞书/豆包。文件格式示例：

```json
{
  "messages": [
    {
      "id": "im-1",
      "from": "现场同事",
      "text": "NE_A 时钟失锁，已换纤仍存在",
      "ts": "2026-11-26T10:00:00+08:00",
      "conversation": "BBU 支撑群"
    }
  ]
}
```

接入真实 provider 前需要确定凭据、出域授权和用户身份映射；当前接口只提供读取，不提供消息回写。

## 11. 常见使用问题

**任务一直“排队”**

检查「系统信息」的运行/并发上限与调度器状态；4 个任务并发占满时会排队。管理员可调整 `max_workers` 后重启服务。

**任务显示“证据不足 / needs_data”**

平台没有编造根因，而是列出缺失信息。按建议补充时间窗、告警日志、单板/光模块读数后重跑。

**报告结论与现场不符**

先看「技能卡」的证据条目与限制说明；可能是技能规则不匹配或日志时间窗不对。可在工坊修正规则/补案例，重新构建发布。不要把未验证技能直接用于生产决策。

**上传后技能工坊没有规则候选**

日志中没有稳定文本特征，或文件类型不在扫描 glob 内。检查日志是否为明文、是否在时间窗内；也可在“补充/纠正”里贴关键日志行，再点“按补充重新生成”。

**任务空间里“可立即释放”和“原始输入”不一致**

重跑任务与首次任务共享同一批输入文件。共享文件只有最后一个引用任务释放时才删除，因此单个任务显示的“可立即释放”可能小于其原始输入。勾选后按页面提示完成释放即可。

**释放原始输入后还能看报告吗**

可以。释放只删除 `data/uploads` 下的原始上传，报告、证据、案例和数据库记录都保留；该任务不能再重跑，需要重新分析时请上传原始日志新建任务。释放中断（如服务重启）会显示“释放中断，可重试”。

**修改运行参数后没有变化**

「保存配置」只写文件，不改变当前进程；必须点「保存并重启」或「仅重启服务」。有诊断、工坊、迁移、升级或评测任务运行时会被拒绝，请等任务结束后再重启。

**浏览器打开报告空白**

报告为同源 iframe；检查是否被浏览器插件/安全软件拦截，或直接点「打开报告」在新标签打开 HTML。
