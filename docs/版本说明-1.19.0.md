# BBU FaultScope 1.19.0 版本说明（1.18.0 验收缺陷修复）

发布日期：2026-11-25

本版本不新增 R3–R6 功能，只修复 1.18.0 逐条验收确认的确定性缺陷，并正式升版。1.14.0 和 1.18.0 的安装包、SHA 文件和版本说明保持原样，不覆盖、不静默替换；1.19.0 使用独立文件名、独立 SHA 文件和独立升级快照。

## 一、修复范围

### 1. 可信报告：数字必须回到证据原文

- `bbu/claims.py` 的 `validate_claims()` 不再在 claim 文本之间互证。数字和时间按 claim 引用的 `evidence_id` 回到 `bundle["evidence_texts"]` 或证据原文做规范化定位，找不到即 `unsupported_number` / `unsupported_time`。
- `build_claims()` 增加 `evidence_texts` 映射；`number/time` 类型必须携带证据引用，否则报 `missing_evidence`。
- `bbu/pipeline.py` 的 LLM 报告门禁改为 `chosen and claim_check.get("ok") and ...`。claim 校验失败时不再调用 writer 模型，直接回退确定性模板。

### 2. 工具授权：默认 shadow 不再放行安全关键违规

- `bbu/tool_contract.py` 增加风险别名归一：`read_only/collect → low`、`change/modify/write → high`、`reset/restore/upgrade/delete → destructive`，修正此前 `change/reset` 被当成 `low` 放行的问题。
- 新增 `_SHADOW_CRITICAL`：`tool_unavailable / approval_contract / approval_required / approval_mismatch / role_denied / site_denied / device_denied / path_denied / schema_invalid / input_count / input_empty / network_unenforced` 在 shadow 模式下直接 `allow:false, decision:"deny"`，并返回 `shadow_critical` 列表；普通策略原因仍只记录 `would_deny`。
- 只有 `tool_policy_mode=off` 才完全保留旧 runner 行为。

### 3. 工坊合并：人工锁保护值而不是只保护标记

- `bbu/provenance.py` 新增 `get_path / set_path / locked_values / restore_locked`。
- `bbu/workshop_spec.py` 的 `merge_specs()` 在规范化与 `_map_cases` 之前抓取所有 `locked:true` 字段值，合并后恢复原值，并在结果中写 `locked_restored`。
- 测试契约由“锁标记仍在、值可被覆盖”改为“锁定 `/fault_name` 后值保持原值”。

### 4. 工坊硬字段来源覆盖率提升到 100%

- `bbu/provenance.py` 的 `attach_provenance()` 支持空白规范化定位、`line_anchor` 行级回退、`derived_from/derivation` 推导记录。
- 规则 regex、根因 condition/name/actions/mechanism、threshold value 均可追溯到规则原文或条件引用。
- 三个 intake 样本实测：SSD 46/46（原文直引 34、可追溯推导 17）、USBFLASH 30/30（22+12）、watchdog 30/30（18+16）。
- `web/assets/js/page_workshop.js` 的“字段来源”改为 `sourced/总数字（原文直引 X，可追溯推导 Y）`，不再只统计 `verified`。

### 5. 恢复验证：没有后验证据不能判 recovered

- `bbu/recovery.py` 的 `compare()` 新增 `same_case` 显式任务/对象一致性、`before_files/after_files` 差集、`after_independent_evidence`（只统计恢复后新增文件）。
- 根因从有到无时，必须同时满足 `same_case` 且恢复后新增独立文件 ≥1 才判 `recovered`，否则 `inconclusive`。
- `create_run()` 把 `task_id` 注入 before，`observe()` 注入 after；`review()` 的学习门禁增加 `same_case`。
- `observe()` 自动写一条 `EvidenceEvent`（`kind=manual`、`name=recovery.verification`、`trust.origin=platform_validation`），并返回 `comparison.evidence_event_id`。

### 6. HypothesisState 接入运行链路

- `bbu/session.py` 的 `update_hypothesis()` 增加可选 `state`，事件 payload 使用 `hypothesis_state`，不覆盖全局会话 `state`；`snapshot()` 写回 hypothesis 状态并新增 `budget`。
- `bbu/pipeline.py` 新增 `_hypothesis_id / _init_hypotheses / _sync_hypotheses`：按计划候选技能生成 `H-<skill>` 假设（applicability、necessary_checks、prior_score、supporting/contradicting evidence、missing_data）。
- 执行后按技能结果更新 `supported / weakened / refuted`；仲裁后把 chosen skill 设为 `confirmed`，其余 supported 降为 `weakened`。
- `_run_one` 写 `tool_started`、`tool_finished`、`evidence_added` 会话事件；`run_started` 和 `decision_summary` 写入 budget 快照。

### 7. 补充文件按 glob 选择性失效

- `bbu/api.py` 新增 `_input_members / _skill_globs / _glob_match / _affected_skills`。
- 对 `.zip` 读取 `namelist()`，对技能 profile 递归收集所有 `globs`，用 `fnmatch` 匹配成员路径与 basename；只有命中的 `task_skills` 置 `invalidated=1`，未命中保留。
- API 响应和 `input_added` 事件新增 `invalidation_reasons`，说明是哪个 glob 命中。
- 注意：如果技能声明了宽泛 glob（如 `**/*.log`），按合同它仍应被失效；选择性来自技能自己的声明范围，不是平台猜测。

### 8. 供应链 `verified` 语义修正

- `bbu/supply.py` 的 `build_manifest / sign_skill` 增加 `verification` 字段并签名；`verify_skill` 回传该字段。
- `bbu/skills.py` 的 `verified` 现在要求 `semantic_verified and manifest_status=="verified" and verification.status=="case_regression" and verification.ok`；`tampered / bad_signature / invalid` 一律 `status="incompatible"`，不再以 `degraded` 继续执行。
- `bbu/api.py` 的 ZIP 导入签名带 `{"status":"quarantined","ok":false,"reason":"...未执行案例回归"}`，不再冒充已回归验证。
- `bbu/workshop.py` 的 `build()` 用 `result.regression` 的 `total/passed/failed/errors` 计算 `verified_mode`；`publish()` 复制后调用 `sign_skill(... verification={"status":"case_regression",...})`；`rollback()` 按 `skill_versions.build_json` 的回归结果重签。

### 9. 同根因新变体不再作为重复丢弃

- `bbu/case_matrix.py` 的 `record_candidate()` 增加可选 `kind`。
- `bbu/learning.py` 新增 `_input_digest()`：同根因时比较源任务输入摘要，完全相同才 `duplicate_root`；不同则写入 `experience_candidates`，`kind="same_root_variant"`，返回 `status="candidate_recorded"`。

### 10. OpenAI 原生结构化输出

- `bbu/ai.py` 新增 `_strict_output_schema()`，递归补 `additionalProperties:false`、`required=全部 properties`。
- 请求发送 `response_format={"type":"json_schema","json_schema":{"name":..., "schema":..., "strict":true}}`；不支持时降级 `json_object`，再不支持则去掉 `response_format` 重试。

### 11. Budget 原子预占

- `bbu/ai.py` 的 `Budget` 新增 `_pending_calls / _pending_tokens`、`reserve() / settle() / release()`；`check()`、`remaining_calls`、`snapshot()` 都计入 pending。
- `AIGateway.complete()` 改为 `budget.reserve(est)` → `_call` → `budget.settle(...)`；`_call` 异常时 `release`。repair 调用同样预占/结算/释放，避免 check 与 record 之间并发超卖。

## 二、验证结果

- 单元测试 **144/144** 通过：
  `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_*.py'`
- HTTP 全量冒烟 **135/135** 通过：
  `PYTHONDONTWRITEBYTECODE=1 python3 tests/api_full_smoke.py`
- 新增/加强测试：
  - `tests/test_r4_trust.py`：温度 999℃ 但证据仅 42℃ 必须 `unsupported_number`；42℃ 通过。
  - `tests/test_tool_security.py`：shadow 下 `change` 映射 high、`approval=required`、`allow:false`、`shadow_critical` 含 `approval_required`。
  - `tests/test_r5_r6_governance.py`：锁字段值保持；三个 intake coverage=1.0；unsigned/quarantined 不算 verified、case_regression 才算、tamper 后 incompatible；恢复事件与无独立证据 `inconclusive`。
  - `tests/test_core.py`：Budget `reserve` 原子性、release/settle、pending 归零。
  - `tests/test_ai_protocols.py`：OpenAI payload 含 `response_format.type=json_schema` 且 `strict=true`。
  - `tests/test_session_continue_http.py`：clock zip 只失效 clock 技能，不失效收窄 glob 的 optical 技能，并校验 `invalidation_reasons`；续跑后 hypothesis 有 confirmed、会话有 `tool_started/evidence_added` 和 budget。

## 三、数据库、接口与兼容性

- 数据库 schema **保持 16**；本版本没有新增表或列，旧库无需迁移。
- REST 接口保持 **135 条**；没有新增或删除路由。
- 1.18.0 数据可直接升级；1.14.0 可经 1.19.0 升级脚本迁移到 schema 16。
- 升级前自动做 state/code 备份，回滚使用 1.19.0 升级快照；不会覆盖 1.18.0 包。

## 四、仍未完成（不能宣称已满足报告全部条款）

本轮只修复确定性硬缺陷，以下结构性能力仍未实现，1.19.0 不宣称 1.18.0 报告 17 步“全部满足”：

1. `bbu/agent.py` 的 `BoundedAgent` 仍是计划审查器，不是真正的 Agent Loop；`bbu/dag.py`、`action_space.py`、`stop_policy.py` 仍不存在。
2. 报告要求的真实任务卡 schema、hidden 集、五条对照基线、pass@3、混淆矩阵尚未落地；仓库仍没有 `task-cards/`、`hidden/`、`evaluations/suites/`。
3. 检索仍是词法 + 64 维字符三元组，不是 BM25 + RRF + 重排；校准未实现 ECE/Brier/risk-coverage；报告未做语义蕴含校验。
4. 工坊补证仍是整份重解析，不是字段级 diff；`case_matrix` 仍不是规则变异测试矩阵，`test-plan.yaml` / `mutation_test` 未实现。
5. canary 仍不能自动暂停；decision cards 仍在仲裁之后生成，不能提前阻止高置信结论。
6. 沙箱仍是 Python audit hook + rlimit，不是容器/seccomp；组织级离线签名未实现。
7. 上述未完成项需要真实数据、专家标注和结构性改造，不能用代码声明替代；后续版本应单独立项。

## 五、升级提示

- 不要覆盖或重命名 1.14.0 / 1.18.0 的安装包和 SHA 文件；1.19.0 使用：
  - `bbu-fault-platform-1.19.0-offline.tar.gz`
  - `bbu-fault-platform-1.19.0-windows.zip`
  - `bbu-fault-platform-1.19.0-ubuntu1604-offline.tar.gz`
- 升级后 `/api/health` 应返回 `{"ok": true, "version": "1.19.0"}`。
- 首次升级后建议检查：schema 16；默认 shadow 下高风险工具无审批应被拒绝；工坊字段来源覆盖率为 100%；恢复验证无独立证据应为 `inconclusive`；技能清单只有案例回归通过才显示 verified。
