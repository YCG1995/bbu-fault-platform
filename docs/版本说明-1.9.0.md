# 版本说明 1.9.0

基线：1.8.1（schema 8）→ 1.9.0（schema 9）
日期：2026-11-25

## 一、本版内容

本版新增「统一工作目录 + 精简迁移包」，并补齐迁移后的输入缺失门控。

### 1. 统一工作目录

- `bbu/config.py` 新增 `work_dir`、`BBU_WORK_DIR`、`max_migration_mb`（默认 4096）；提供统一目录时自动派生 `data/skills/cases`。
- 兼容旧 systemd 的 `BBU_DATA_DIR/BBU_SKILLS_DIR/BBU_CASES_DIR`：没有 `BBU_WORK_DIR` 时，以三项实际路径的公共父目录为准，避免 `config.json` 中过期的 `work_dir` 覆盖部署路径。
- 标准布局：`<work_dir>/data`、`skills`、`cases`、`updates`、`backups`。`updates/backups` 沿用 `U` 前缀任务目录，和离线升级共用助手触发器。

### 2. 精简迁移包

- 数据库 schema 9：`tasks/real_cases/cases` 增加 `inputs_state`，旧库采用加法式 `ALTER`，不重建表。
- 新增 `bbu/migration.py`：SQLite 一致性快照、白名单文件复制、数据库与文本路径重写、案例 JSON 脱敏、清单 SHA256 校验、ZIP 安全解压、目标目录预检、后台任务与维护锁。
- 新增 `bbu/migration_crypto.py`：`BBUMIG01` 格式，独立迁移口令经 scrypt 派生密钥，ChaCha20-Poly1305 认证加密（纯 Python 实现，不依赖 `cryptography`）；AES-256-GCM 仅保留解密兼容。AAD 绑定 header，错误口令或篡改直接拒绝。
- 导出包包含：用户与密码哈希、模型 Key 密文、`master.key`、技能源码与版本、任务/工坊/案例/评测元数据、报告和证据。
- 导出包不包含：`uploads`、`draft_uploads`、`tmp`、`logs`、`real_logs`、`real_cases/*/inputs`、工坊原始日志与 `extracted`、任务 `unpacked`、缓存、登录会话、认证挑战与用户邀请码、初始管理员密码文件、旧升级包和备份。

### 3. 网页与 API

新增管理员接口：

- `GET /api/system/migrations`
- `POST /api/system/migrations/workspace/preflight`
- `POST /api/system/migrations/workspace`
- `POST /api/system/migrations/export`
- `POST /api/system/migrations/import`（multipart）
- `GET /api/system/migrations/<id>`
- `GET /api/system/migrations/<id>/download`
- `DELETE /api/system/migrations/<id>`

管理页「系统信息」新增「工作目录与迁移」卡片：当前路径/允许根/磁盘、切换预检与密码确认、导出独立口令、迁移记录、下载、覆盖恢复上传进度和删除。所有提交要求管理员、CSRF，导出/切换/导入/删除还要求二次输入管理员密码，并写审计。

维护期间 `httpd` 对所有写请求返回 503，只保留状态查询和下载；下载走流式 `FileBody`。

### 4. Linux 与 Windows 激活

- Linux 复用 `bbu-upgrade-helper@.service`：新增 `workspace` 和 `restore` 动作，root 助手负责停服、校验、复制/替换、chown、改写 systemd 的 `BBU_DATA_DIR/BBU_SKILLS_DIR/BBU_CASES_DIR` 和 `ReadWritePaths`、更新 `config.json` 与 `/etc/bbu-upgrade.json`、重启并做健康检查。失败回写 `failed`，工作目录切换不会修改旧目录。
- `/etc/bbu-upgrade.json` 新增 `allowed_work_roots`，默认 `/var/lib`、`/srv`、`/data`、`/mnt`；网页预检和 root 助手都会校验。
- Windows 手动运行没有 root 助手：准备完成后写程序根 `pending_maintenance.json`，提示手动重启；`run.py` 在 App 初始化前由 `bbu/startup.py` 应用切换或覆盖恢复，失败恢复旧目录。
- 新增 `bbu/startup.py`，把 Windows 的目录替换、config 更新、状态回写、备份和失败恢复放在打开数据库之前。

### 5. 输入缺失门控

迁移后历史任务仍可查看报告和证据，但依赖原始输入的动作停用：

- 任务详情显示「原始输入未随迁移包导出」，隐藏重跑按钮；后端重跑接口对 `inputs_state != available` 返回 400。
- 复核不能勾选「回流案例」；`review.submit()` 在服务端再次拒绝，避免产生空案例。
- 案例列表/详情显示「原始输入未迁移/未随迁移包导出」。
- 评测不选中无原始输入的案例；若所选案例全部缺失，返回明确错误。
- 迁移包导入后再次标记 `inputs_state`，避免旧快照残留 `available`。

### 6. 其它修复

- `LearningService.busy()`：自动沉淀队列有积压时拒绝迁移。
- 删除迁移记录规则：导出 ready 可删；workspace/import 的 ready 仍视为执行中，避免删除交接窗口。
- 导入失败清理全部上传临时文件；`safe_extract` 失败删除半成品目录。
- `MigrationManager` 显式接收维护 gate；Linux 助手启动失败时回收 gate，避免页面永久 503。
- Windows pending 的清单键统一为 `manifest_path`；启动导入时用 `Config` 解析实际 `work_dir`，避免只写 `work_dir` 的配置被误判为程序目录下 `data`。
- 导入校验要求迁移包内至少有一个启用状态的管理员账号，避免恢复成无法登录的实例。
- Windows 准备完成后维护锁保持到重启，防止第二个迁移任务覆盖 `pending_maintenance.json`；`httpd` 维护期间暂停所有写请求，仅保留状态查询和下载。
- 迁移任务自动清理超过 30 条的非导出终态记录；导出包仍需管理员手动删除。
- 启动时清理遗留的 `evaluations.status='running'`，并拒绝在有评测运行或自动沉淀积压时开始迁移。

## 二、升级说明

- 升级包：`dist/bbu-fault-platform-1.9.0-offline.tar.gz`（只含代码，不含 Python 运行时）
- 一键部署大包：`dist/bbu-fault-platform-1.9.0-ubuntu1604-offline.tar.gz`（含 CPython 3.13 运行时，约 76MB）
- Windows 手动包：`dist/bbu-fault-platform-1.9.0-windows.zip`
- 数据库：schema 8 → 9，加法式迁移，旧数据保留
- Linux 升级：平台「系统信息 → 离线升级」上传，由 root 助手执行；已有 `/etc/bbu-upgrade.json` 不需要重建，缺 `allowed_work_roots` 时助手使用默认根
- Windows 升级：停止平台，备份 `data/`、`config.json`，覆盖程序目录后重启
- 迁移包和离线升级包不是同一种文件：`.bbumig` 只用于实例迁移/灾备恢复，不能用于升级或回滚；升级快照也不能当迁移包

## 四、已知限制

- 当前构建环境没有真实 Windows 主机和 root/systemd，Linux 助手真实停服/重启、sudoers、健康检查和 Windows 重启激活仍需目标机验收。
- 迁移加密使用纯 Python ChaCha20-Poly1305，速度约 0.7 MB/s；精简工作区通常几 MB，但大包导出/导入会较慢。`max_migration_mb` 默认 4096，实际应按现场数据量评估。
- 覆盖恢复是整体替换，不做增量合并；会先备份当前 `data/skills/cases`，但不自动清理历史备份。
- 工作目录切换保留旧目录，需管理员确认稳定后手工归档/删除。
- 迁移包包含 `master.key` 和模型 Key 密文，必须与迁移口令分渠道保管；不要放到普通共享目录。
