# [示例] 时钟失锁诊断

## 1. 故障标识

- 规范名称：时钟失锁
- 别名：时钟失锁、参考时钟异常、时钟不同步
- 告警码：CLK032 时钟失锁告警
- 设备形态：BBU、ITBBU、SDR
- 制式：待补充
- 版本范围：待补充
- 执行模式：script
- 故障大类：时钟同步

## 2. 故障现象

- 可感知现象：网管 CLK032 告警；日志出现 PLL unlock / 时钟失锁
- 描述关键词：时钟、失锁、PLL、参考源、CLK032、频偏、不同步

## 3. 分析步骤与判定决策链

### S1：检索时钟失锁直接证据
- 目标：确认日志中是否存在 CLK032 或 PLL unlock 等直接证据
- 规则 **E1**（text）：日志出现时钟失锁告警或 PLL unlock
  - 路径：`**/*.log, **/*clock*.txt, **/*.txt`
  - any_of: ['CLK032', '时钟失锁', 'PLL unlock', 'PLL失锁']
- 命中 → 命中时钟失锁直接证据
- 未命中 → 无时钟失锁证据

## 4. 根因与处理方案

### R1：参考时钟源失锁
- 判定条件：`E1`
- 关联时序约束：自动（condition 中肯定引用的规则两两相关的约束）
- 置信度：medium
- 处置动作：
  1. 检查 GNSS 天线、馈线与卫星可见性，确认锁星数量与 C/N0
  2. 检查上级 SyncE/1588 时钟源与传输链路告警
  3. 查看 clockstatuslog 中的参考源切换与 PLL 状态，定位失锁起点
  4. 恢复参考源后观察 CLK032 是否清除，并复核时间同步偏差
- 前提条件：已获取故障时段完整 clockstatuslog 与网管告警
- 风险：现场操作前需确认业务影响与变更窗口
- 回退：恢复原配置并保留日志，升级时钟专项分析
- 升级路径：参考源正常但仍反复失锁时，升级单板时钟硬件分析
