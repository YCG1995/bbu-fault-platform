## 1. 通用输入参数

| 参数 | 必需 | 说明 |
|---|---|---|
| `--description` | precise/shallow 必需 | 用户故障描述原文；可能不完整或误导，仅作线索之一 |
| 位置输入（日志包/目录/单日志） | 可选 | zip/tar.gz/多层嵌套；shallow 模式必需；多文件可并列，目录含并列采集包自动合并 |
| `--out` | 可选 | 输出目录，默认首个输入同级 `<输入名>.analysis`，不落在 skill 目录 |
| `--site` | 可选 | 多站点包仅输出指定站点；不填则输出全部站点的一份汇总 |
| `--specialized` / `--fm-align` | 可选 | 专项复核/告警对齐输入，仅在对应文件已存在时传入 |
| `--mode`（router 侧） | 可选 | precise / shallow / full，见 router SKILL.md |

接口调整仅涉及上述输入参数变化，开发量小；不改变子 skill 内部流水线。

## 2. 采集项清单（按采集来源）

> 各采集包内部目录、文件名与文件类型见 `references/platform/log-package-map.md`；本节只列平台需要勾选的采集项。

| 采集来源 | 典型内容 | 关键文件/目录 | 支撑故障 |
|---|---|---|---|
| 设备侧全量日志（tar.gz） | 板内运行日志、告警、复位、时钟 | `BSP*HWM_APP*.tar`、容器 `uds/dps` 日志 | 复位、链路、光模块、电源、数据库、升级 |
| SDR 网管一键采集（zip） | 网管导出告警表、网元日志 | `*OMMB_NE_LOG.zip`、fm-active/fm-history | 时钟、告警类、链路 |
| DCM 深度采集（ITBBU） | 深度诊断、多站点并列 | DCM 包内多站点目录 | 硬件根因、复杂故障（agent 模式） |
| CloudMAT 工装日志（纯文本） | 拷机/工装测试结果 | `<条码>_...@槽位_.log` | 工装拷机失败 |
| FM 告警表 | 当前/历史告警 | `fm-active_*`、`fm-history_*`（csv/xlsx） | 全部需告警码匹配的故障 |

**各故障类型的具体 DCM 采集项：待确认**（会议责任人：易重桂与项目组确认后提供）。填写口径：逐类列出「必需项 / 可选项 / 缺项影响」，并标注所属单板域；本文件在确认后补全，不先填默认值。

## 3. 缺项降级行为

- 无日志：只给可能性分析，明确「无日志、无证据」，不给确定性根因。
- 缺部分采集文件：写明「证据不足/需补采」，不得把「未采到」写成「无故障」。
- 二进制/密文/未登记格式：默认只登记、不解析；无格式描述与解析手段时标「需人工专用工具解析」。
- 多站点缺某站点：只对已采集站点出结论，缺失站点在报告中显式列出。
- 浅扫未命中：不等于设备正常，可转 full 全量或人工确认。

## 5. 路由对接字段（子 skill 如何被 router 索引）

子 skill 由 builder 生成后，router 动态扫描其 `assets/` 下文件，按下表字段索引；填写质量直接决定路由命中率，避免选错。

| profile 字段 | 渲染产物 | router 用途 |
|---|---|---|
| `fault.name` + `fault.aliases` | fault-profile / frontmatter | 描述精确命中（高分） |
| `symptoms.description_keywords` | fault-profile | 描述关键词命中 |
| `fault.alarm_codes` | alarm-code-dictionary | 描述告警码 + 包内告警码匹配 |
| `quick_signatures` | `assets/quick-signatures.yaml` | shallow 浅度扫描特征 |
| `category` | quick-signatures / frontmatter | 大类聚合（粒度待业务研发确认） |
| `skill.execution_mode` | frontmatter / SKILL.md | 标记 script/agent，决定执行与编排方式 |

**填写要求**：
- 告警码、关键词、特征字必须给日志中真实出现的原文写法，不写概括词；
- 未验证规则标 `verified: false`，不进根因条件，router 默认跳过 triage 候选；
- 一个子 skill 只覆盖一类故障，差异大的故障拆开，避免路由区间重叠。
