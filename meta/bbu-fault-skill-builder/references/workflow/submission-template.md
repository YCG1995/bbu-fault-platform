## 6. 故障案例（至少 1 个故障正例；建议再加 1 个正常/反例）

> 案例是 AI 验证规则的依据：**正例该命中、正常/反例不该命中**。每个案例填一张卡片，有几个填几张。
> 文件名记不清可以只写个大概（如「DCM 包 xxx.zip」）；结论拿不准写「待确认」，AI 会和你核。

### 6.2 填写要点

- **正例至少 1 个，且你已知根因**——否则只能先登记案例、暂不生成。
- **最好有反例**（现象相似但结论不同），能显著降低误判。
- 文件名不必精确到路径，AI 会按名字去匹配日志包。
- 案例数据**不用拷进 Skill 目录**，只登记名字和结论即可。

## AI 会自动完成的部分（你不用管）

| 你不用填 | AI 自动生成 |
|---|---|
| 规则 ID（E1/E2…） | 按你的判断逻辑拆规则、编号、绑定到步骤 |
| 日志通配 / 正则 / 编码 | 生成 glob、正则、编码探测、最少命中次数、上下文行数 |
| 时序约束 | 从"先看什么后看什么"里提取先后顺序与允许间隔 |
| 数值趋势 / 滑动窗口 | 把你的"窗口 + 阈值"逻辑转成数值规则或专项脚本 |
| 快速特征 / 分类 / 执行模式 | 生成浅扫特征、category、execution_mode 建议 |
| fault-profile / 报告模板 / 子 skill | 生成并跑真实案例验证 |

> 填完把整份文件交给 AI 即可；哪项拿不准留空，AI 会回头问你。
